**감리 담당**: Opus (감리 전문가) · **테스트 수행**: Sonnet (테스트 담당, 7개 병렬 에이전트)
**감리 기준**: `docs/user_manual_app.md`(2026-07-06) — 블랙박스, 매뉴얼을 유일한 스펙으로 삼음
**감리 기간**: 2026-07-06 ~ 2026-07-08
**대상**: 활성 상장사(KOSPI/KOSDAQ) 전수 2,548사 + 기업 시각화 화면 전 4조합(연간/분기 × 연결/별도)

## 1. 감리 개요

### 1.1 범위
- **Tier 1(전수)**: 기업 시각화 화면(매뉴얼 §3)의 데이터 표시 무결성을 활성 대상기업 전수(2,548사) × 4조합(연간×연결, 연간×별도, 분기×연결, 분기×별도)에 대해 자동 스윕. 크래시 여부(DS-1), UI값↔DB값 기간별 자동대조(DS-2), 시계열 중간 결측 탐지(DS-3), 연결/별도 자동대체 표기(DS-4), 신뢰배지 렌더(DS-7), 헤더 정합성(DS-8), CSV 다운로드(CV-3), 지표 탭 기본선택(CV-6)을 점검.
- **Tier 2(엣지케이스 표본)**: 결산월·시장·규모·재무기준·이력(관리/상폐/기재정정/신규상장)·데이터특성 축을 기준으로 선정한 34개 엣지케이스 기업 + 무작위 20개사(총 54개사) 표본에 대해 매뉴얼 전 페이지·전 위젯(사이드바, 기업시각화 9탭, 스크리너, 분기변화, 밸류에이션, 기업비교, 자유조합차트, 도움말) 기능 체크리스트 55항목 실행.
- **보고서 수집(COL-2/유니버스 갱신, COL-3/신규 공시 수집)**: 외부 DART API 호출 및 운영 DB 쓰기를 유발해 감리 라운드 당시엔 사용자 승인 전까지 보류(§8 참고). **2026-07-10 사용자 승인 후 운영 DB에서 실행 완료 — 둘 다 PASS**(상세 §5·`02_checklist.md`).

### 1.2 방법
- 실행 중인 앱(Streamlit, 로컬 Postgres 연동)을 Playwright(헤드리스 Chromium)로 직접 구동해 렌더된 화면·값을 검증(로그·DB만으로 판정하지 않음).
- Tier 1은 병렬 6개 워커(각자 독립 Streamlit 인스턴스+포트)로 전수를 분담, 스크린샷은 이상 발견분 위주로만 저장.
- UI 표시값은 CSV 다운로드를 통해 파싱해 `calendar_financials`/`std_financials_v2` 원장 값과 단위환산(원→억원) 후 허용오차(0.5%) 내 일치 여부를 자동 대조.
- 파일럿(54사) 이후 전수 스윕을 진행하기 전, 감리가 직접 결과를 스팟체크(테스트 스크립트 자체의 셀렉터 버그 1건 발견·수정 확인)한 뒤 확대 진행.

|---|---|---|---|

| 재무제표 탭엔 데이터가 있는데 지표 탭만 기본지표 미표시 | 16건(shard5, `DEF-S5-2.md`) | 같은 조합의 CV-3(CSV 다운로드)는 실제 행·열 데이터와 함께 PASS 확인, mid_gaps에도 이상 없음 | **원인 미확정** — 위 두 패턴 어느 쪽으로도 설명되지 않음, 재현율 낮고(~1%) 크래시 없음(개발자 확인 권고, DEF-S5-2 참고) |
| 나머지(shard1·4·6, 약 82건) | 미개별 재검증 | 패턴상(회사 전환 직후 첫 조합에서만 발생, 동일 회사 이후 조합은 PASS) 위 첫 번째 패턴과 유사할 것으로 추정되나 개별 재현 확인은 되지 않음 | 추정(미확정) |

즉 118건 중 **직접 재현으로 "앱 결함 아님"이 확정된 것은 2건뿐**이며, 18건은 테스트 스크립트의 분류 누락, 16건(DEF-S5-2)은 원인 미확정으로 남아있고, 나머지 82건은 패턴상 타이밍 문제로 추정되나 미확인 상태임.

## 6. 매뉴얼 ↔ 구현 불일치

- DEF-1: 매뉴얼은 `/company`가 기본 페이지로 즉시 정상 표시된다고 암묵 전제하나, 딥링크 최초 진입 시 일시적 오류 모달이 뜸 — 매뉴얼이 다루지 않는 동작.
- 그 외 매뉴얼에 기술된 기능·표시 규칙과 실제 동작 간 불일치는 발견되지 않음(부록 B 각주·신뢰배지, 부록 C CSV/PDF 형식, 부록 D 용어 정의 모두 매뉴얼 기술과 일치).

## 8. 조치 권고 (우선순위)

1. **DEF-2 수정**(재무제표 3개 표 결측 표시) — 사용자가 매 페이지에서 마주치는 고빈도 표시 결함. 수정 방향은 결함 문서 참고.
2. **DEF-3 원인 조사**(별도/연결 표시 레이스) — 재현 조건(빠른 토글)이 파악되어 있어 개발팀이 바로 재현 가능. 조용히 틀린 값을 보여주는 유형이라 우선순위 높음.
3. **DEF-4는 개발팀과 별도 트랙으로 전달** — 시각화 앱 자체의 출시를 막을 필요는 없으나, 데이터팀 검토를 별도로 신속 개시 권고(범위가 3,626개 조합으로 넓음).
4. **DEF-1은 경미하므로 후순위**(사용자 영향 적음, Close 버튼 1클릭으로 해소).
5. **DEF-S5-2(지표 탭 기본지표 미표시, 16건)는 원인 미확정 상태로 개발팀에 전달** — 재현율이 낮아 우선순위는 낮으나, 재무데이터가 있는데 표시가 안 되는 유형이라 방치하지 말고 대표 사례(삼성에스디에스 등) 1~2건을 개발팀이 직접 확인 권고.
6. **재검증 범위**: DEF-2/DEF-3 수정 후, 이번에 결함이 발견된 대표 기업(삼성전자/SK하이닉스 - DEF-2, 코스메카코리아/파인테크닉스/삼영이엔씨 - DEF-3)에 대해서만 재스윕하면 충분 — 전수 재스윕은 불필요(구조적 결함이므로 대표 사례 검증으로 수정 확인 가능).
7. **COL-2/COL-3**은 이번 감리 범위에서 제외됨 — 사용자 요청으로 이번 라운드에서는 보류, 필요 시 별도 승인 하에 복제 DB에서 검증 권고.
