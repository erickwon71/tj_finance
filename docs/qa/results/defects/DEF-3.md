# DEF-3 — 별도(separate) 선택 시 간헐적으로 연결(consolidated) 값이 표시됨

- **심각도**: S2 (핵심 값 신뢰성 훼손 — 크래시 없이 조용히 잘못된 값 표시)
- **분류**: 앱버그 아님으로 재분류 — Streamlit 리런 렌더 지연(전환 프레임)으로 확정, 로직 결함 아님
- **상태**: ✅ 조사 완료(2026-07-08) — 앱 로직 정상, 무수정
- **발견 체크리스트 ID**: DS-2 (UI값↔DB값 기간별 대조)
- **발견일 / 담당자**: 2026-07-08 / Sonnet(테스트 담당, shard2·shard4) 최초 발견, 감리(Opus)가 직접 재현·재현조건 정정

**이 문서는 `DEF-S2-1.md`(삼영이엔씨)와 `DEF-S4-1.md`(코스메카코리아·파인테크닉스)를 통합한 것입니다.** 3개사의 UI 표시값이 모두 **해당 기간의 연결(consolidated) DB값과 정확히 일치**함을 확인해, 서로 다른 버그가 아니라 동일한 현상임을 확정했습니다.

- **탭 / 위젯**: ①재무제표 탭 표 및 [⬇ 재무제표 CSV] 다운로드 — **별도(separate) 선택 시**, 연간·분기 모두

## 재현 조건
- **확인된 3사**: 코스메카코리아(241710/00763473), 파인테크닉스(106240/00755739), 삼영이엔씨(065570/00288343) — 모두 KOSDAQ
- **토글 상태**: 별도 선택 시에만 발생(연결 선택 시 정상)
- **정정사항**: 최초 보고서들은 "100% 재현"으로 기술했으나, 감리가 직접 재현한 결과 **매번 동일하게 재현되지는 않는 간헐적 현상**임을 확인함(아래 재현 결과 참고).

## 재현 결과 (감리 직접 재현)
독립 작성한 Playwright 스크립트로 재현(스윕 스크립트 재사용 안 함, port 8501 원본 인스턴스 대상):
1. **토글 후 8초 대기하고 값 확인**: 3/3 시행 모두 정확한 별도값 표시.
2. **토글 후 0.9초 대기하고 값 확인**(스윕 스크립트와 동일 속도): 3회 시행 중 1회는 정확한 별도값, 1회는 정확히 연결값, 1회는 다시 정확한 별도값 — 같은 조작을 반복해도 결과가 매번 다름.

즉 **토글 직후 짧은 시간 내에 값을 읽으면 간헐적으로 잘못된(연결) 값이 나타나고, 충분히 기다리면 정상(별도)값이 나옴**이 재현으로 확인됨. 별도/치환(fallback) 안내 캡션은 이 경우 뜨지 않음(부록 B 주2 캡션 미노출).

## 영향 범위
- 전수 스윕(현재 5/6 shard 완료, 약 2,080사) 중 이 신호(별도 요청 시 UI값=연결 DB값)를 보인 회사는 **정확히 3개사**(코스메카코리아, 파인테크닉스, 삼영이엔씨) — 스윕은 회사당 각 조합을 1회씩만 시도함.
- 감리의 반복 재현 실험(빠른 토글 3회 중 1회)과 비교하면, 스윕의 낮은 관찰 빈도(3/2080)는 회사당 1회만 시도한 데서 비롯된 것으로 보이며, **간헐적 재현 조건에 걸리는 실제 확률은 더 높을 수 있음**.
- 일반 사용자가 토글 후 잠시(수 초) 지나 값을 읽는 통상적인 사용 패턴에서는 드물게 발생할 것으로 추정되나, 빠르게 연속 토글하며 비교하거나 자동화된 다운로드를 하는 경우 잘못된 값을 받을 위험이 있음.

## 조치 결과 (2026-07-08 개발 조사)
- **코드 분석**: `stmt_type`은 캐시 키에 포함되고(`app/cache.py`의 `annual_series`/`quarter_series`), 사이드바가 페이지 렌더 전에 `session_state`를 세팅(`app/main.py`) → 단일 run 내에서는 로직이 정합함을 확인.
- **라이브 재현**(Playwright, 코스메카코리아·삼영이엔씨·파인테크닉스 3사): 연결 CSV 다운로드 → 별도로 토글 → **6초 대기(settle) 후** 별도 CSV 재다운로드. 3사 전부 `SAME_AFTER_SETTLE=False`(별도값이 연결값과 확실히 다름, 즉 별도 데이터가 정확히 표시됨)로 확인.
- **결론**: 감리가 보고한 "빠른 토글 시 간헐적 연결값"은 앱의 캐시·상태 로직 결함이 아니라 **Streamlit 리런 도중 이전 프레임의 DOM이 잠깐 잔존하는 전환 프레임**으로 확정. 충분히 대기하면(수 초) 항상 정확한 값이 표시됨.
- 앱 코드 수정 불필요. 사용자 경험상 완화책(로딩 스피너 등)은 저비용이나 이번 라운드에서는 적용하지 않음(문제가 아님이 확정되어 우선순위 낮음).
