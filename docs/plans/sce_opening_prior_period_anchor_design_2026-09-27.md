# SCE 기초잔액 ↔ 전기말 잔액 대조 앵커 설계 (2026-09-27, 검토 단계 — 구현 전)

> 상태: **설계·측정 완료, 구현 전.** 사용자 검토 후 별도 지시로 착수한다.
> 관련 규칙: R162(열 롤포워드 부호복원)·R162-b(이월잔액)·R162-d(행 항등식)·R185(열 일관성)·R186(R162-e 자기일관성)
> 측정 스크립트: `scripts/scan_sce_opening_vs_prior_2026-09-27.py`, `scripts/scan_sce_opening_recheck_scope_2026-09-27.py`

## 1. 배경

자본변동표(SCE)의 잔액 행에는 날짜가 붙어 있다("2013.01.01 (기초자본)", "2013.12.31 (기말자본)").
**X.01.01 기초 = 직전 기간 X-1.12.31 기말**이므로 직전 보고서(BS·SCE)가 그 부호를 외부에서 증명할 수 있다.

계기: 원익큐브 2015 사업보고서 `20160330000801` 별도 SCE "2013.01.01 (기초자본)" 행.
- 자본조정 +9,615,576: 2012 사업보고서 `20130329000428` BS·SCE 는 모두 **−9,615,576**이다.
- 기타포괄손익누계액 +705,022,515: 2012 보고서에는 이 열이 없다(이익잉여금에 포함). 2015 보고서의 이익잉여금 16,997,120,025
  = 2012 이익잉여금 16,292,097,511 + 705,022,514 이므로 **−705,022,515**여야 총계가 유지된다.
  같은 열의 2013 블록 롤포워드로도 −705,022,513(2원 차)이 나온다.
- 두 셀을 모두 음수로 하면 기초 행 합계 52,723,885,539 가 인쇄된 총계와 2원 차로 맞는다. 현재 R162 계열은 정확히 닫힐 때만
  작동하므로 2원 차 때문에 이 셀을 건너뛴다.

### 2.2 불일치 7,581셀 — 현재 표 항등식과의 관계

뒤집었을 때 (a) 그 열의 블록 롤포워드, (b) 그 행의 행 항등식이 어떻게 되는지를 봤다.
"근거"는 직전 보고서에서 같은 금액을 찾은 곳이다.

| 근거 | 롤포워드 | 행 항등식 | 셀 | 판단 |
|---|---|---|---|---|
| BS | 뒤집어야 닫힘 | 개선 | 1,073 | 확정 후보(강) |
| BS | 둘 다 안 닫힘(다른 결함) | 개선 | 1,835 | 유력 |
| BS | 지금 닫힘 → 뒤집으면 깨짐 | 개선 | 1,454 | 열 전체 괄호 누락형(R185 확장 필요) |
| SCE | 지금 닫힘 → 깨짐 | 개선 | 580 | 〃 |
| BS | 지금 닫힘 → 깨짐 | **악화** | 517 | **적용 금지** |
| SCE | 지금 닫힘 → 깨짐 | **악화** | 754 | **적용 금지** |
| 기타 | | | 1,368 | 혼재 |

반대 사례의 원인: ① **금액 우연 일치**(예: `20210517000195` 기타포괄 546,000,000), ② **표시 관행 차이**(자기주식을 양수로 두고 상위 합계에서
차감하는 양식, `20221114000343`). → **직전 보고서 값만으로 덮어쓰면 안 된다.** 근거가 직전 **SCE 기말**이면 반대 사례 비율이 높아
신뢰도가 낮다. **BS 를 우선한다.**

## 3. 설계

### 원칙
1. **직접 덮어쓰지 않는다. 앵커(부호 증거)로만 쓴다.** 기존 R162 계열이 "앵커 + 항등식이 정확히 닫힘"일 때만 적용하므로,
   §2.2 의 "적용 금지" 유형(현재 표 항등식이 반대)은 자동으로 걸러진다.
2. **날짜로 맞춘다.** 잔액 행 라벨의 날짜 D 에 대해, 날짜가 D−1일(기초) 또는 D(기말)인 BS 열의 **같은 개념 라벨**
   (`concept_of_col_label`)에서 같은 절대값을 찾는다. 금액만 맞추는 현재 방식보다 우연 일치가 적다.
3. **BS 만 근거로 쓴다**(1차). 직전 SCE 기말은 신뢰도가 낮아(§2.2) 제외한다.
4. 잔액 행(기초·기말)에만 적용한다(R162-b 와 같은 이유: 변동행은 우연 일치 위험).

### 1단계 — 같은 필링 BS 전기말 열 (DB 의존 없음)
- `build_sign_anchors` 를 확장한다. BS 의 col 0 뿐 아니라 col 1·2 도 **열 날짜와 함께** 모은다:
  `(basis, label, date) → {values}`. 열 날짜는 보고서 종류로 정한다(사업보고서 col k = 기말 − k년,
  분·반기 col 1 = 직전 사업연도말).
- `_required_sign` 은 잔액 셀의 날짜 D 에 대해 D 또는 D−1일 앵커를 먼저 보고, 없으면 기존 col 0 앵커로 간다.
- 추출기 내부 변경만이라 `collect_new.py` 두 call site 와 재적재 경로에 **자동 반영**된다.
- 기대 효과: §2.3 의 2,556셀 + 롤포워드로 이어지는 같은 열 셀.

### 2단계 — 다른 필링(직전 사업보고서) BS (DB 의존)
- 추출기에 선택 인자 `prior_balances: dict[(basis, label, date)] → set[int]` 를 추가한다. 추출기는 DB 를 모르는 채로 유지한다.
- 적재 쪽(collect_new 두 call site, `ops._reload_rcept`, `note_lines_sync`)이 추출 직전에 DB 에서 채운다.
  대상: 이 필링 SCE 잔액 날짜들 중 필링 BS 열 날짜로 덮이지 않는 날짜 → 같은 회사, `period_end_date` 가 그 날짜인
  사업보고서(정본 정책 = 최초등록본 + 순차 정정)의 BS col 0.
- **연쇄 재적재**: 필링 X 가 재적재되면 X 를 참조한 필링(같은 회사, 다음 해 보고서들)도 결과가 바뀔 수 있다.
  참조 관계는 `filings`(회사·기간)만으로 계산된다. 따라서 **새 테이블 없이** `batch reload` 가 대상 필링의 "다음 연도 필링"을
  후속 대상으로 제안하게 한다(스키마 변경 없음).
- 순환 없음: 참조 방향이 항상 과거 → 현재다.

### 재확인 목록(자동 확정 불가)
- 다음 셀은 수동 재확인 목록으로 낸다. 직전 보고서가 없음 / 같은 금액이 없음 / 직전 보고서에 양·음이 모두 있음,
  **그리고** 현재 표의 롤포워드나 행 항등식이 깨짐.
- 표가 멀쩡한 셀은 직전 보고서가 없어도 재확인하지 않는다.

### 원익큐브 같은 "소액 오차" 사례
- 2원 차처럼 정확히 닫히지 않는 경우는 이 설계로도 자동 확정되지 않는다(원칙 1: 정확히 닫혀야 적용).
- 직전 보고서 증거 + 행 항등식 잔차 ≤ N원이면 확정하는 **허용오차 규칙**은 별도 판단 사항이다(§6 질문 2).

## 4. 파이프라인 편입 (runbook 준수)
1. 1단계: 추출기 내부 → 두 call site 자동. 회귀 테스트 + 켬/끔 재추출 측정 + 재적재.
2. 2단계: `collect_new.py` 메인·`--standardize-only` 두 call site, `ops._reload_rcept`, `collector/note_lines_sync.py`
   에서 `prior_balances` 를 채운다. 공용 헬퍼 1개로 만든다.
3. 소급 백필: 1단계 적용 뒤 영향 필링(켬/끔 재추출 차이)만 `batch add-targets` → `batch reload`.

## 5. 검증 계획
- 켬/끔 재추출(★`include_notes=True`)로 셀 단위 변화를 측정한다.
- 변화 셀마다 롤포워드·행 항등식 두 기준으로 판정하고, 명확한 악화가 있는 필링은 제외한다.
- §2.2 "적용 금지" 유형이 실제로 바뀌지 않았는지 확인한다(0 이어야 함).
- 표본 원문 대조: 원익큐브 `20160330000801` 외 유형별 3건씩.

## 6. 사용자 판단이 필요한 질문
1. 1단계(필링 내)만 먼저 할지, 2단계(필링 간 조회·연쇄 재적재)까지 할지.
2. 원익큐브 기타포괄처럼 **직전 보고서 증거 + 소액 잔차(예: ≤ 10원)**면 확정하는 허용오차 규칙을 둘지.
   둔다면 한도를 얼마로 할지.
3. 재확인 목록을 검증 워크트리 이슈로 올릴지(검증 측 권한), 문서 목록으로만 둘지.
