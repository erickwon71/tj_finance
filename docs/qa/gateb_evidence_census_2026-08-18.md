## 2. 증거강도 분포 (설계서 §5 질문 4개)

### Q1. pass 의 E1~E5 분포는?

pass 필드 4,218,532건(전 샤드 "필드: PASS" 합계와 정확히 일치, 교차검증 완료):

```
E1_EXACT      4,213,942   99.89%
E4_IDENTITY       3,600    0.09%
E2_SIGN             945    0.02%
E3_ROUNDING          45   0.001%
E5_HEURISTIC           0       0%
```

### Q2. E3(관용)+E5(휴리스틱)만으로 통과한 행이 몇 건인가?

**0건.** E5 가 0이라 E3 만 남는데, `evidence_detail` 이 `{"E3_ROUNDING": n}` 뿐인 행
(다른 등급 필드가 하나도 없는 행)을 직접 쿼리하면 0건 — E3 를 가진 45개 필드 전부
같은 행 안에 E1/E2/E4 필드가 최소 1개 이상 같이 있다. 설계서가 우려한 "가장 의심스러운
모집단"은 **현재 데이터에는 존재하지 않는다.**

### Q3. 그 행들이 지난 2주에 추가된 후보 확대 경로를 타고 있는가?

Q2 답이 0건이라 실질적으로 해당 없음. (E4_IDENTITY 3,600건 안에는 R32 업종파생 경로가
섞여 있으나, 현재 `evidence_detail` 저장 단위가 E4_IDENTITY 하나로 뭉뚱그려져 있어 4개
항등식 서브경로(revenue=cogs+gp / net_income=cf 대체 / net_income=지배+비지배 / R32
업종파생)를 저장값만으로는 못 나눈다 — 세분화하려면 `FieldAudit.evidence` 를 더 잘게
쪼개야 하는데, 이번 실측에서 그럴 필요가 드러나지 않아 범위 밖으로 남긴다.)

### Q4. M1/M2 재분류 시 현재 fail_a 239건 중 몇 건이 M2_WEAK 로 내려가는가?

**0건.** mismatch(VALUE_DIFF) 필드 1,129건(전 샤드 "필드: FAIL" 합계와 정확히 일치) —
**전부 M1_STRONG**, M2_WEAK 는 0건. `fail_b`(603행)까지 포함한 전체 모집단에서도
M2_WEAK 는 0건이다.

이유: `audit_fields()`에서 후보가 **전부** gapfill 이면 애초에 VALUE_DIFF 가 아니라
`GAPFILL_UNVERIFIED`(pending)로 빠진다(§1-B 경로 8 자체가 fail 승격을 안 시키는 안전판).
M2_WEAK 가 나오려면 후보가 **gapfill 과 non-gapfill 이 섞여 있는데 하필 gapfill 쪽이
최근접**이어야 하는, 설계서 §1-A 가 스스로 "혼합 풀에서만 발생하는 좁은 경로"라고 부른
그 경로다 — 실측 결과 이론상 경로는 실재(R23 인시던트로 확인됨)하지만 **현재 모집단에는
사례가 0건**이다.

## 3. Phase 3 결정에 주는 함의

- M1/M2 축만 놓고 보면 **현재 fail_a/fail_b 어느 쪽도 재분류되지 않는다** — 이번 실측은
  "증거강도가 fail_a 를 대량으로 fail_b 로 강등시킬 것"이라는 가설을 **기각**한다.
- pass 쪽도 마찬가지로 "관용·휴리스틱으로 통과한 오염된 pass" 우려가 **현재 데이터
  기준으론 근거가 약하다**(E3+E5 행 0건).
- 즉 이번 census 는 "게이팅을 바꿔야 한다"는 근거가 아니라 **"지금까지의 fail_a/fail_b
  분리가 이 데이터에서는 이미 타당했다"는 확인**에 가깝다. §6 선택지 A(보수, 현행 유지에
  가장 가까움)를 채택해도 실질적 손실이 없다는 뜻이지만, **최종 선택은 여전히 사용자
  결정 사항**(설계서 원칙 — 분포를 보기 전엔 고르지 않는다, 지금 봤으니 고를 수 있다).
- Phase 4(게이팅 산식 실제 교체) 착수 여부·안(A/B/C) 선택은 별도 확인 필요.
