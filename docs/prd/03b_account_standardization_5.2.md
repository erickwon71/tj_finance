# PRD 03 §5.2 — 계정 표준화(일반 vs 금융 2버킷) 산출 리포트

> 작성 2026-06-22. PRD 03 §5.2 "계정 표준화(일반 vs 금융 2버킷)" 의 산출물 = ① 버킷 분류 ②
> 갭 리포트(커버리지). 본 문서는 조사 결과·결정·산출물을 기록한다.

## 1. 버킷 분류 (산출물 ①)

- **컬럼**: `corporations.account_bucket` ∈ {`general`, `financial`}. 태깅 스크립트
  `scripts/tag_account_bucket.py`(데이터 기반·멱등).
- **분류 규칙(데이터 기반, 외부 업종표 불요)**: financial = **매출원가/매출총이익 구조 부재**
  (FY 행의 <20% 만 cogs/gp 보유) **∧ 금융수익 마커**:
  - 보험: `보험료`/`수입보험료`/`책임준비금`
  - 증권: `순영업수익`/`순수수료손익`
  - 카드·캐피탈: `신용판매수익`/`할부금융수익`/`리스금융수익`
  - 은행: `is.finance_income`(이자수익) 최대액 ≥ 영업이익 최대액 ×3 (이자수익이 주영업수익)
- **결과**: financial **75사**(삼성생명·한화생명·미래에셋증권·삼성카드·KB금융·신한지주·증권/보험/
  은행/캐피탈/창투), general 2,478사.
- **플랫폼·지주 분리**: NAVER·카카오·SK텔레콤·크래프톤 등은 매출원가가 없으나 이자수익이
  incidental 이라 **general** 로 정확 분리(무-COGS ≠ 금융).

> 금융 하위세분(은행/보험/증권/지주)은 필요 시 후속(현재 2버킷으로 충분). KRX 업종표 도입 시
> 정밀화 가능하나, 시각화 peer 그룹·버킷별 지표(예: 은행에 매출총이익률 미표시) 용도엔 2버킷 충분.

## 2. 커버리지 갭 리포트 (산출물 ②)

진단 `scripts/std_coverage_gap.py`. **핵심 std 필드 NULL률(FY 연결 fy≥2015)**:

| 필드 | 일반 NULL% | 금융 NULL% |
|------|-----------|-----------|
| revenue | 0.5% | 5.2% |
| operating_income | 0.3% | 2.7% |
| net_income | 0.3% | 2.9% |
| total_assets | 0.1% | 3.6% |
| total_equity | 0.1% | 3.5% |
| cfo | 0.7% | 6.4% |
| cogs | 3.0% | **97.8%** |
| gross_profit | 3.4% | **98.7%** |

**해석**:
- **표준화 커버리지는 이미 우수**: 일반 99.5%+, 금융 95%+ 핵심필드 매핑. iterations ⑧~⑪ Gate B
  피드백으로 금융 alias(영업수익·이자수익·수수료수익·보험료·EBT 가드·매출및지분법손익 등) 보강 완료.
- **금융 cogs/gross_profit 98% NULL = 정상**(금융업은 매출원가·매출총이익 구조 자체가 없음).
- 미매핑 상위 라벨(대손상각비·지분법이익·외화환산손익·working-capital CF 라인 등)은 **std 40 필드에
  없는 상세 항목 = 의도된 무손실 보존**(fact_v2 에 acode 보존, 필요 시 backfill).

## 3. 결정: 은행 revenue 는 NULL 유지 (사용자 확정 2026-06-22)

- **잔여 금융 revenue NULL 74사 = 은행·금융지주**(KB금융·하나금융지주·우리금융지주·NH투자증권·
  삼성카드 등). 이들은 **단일 '영업수익/매출' top-line 이 없다**(이자수익+수수료수익+… 분리 보고).
  예: KB금융 2023 연결 — 이자수익 29.1조·수수료수익 5.4조·영업이익 6.4조·당기순이익 4.6조,
  단일 매출 라인 부재.
- **결정**: 강제 합성 매핑은 **잘못된 값**(구조 클러 위험)이며 PM 마스터플랜 §0 "추정·보간으로
  빈칸을 채우지 않는다 — 모르면 비워두고 보고한다" 위반 → **revenue NULL 유지**. 이자수익
  (is.finance_income)·수수료수익(is.revenue)은 이미 매핑돼 분석 가능.
- 시각화에서 은행은 `account_bucket='financial'` 로 식별해 **매출/매출총이익률 미표시**, 대신
  순이자마진·이자수익·수수료수익·ROE 등 금융 지표 노출(B 단계 설계 반영).

## 4. 산출물 / 자산

- `corporations.account_bucket`(general/financial) + `scripts/tag_account_bucket.py`.
- 진단: `scripts/std_coverage_gap.py`(버킷별 커버리지), `scripts/std_fin_revenue_gap.py`(금융 revenue
  NULL 라벨).
- **코드 매핑 변경 없음**: 조사 결과 헤드라인 커버리지가 이미 충분(일반 99.5%·금융 95%)하고 잔여
  금융 revenue NULL 은 구조적(은행)이라 §5.2 의 "reference 보강"은 추가 alias 불요로 종결.

## 5. DoD 충족

- ✅ 버킷별 reference(분류) 산출 + 갭리포트(보강 전후: 이미 강함, 추가 보강 불요 확정).
- ✅ 미매핑률: 일반 0.1~0.7%(핵심), 금융 2.7~6.4%(은행 revenue 구조적 제외 시 더 낮음).
- ✅ 은행 revenue NULL = 의도(PM §0) 문서화.
