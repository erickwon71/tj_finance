(`docs/PARSING_RULES.md` R145 등재, pytest 1,089 passed) · **소급 백필 미실시**
· 선행 R144 · 관련 R27 / R28

## 1. 문제

계층2 IS 전사는 EPS(주당손익) 행을 **표 본류와 다른 경로**로 처리한다. 주당 금액은
표 단위(천원/백만원)가 아니라 **원** 단위이기 때문이다.

그 두 경로를 가르는 판정이 지금은 라벨의 **`"주당"` 부분문자열 단 하나**다.

| 위치 | 코드 |
|---|---|
| `fin2/extract/report_lines.py:653` | `if not cells or "주당" not in cells[0]: continue` (EPS 경로 진입) |
| `fin2/extract/report_lines.py:891` | `if "주당" in row.account_name and _looks_like_eps_amounts(...)` (본류 제외) |

이 판정이 두 방향으로 틀린다.

**(a) 거짓 양성 — 총액 행을 EPS로 오판**
`지배주주당기순이익`(= 지배 + **주주** + **당기**순이익)은 우연히 `주당` 부분문자열이
생긴 **총액** 행인데 EPS로 끌려간다. R27(2026-08-15)이 KBI메탈에서 발견한 결함이다.

**(b) 거짓 음성 — 진짜 EPS를 놓쳐 ×10⁶ 유령행 생성**
R144 조사에서 드러났다. 표가 백만원 선언이면 본류 게이트(`_looks_like_eps_amounts`,
표 단위를 이미 곱한 값으로 판정)가 EPS를 "EPS 아님"으로 보고 같은 행을 한 번 더
담는다. R144 가 이를 "원 단위 선언" · "금액 없는 `주당` 섹션 헤더" 두 증거로 막았지만,
**증거가 둘 다 없는 원문**이 남았다 — 2015+ 기준 38행 / 19필링 / 5개사.

```
NH투자증권 20160325001275 연결IS   표 선언 단위 = 백만원
  ['기본보통주당순이익 주석37>', '', '719', '', '373']
    → eps/  경로 :           719 원   (정답)
    → IS_C  경로 : 719,000,000 원   (유령, ×10⁶)
```

## 2. R27 의 기각 근거를 재검증했다 — **실측으로 뒤집혔다**

R27 은 라벨 텍스트 규칙을 다음 근거로 기각했다:

> "보통주주당이익"(=보통주+주당이익, 진짜 EPS)과 "지배주주당기순이익"(=지배+주주+
> 당기순이익, 버그)은 **서로 다른 조어구조에서 나온 문자열 레벨 동일 부분열**이라
> 정규식으로 원리적으로 구분 불가. "주당기"(주당+기) 뒤 글자로 가르는 것도 기각 —
> `기본주당기순이익`류(DART 관행상 **매우 흔한** 정상 EPS 표기)가 **대량으로** 걸림.

두 주장 다 실측과 다르다.

### 2-1. `기본주당기순이익` 계열은 "대량"이 아니다

`report_lines` 2015+ EPS 경로 전수 집계:

| | 값 |
|---|---|
| 전체 EPS 경로 | 363,565행 / 4,854종 |
| `주당기순이익` 계열 | **213행 / 32종 / 0.059%** |

"매우 흔한"이 아니라 **극소수**다. 회사별로도 13개사(한익스프레스 38행이 최대)에
그친다. 값 범위 8~2,467원 + 행 자체에 `(단위 : 원)` 표기 → **EPS 개념이 맞다**
(사용자 확인 2026-09-19).

### 2-2. 두 라벨은 구분된다 — `주당` **뒤**를 보면 된다

R27 은 공유 부분열 `주주당`만 봤다. `주당` 뒤를 보면 갈린다:

| 라벨 | `주당` 뒤 | 성격 |
|---|---|---|
| `보통주주당이익` | **이익** (수익어가 바로) | EPS |
| `지배주주당기순이익` | **기**순이익 (`당기순이익`이 걸쳐 있음) | 총액 |

여기에 두 번째 신호를 더하면 거의 완벽해진다 — **총액 행은 `기본`/`희석`(산정방식)을
쓰지 않는다.** 2015+ EPS 경로에서 `주당` **앞** 6글자 분포:

```
142,306행 '기본'          16,337행 '계속영업기본'     5,383행 '보통주기본'
111,120행 '희석'          11,927행 '기본및희석'       3,890행 '보통주희석'
                          11,214행 '계속영업희석'     2,452행 '우선주기본'
                           7,913행 '중단영업기본'
```

## 3. 제안하는 규칙 (A ∪ B ∪ C)

`주당` 단독 매칭을 버리고 **구조**로 판정한다. 자간 공백은 전부 `\s*` 허용
(R111 실측 — 옛 강조체가 `주 당 순 이 익`처럼 글자마다 공백을 넣는다).

```
A) 산정방식 선행 :  (기본|희석)  …≤8자…  주당
B) 수익어 후행   :  주당  (계속영업|중단영업|분기|반기|당기|연결|별도)?  (순이익|순손익|순손실|이익|손익|손실)
C) 섹션 문맥     :  그 행의 **section_path**(들여쓰기 조상 체인) 말단이 '주당' 을 포함하는가

EPS  ⟺  (A 또는 B) 또는 C
```

`C` 는 사용자 제안(2026-09-19)이며 **모호한 `주당+기순이익` 형태를 가르는 결정타**다.
원문이 스스로 밝힌 절 구조를 읽는 것이라 라벨 문자열 추측이 아니다.

★**2026-09-19 개정** — `C` 를 "직전의 금액 없는 헤더 행"이라는 **신규 국소 휴리스틱**으로
두려던 초안을 버리고, 이미 있는 `_assign_section_paths()`(들여쓰기 스택)를 재사용하는
쪽으로 바꿨다. 근거는 §3-4. 요약: 같은 판정을 두 번 구현하면 갈린다는 것을 R144 가 이미
증명했고, 들여쓰기 스택은 깊이까지 다루므로 "직전 행" 휴리스틱의 상위호환이다.

```
주당순손익                              ← 금액 없는 헤더 = EPS 섹션 시작
  기본주당계속사업순손익 (단위 : 원)   582  240  (167)
  기본주당중단사업순손익 (단위 : 원)   (1)
  기본주당기순이익 (단위 : 원)         581  240  (167)   ← C 로 EPS 확정
```

R144 가 이미 `in_eps_section` 으로 절반을 구현해 뒀다(금액 없는 `주당` 행을 헤더로
인식). R145 에서는 이것을 **판정의 1급 신호로 승격**하고 아래 §3-3 처럼 보강한다.

`B` 의 수식어 목록에 **`기` 단독은 넣지 않는다** — 그게 `당기순이익`이 걸친 총액
행(`주당기순이익`)과 갈리는 지점이다. 반대로 그런 라벨이라도 `기본`/`희석`이 앞에
있으면 `A` 로 EPS가 된다(`기본주당기순이익` = EPS, §2-1).

### 3-3. `C`(섹션 문맥) 실측 검증 — 함정이 어디 있는지

미커버 8종 중 유일한 **총액** 라벨 `지배기업주주당기순이익(손실)`(00160588
`20170515004474` 연결IS)의 원문 절 구조:

```
tr#20  당기순이익                       616,201 …
tr#21  당기순이익(손실)의 귀속            (금액 없음 = 헤더)      ← 총액 섹션
tr#22    지배기업주주당기순이익(손실)     270,700 …               ← 함정
tr#23    비지배지분당기순이익(손실)       345,501 …
…
tr#38  XV. 주당이익(단위:원)             (금액 없음 = 헤더)      ← EPS 섹션
tr#40    (1) 주당계속영업이익             3,839 …
tr#42    (3) 주당이익                     3,839 …
```

직전 헤더가 `당기순이익(손실)의 귀속`(= `주당` 없음) → `C` 불성립 → **총액으로 올바르게
배제**된다. 진짜 EPS 는 `XV. 주당이익(단위:원)` 헤더 아래 따로 있다. 값 크기로도
교차 확인된다(270,700원 vs 3,839원).

★**구현 주의 — `in_eps_section` 을 one-way latch 로 두면 안 된다.** 위 표처럼 총액
섹션이 EPS 섹션보다 **앞**에 오는 게 일반적이라 현재 R144 구현(한 번 True 면 유지)은
이 표에서 우연히 맞지만, 순서가 뒤집힌 표에서는 총액 행을 EPS 로 오판한다.
→ **§3-4 의 `section_path` 재사용으로 가면 이 주의사항 자체가 사라진다**(들여쓰기
스택은 애초에 latch 가 아니다). 국소 휴리스틱을 유지할 경우에만 유효한 경고로 남긴다.

### 3-4. ★왜 "섹션을 보고 있는데도" 다른 섹션 항목이 EPS 로 오분류되나

사용자 질문(2026-09-19). 답: **섹션을 보는 것은 본류뿐이고, EPS 경로는 그 판정이
내려지기 전에 같은 표를 따로 훑어서 행을 먼저 가져간다.** 세 겹의 구조적 이유가 있다.

**① 두 경로가 서로 다른 행 객체를 본다 — 조회 자체가 불가능하다**

```
report_lines.py:864   section_paths = _assign_section_paths(table_rows, statement)
                      #   ↑ extract_rows() 산출물(RowData)에 id() 로 키잉
report_lines.py:874   _emit_eps_lines(table, ...)          ← section_paths 를 안 넘긴다
report_lines.py:651     for tr in table_direct_rows(table) ← 원본 XML <TR> 을 다시 훑는다
report_lines.py:893   section_path = section_paths.get(id(row))   ← 본류만 조회
```

`_assign_section_paths` 는 `{id(RowData): path}` 를 돌려주는데 EPS 경로가 들고 있는
것은 `RowData` 가 아니라 `<TR>` 엘리먼트다. **넘겨줘도 키가 안 맞는다.**

**② EPS 경로의 진입 조건은 부분문자열 하나뿐이다**

```
report_lines.py:653   if not cells or "주당" not in cells[0]: continue
```

`지배기업주주당기순이익` 은 `지배기업주주` + `당기순이익` 인데 `주주`의 `주` 와
`당기`의 `당` 이 붙어 `주당` 이 된다. 그 뒤 게이트는 `_looks_like_eps_amounts()`
(값 크기)뿐이고 **구조는 한 번도 안 본다**. 백만원 표에서 원문 셀은 `270,700` 이라
EPS 크기로 완벽히 그럴듯하다 → 통과.

**③ 통과하면 본류에서 그 행이 사라진다**

```
report_lines.py:890   if row.account_name.strip() in eps_labels: continue
report_lines.py:892   if "주당" in row.account_name and _looks_like_eps_amounts(...): continue
```

그래서 총액이 **제 섹션에서 유실**되고, EPS 경로가 `section_path="주당손익"`
(`:724` 하드코딩) + `row_order/depth/node_role = NULL` 로 다시 적재한다.

실측(00160588 `20170515004474` 연결IS, 표 단위 백만원):

| 라벨 | 저장된 값 | adecimal | section_path | 판정 |
|---|---|---|---|---|
| 비지배지분당기순이익(손실) | 345,501,000,000 | -6 | `당기순이익(손실)의 귀속` | ✓ 본류 |
| 지배기업주주당기순이익(손실) | **270,700** | **0** | **`주당손익`** | ✗ EPS 오분류 |
| (1) 주당계속영업이익 | 3,839 | 0 | `주당손익` | ✓ 진짜 EPS |

616,201 = 270,700 + 345,501 → 지배지분 순이익임이 산술로 확정. **10⁶배 값 오류 +
총액 유실**이 동시에 난다. 바로 옆 형제 행은 올바른 `section_path` 를 받았다 —
파서는 이미 알고 있었고 EPS 경로가 묻지 않았을 뿐이다.

**★그런데 `section_path` 를 그냥 넘겨주는 것만으로는 부족하다 — 선결 결함이 있다**

같은 표를 `extract_rows()` 로 뽑아 실제 부여되는 경로를 찍어보면:

```
ind=0  당기순이익(손실)의 귀속      amt=[None,…]   path=None
ind=1    지배기업주주당기순이익(손실) 270,700…      path=당기순이익(손실)의 귀속   ← 함정. C로 배제 ✓
ind=1    비지배지분당기순이익(손실)   345,501…      path=당기순이익(손실)의 귀속
…
ind=0  포괄손익의 귀속              amt=[None,…]   path=None
ind=1    포괄손익, 지배기업 지분      278,131…      path=포괄손익의 귀속
ind=1    1. 보통주                  amt=[None,…]   path=포괄손익의 귀속
ind=2      (1) 주당계속영업이익       3,839…        path=포괄손익의 귀속>1. 보통주  ← ★EPS인데 엉뚱한 섹션
```

원문에 분명히 있는 **`XV. 주당이익(단위:원)` 헤더 행이 `extract_rows()` 에서 통째로
사라졌다.** 원인은 `_header_rule_name()` 의 `단위표기` 규칙(측정):

| 라벨 | `_is_header_cell` | 규칙 |
|---|---|---|
| `XV. 주당이익(단위:원)` | **True → 드롭** | 단위표기 |
| `기본주당기순이익 (단위 : 원)` | **True → 드롭** | 단위표기 |
| `XIV.주당이익` | False → 생존 | — |
| `주당손익 (주32)` | False → 생존 | — |
| `당기순이익(손실)의 귀속` | False → 생존 | — |

즉 **EPS 섹션 헤더와 EPS 데이터 행은, 인라인 단위선언을 달고 있다는 바로 그 이유로
섹션 트리를 만드는 뷰에서 제거된다.** 이게 애초에 EPS 경로가 `table_direct_rows()`
로 우회하게 된 이유이고(`_emit_eps_lines` docstring 의 사유 (a)), 우회의 대가로 섹션
트리를 잃은 것이다. 게다가 헤더가 사라진 탓에 들여쓰기 스택이 **직전 섹션
(`포괄손익의 귀속`)을 EPS 행에 물려주는** 2차 오염까지 이미 일어나 있다(위 표 마지막 줄).

같은 필링 별도IS 는 `XIV.주당이익`(단위 표기 없음)이라 살아남는다 — **같은 문서 안에서
연결/별도가 갈린다**는 것이 이 결함이 서식 우연에 좌우된다는 증거다.

→ 결론: `C` 를 쓰려면 **섹션 트리를 먼저 완전하게 만들어야 한다**(§5-2).

## 4. ★적용 범위 = **2015+ 한정** (pre-2015 무변경)

전수 측정 결과 pre-2015 에 같은 규칙을 적용하면 **양방향으로 손해**다.

| 방향 | 2015+ | pre-2015 |
|---|---|---|
| ① 현재 EPS경로 → 새 규칙이 "아니다" (**회귀 위험**) | 65행 / 8종 (0.018%) | **1,834행 / 204종 (2.212%)** |
| ② 현재 본류행 → 새 규칙이 "EPS다" (수정 효과) | 417행 / 164종 | **11,519행 / 7,350종** |

pre-2015 의 ②가 커 보이지만 **이건 효과가 아니라 사고다.** 그 라벨들이 R28 이 다룬
K-GAAP 통짜 블럽이기 때문이다:

```
'ⅩⅢ. 당기순이익주당 경상이익: 주당 순이익  :'
'(주당경상이익:원)      (주당순이익:원)'
```

이건 **헤드라인 당기순이익 행에 EPS 노트가 괄호로 곁들여진 것**이라 EPS 로 담으면
안 된다(R28 이 curated 키로 본류에 위임해 둔 바로 그 패턴). 새 규칙은 이 블럽을
`주당 순이익` 으로 읽어 EPS 로 끌어간다 — 11,519행 규모의 신규 오염.

→ **결론: 2015+ 에만 적용.** pre-2015 는 서식 자체가 다른 별개 트랙이라는 기존
아키텍처(R13 `legacy_pre2015.py`, 캠페인 era 게이트)와도 일치하고, 사용자 지시
("캠페인이 2015+니까 이 가드를 잘 지켜라", 2026-09-19)와도 맞는다.

게이트 값은 `_PRE2015_ROUTING_MAX_FY`(=2010)가 아니라 **2015** 를 쓴다 — 둘은 다른
경계다(전자는 파서 라우팅, 이건 라벨 관행 경계). 상수를 새로 두고 근거를 주석에 남긴다.

### 5-2. ★EPS 섹션을 구분하는 `section_path` 도입 (사용자 지시 2026-09-19)

§3-4 가 드러낸 대로 **선결 작업 → 신호 → 저장** 3단이다. 각 단계가 독립적으로 검증
가능하도록 순서를 지킨다.

**(가) 선결 — 섹션 트리에서 EPS 행이 사라지지 않게 한다**

★**초안 폐기(2026-09-19 재검토).** 처음엔 `extract_rows(keep_header_rows=True)` 로
트리 전용 추출을 하나 더 뽑고 `row_order` 로 키잉하려 했다. **틀렸다** —
`table_extractor.py:368` 에서 `row_order` 는 **실제로 emit 된 행에서만** 증가한다
(헤더 드롭 `continue` 는 :287 로 그 앞에 있다). 따라서 `keep_header_rows` 를 켜면
뒤따르는 모든 행의 `row_order` 가 밀려 **두 추출 간 키가 안 맞는다.**

채택안: **EPS 경로가 이미 훑고 있는 `table_direct_rows(table)`(원본 `<TR>`) 위에서
섹션 트리를 직접 만든다.** 원본 `<TR>` 순회에는 헤더 필터링이 아예 없으므로
`XV. 주당이익(단위:원)` 이 **처음부터 안 사라진다** — 즉 (가)의 문제가 우회가 아니라
소멸한다. 들여쓰기는 `_first_cell_indent(tr)`(이미 import 돼 있음, `:39`).

```
# 신설 — 들여쓰기 스택 알고리즘을 한 군데로
def _indent_stack_paths(items: list[tuple[int, str]]) -> list[str | None]:
    """[(raw_indent, label)] → 각 항목의 조상 체인('A>B'). 알고리즘 단일 출처."""

```

★**본류 경로(`extract_rows` · 본류 emit 루프 · `table_rows`)는 한 줄도 안 건드린다.**
따라서 본류 행의 `section_path`·`row_order` 저장값은 **그대로**고, 회귀 위험이
EPS 경로 안으로 봉쇄된다. §8-6(추출 2회 비용) 도 같이 소멸한다.

**(나) 신호 — `C` 판정 (실측으로 확정, §6-2)**

**말단만이 아니라 체인 전체**를 본다(§8-5 결정). 실측이 갈랐다 — 말단만 보면
`주당이익(단위 : 원)>계속영업` 류(EPS 헤더가 조부모, 말단은 `계속영업`)가 전부

| **체인 전체(C-any)** | **98.89%** | **41** |
| 직전 헤더(구 §3-3 휴리스틱) | 97.97% | 75 |

### 6-2. ★실측 — "주당이익 섹션 없이 EPS 항목만 있는 표가 있는가" (사용자 질문)

25행 중 18행은 **단위 선언조차 없다** — R144 의 두 증거가 모두 없는 바로 그 사례군이다.
이들은 `A∪B`(라벨 구조)로만 구제된다. **`C` 를 필수로 걸면 이 25행이 유실된다.**

`C` 단독으로만 걸리는 행(= `C` 를 단독 인정할 때 새로 EPS 가 될 행)은 **4행**
(`보통주당기순이익` 2, `우선주당기순이익` 2)뿐이고 **전부 라벨에 `주당` 을 포함**한다
→ `C ∧ '주당'` 보수화의 비용이 0 임이 확인됐다(§5-2 나).

## 8. 미결 — 착수 전 결정 필요

1. ~~미커버 `지배기업주주당기순이익(손실)` 처리~~ → **§3-3 에서 해소.** 직전 헤더가
   `당기순이익(손실)의 귀속`이라 `C` 로 총액으로 올바르게 배제된다. 지금 DB 에 EPS 로
   들어가 있는 것(270,700~491,670원)은 이번 변경으로 **고쳐지는 기존 오류**다. 다만
   본류로 넘어가면 표 단위가 곱해지므로 그 표의 단위 선언을 구현 전 확인할 것.
2. **`계속사업` 수식어 추가 여부**(§5-1) — 14행 해소 vs 규칙 확장 리스크.
   (`C` 가 들어오면 상당수가 섹션 문맥으로 자동 해소될 가능성이 높다 — 착수 시 재측정)
3. **적용 후 백필 범위** — ② 5개사만? 아니면 2015+ `주당` 보유 전 기업?
4. ~~**`C` 단독으로 EPS 를 인정할 것인가**~~ → **§6-2 실측으로 종결.** 안 한다.
   `(A∪B) ∪ (C ∧ '주당' 포함)`. 보수화 비용 0(단독 4행이 전부 `주당` 포함), 그리고
   섹션 헤더 없는 표가 0.68% 존재하므로 `C` 를 **필수 조건으로 쓸 수 없다**.
5. ~~**말단만 볼 것인가 체인 전체를 볼 것인가**~~ → **§6-2 실측으로 종결.** 체인 전체
   (`C-any`, 98.89% > 말단 97.54%). `주당이익(단위 : 원)>계속영업` 류가 갈랐다.
6. ~~**(가) 단계의 파급범위**~~ → **§5-2(가) 재설계로 소멸.** 원본 `<TR>` 위에서
   트리를 만들므로 `extract_rows` 를 두 번 돌리지 않고, 본류도 안 건드린다.

## 부록. 재현 방법

이 문서의 모든 수치는 아래로 재현된다(스크립트 아님, 1회성 집계).

```sql
-- 라벨 분포
SELECT label_raw, count(*) FROM report_lines
 WHERE report_fiscal_year >= 2015 AND statement='IS' AND source_ref LIKE 'eps/%'
 GROUP BY label_raw;
-- 본류 '주당' 행
SELECT label_raw, count(*) FROM report_lines
 WHERE report_fiscal_year >= 2015 AND statement='IS' AND source_ref LIKE 'IS%'
   AND label_raw LIKE '%주당%' GROUP BY label_raw;
```
