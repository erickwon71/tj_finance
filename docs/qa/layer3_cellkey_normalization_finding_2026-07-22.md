> 계기: 사용자 질문 "세부 항목 확장 때 필요한 라벨 정규화 키 보강, 필요하면 지금 하면 안 되나?"

## 0. 질문
델타 패치 셀키 = (statement, basis, col_index, section_path, **label_raw**). 기재정정이 라벨만
바꾸면(예 주석참조 `(주27,28,36)→(주27,28,37)`, 연번 `(7)→(6)`) 키가 어긋나 ONLY_ORIG+ONLY_AMEND
로 갈린다. label_raw 대신 **정규화 라벨**(`normalize_account_name`: 주석참조·로마숫자·연번·전각공백
제거)을 키에 쓰면 정렬될까? 지금 해야 하나?

## 1. 측정 (amendment 80쌍, 2015+ FY)

| 항목 | 값 |
|---|---:|

**충돌의 statement 분포:** SCE **454** · IS 4 · BS 2.

## 2. 충돌 원인 (SCE 99%)
- **날짜 접두 붕괴**: `2020.01.01 (기초자본)`·`2021.01.01`·`2022.01.01` → `normalize_account_name`
  의 `^[\d가-힣]+\.` 규칙이 `2020.` 을 벗겨 **셋 다 `01.01 (기초자본)` 하나로 붕괴**(값 3개 오합침).
- **행렬 반복 라벨**: SCE 는 (변동사유 × 자본구성요소) 행렬 → `유상증자`·`전환사채권행사` 가
  정당하게 반복. 정규화 라벨이 같아 충돌.

## 3. 판정
- **현재 6지표(BS/IS 최상위: 매출·영업이익·순이익·자산총계·자본총계·이익잉여금)는 label_raw
  키로 이미 안전.** BS/IS 충돌 6건/160 filing, 그나마 6지표 아님. 이 지표들은 라벨 안정 → 드리프트 0.
- **전역 정규화는 지금 순손해**: 드리프트 189 개선 대가로 충돌 460(SCE 454 파괴).
- **실패 모드는 안전**: 드리프트로 키가 어긋나도 원본+정정 셀이 둘 다 남아 canonical 충돌 → held
  (결측). **틀린 값은 안 나온다**(결측 > 오염).

## 4. 나중에(세부 line item 확장 시) 할 일 — 근거 보존
정규화 키는 **statement-scoped** 여야 한다:
- BS/IS/CF **face** 행: 정규화 적용(드리프트 189 개선, 충돌 ~6 — 개별 검증 후).
- **SCE 제외**: 행렬이라 라벨이 아니라 **col_label/위치(col_index) + 날짜** 로 키 구성(SCE 편입
  설계와 동일 원칙). 날짜 접두어 보존 필수.
- 연번 `(N)` 접두어만 벗기고 날짜 `YYYY.` 는 보존하는 **부분 정규화**도 후보(충돌 주범이 날짜라).
