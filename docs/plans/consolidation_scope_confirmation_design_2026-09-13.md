# 연결 비대상(non-consolidation-scope) 확정 설계 (2026-09-13)

상태: ✅ **Track 1(2015+) 구현+백필+재빌드 완전 종료(2026-09-13).** `consolidation_status`
분포(2015+, consolidated 95,292행): `consolidated` 76,258 / `no_subsidiary_confirmed`
18,161 / `fallback_unconfirmed` 873. 화면 캡션(주4) 실측 확인 완료(코리아에셋투자증권
00304915). `pytest` 988 passed(무관 기존 실패 3건 그대로, 회귀 0).

**★★★다음 세션 시작점★★★** — R106 후속: report_lines와 여전히 모순되는 41건("버킷A류
신규사례", §8 R106 참고) 원문대조 착수(사용자 지시, 2026-09-13). 아래 쿼리로 대상 목록
재현 가능:
```sql
SELECT DISTINCT f.rcept_no FROM filings f
JOIN report_lines rl ON rl.rcept_no = f.rcept_no
WHERE f.consolidation_evidence = 'no_consolidated_fs_track1'
  AND rl.basis = 'consolidated' AND rl.statement IN ('BS','IS','CF');
```

Track 2(pre-2015)는 여전히 📋설계만(§5 미해결 다수, 착수 안 함) — 41건 조사 이후 후순위.

관련: `basis_fallback`(`fin2/layer3/combine.py:3182-3192`), `is_ifrs_v3_design_2026-09-08.md`
(동일 패턴 선례), `basis_fallback_stale_reprint_exclusion_design_2026-09-08.md`(버킷A/B 구분).

## 1. 문제

사용자 요청: 보고 기간에 대해 **연결 비대상**(자회사가 없어 연결재무제표를 작성하지
않는 기업/기간)을 확정해서, 데이터 확인 시 이게 "연결데이터 없음"(=갭/버그처럼) 보이지
않도록 하고 싶다.

현재 코드를 확인한 결과 **아직 확정 로직이 없다.** 있는 건 두 가지뿐이고, 서로 안 맞물려
있다:

1. **`std_financials_v3.basis_fallback`**(`combine.py:3182-3192`) — 요청 basis(예: 연결)의
   `report_lines` 행이 그 기간에 **0건**이고 반대 basis(별도)만 있으면, 별도 값을 그대로
   복사해 연결 자리에 채우고 `basis_fallback=True`로 표시. 이건 "원문에 연결 섹션 자체가
   없다"는 것의 **간접 증거**(원문에 연결 표가 있었다면 파서가 report_lines 행을 만들었을
   것이므로)이긴 하지만, 두 가지 서로 다른 원인을 구분하지 못한다:
   - (a) 이 회사/기간은 **진짜로 연결 작성 의무가 없음**(정당)
   - (b) 원문엔 연결 표가 있는데 **파서가 못 잡은 결함**(버킷B처럼 이미 실측된 사례 있음)
2. **app 레이어 폴백 캡션**(`app/data/series.py:31-45`, `company_page.py` 등) — "요청 연도
   범위 전체가 비어있을 때만" 발동하는 훨씬 거친 별도 로직. 그런데 1번이 이미 연결 자리에
   값을 채워놨기 때문에, 화면에서 조회하면 행이 이미 존재 → **이 캡션이 거의 발동하지
   않는다.** 결과적으로 사용자는 화면의 "연결" 수치가 실제 연결인지 별도를 대신 채운
   것인지 **구분할 방법이 전혀 없다.**

그리고 "확정"에 걸맞은 근거(원문에 실제로 "연결대상 종속회사 없음"이라고 쓰여 있는지)는
지금 전혀 추출·저장하지 않는다 — `docs/qa/document_census_2026-07-30.md:63`에 이미
"연결대상종속회사현황(상세)" 섹션이 **미소비 갭**으로 기록돼 있다(120건 표본 중 51건에
존재, 소비처 없음).

## 2. 원문 증거 실측 (짐작 금지 원칙 — 실제 파일 확인)

`basis_fallback=True`인 실제 샘플 하나를 골라 원문을 직접 열어봤다:

- 코리아에셋투자증권(00304915), rcept `20260814002125`(2027Q1)
- 파일: `raw_report/KOSDAQ/00304915_코리아에셋투자증권/quarter/2027/20260814002125.xml`
- 해당 섹션:

  ```xml
  <SECTION-2 ACLASS="MANDATORY">
  <TITLE ATOC="Y" ENG="1. Status of subsidiaries subject to consolidation (Detailed)" ATOCID="43">1. 연결대상 종속회사 현황(상세)</TITLE>
  <P>- 해당사항 없음</P>
  </SECTION-2>
  ```

  → **"해당사항 없음"** = 이 회사는 이 분기 기준 연결대상 종속회사가 없다는 원문상의
  명시적 확정 문구.

- 다른 회사(강원에너지, 00100601) 사업보고서에서 이 섹션의 폼(form) 안내 문구를 확인:

  ```
  연결대상 종속회사 개황(연결재무제표를 작성하는 주권상장법인이 사업보고서,
  분기ㆍ반기보고서를 제출하는 경우에 한함)연결대상 종속회사 현황(요약)
  ```

  → 이 섹션은 **금감원 서식상 "연결재무제표를 작성하는 법인"에 한해 적용**된다는 문구가
  박혀 있다 — 즉 이 섹션의 존재/부재 자체, 그리고 그 내용("해당사항 없음" vs 실제 종속회사
  나열)이 연결 작성 대상 여부를 판단하는 **구조적 신호**로 쓸 수 있다는 근거.

이 두 표본으로 "특정 문구 검색 + 섹션 유무 확인"이라는 접근이 실제로 가능함은 확인했지만,
아래처럼 **아직 확정하지 못한 것**이 많다(§5 참고) — 이번 조사는 실행 가능성 확인 수준.

## 2-1. era 분산 표본 원문대조 결과 (2026-09-13, 사용자 지시로 착수)

`basis_fallback=True` 표본을 1999~2027년 3개 era 구간(pre2011 K-GAAP/2011~2014 전환기/
2015+ IFRS)에서 각 8건씩 무작위 추출(총 24건 + 정정본 체인 3건 추가)해 원문을 직접
`iconv`로 디코딩 후 대조했다. **결론: 신뢰할 수 있는 문구 신호는 시대에 따라 완전히
다르고, "종속회사 유무"만으로는 판정이 불충분하다.**

### (A) 2015+ 구간 — 강한 신호 확인, 문구 카탈로그 확정

이 구간 표본은 예외 없이 `SECTION-2`에 **"2. 연결재무제표"라는 정형 TITLE**이 있고,
연결비대상이면 그 바로 아래 `<P>`에 다음과 같이 명시적으로 "해당사항 없음" 계열 문구가
박혀 있었다(실측 8건 전부 일치, 변형 6종 확인):

| 회사 | rcept | 문구(원문 그대로) |
|---|---|---|
| CMG제약 | 20201112000389 | "당사는 보고서 작성기준일 현재 해당사항이 없습니다." |
| 휴니드테크놀러지스 | 20211112000105 | "보고서 제출일 현재 해당사항이 없습니다." |
| 국일신동 | 20160812000874 | "해당사항없음." |
| 아이로보틱스 | 20160516001720 | "해당사항 없음.&cr;" |
| 아센디오 | 20171228000002 | "당사는 보고서 제출일 현재 해당사항이 없습니다." |

6개 변형을 전부 잡을 수 있다("이/가", "습니다/음", 앞뒤 문구는 자유). 앵커는 `SECTION-2`의
`TITLE`이 정확히 **"2. 연결재무제표"**(사업보고서/분기/반기 공통, `AASSOCNOTE="D-0-3-2-0"`)
인 섹션 — 이게 §3-1에서 제안한 "종속회사 현황" 섹션보다 **훨씬 직접적이고 신뢰도 높은
신호**임이 이번 조사로 드러났다(연결비대상 여부를 원문이 그 자리에서 바로 선언).

### (B) 2011~2014 전환기 — 이 신호가 아예 없음

같은 8건 표본에서 **"2. 연결재무제표" TITLE 자체가 한 건도 없었다**(구형 서식이라 아직
이 정형 섹션이 도입되기 전). 대신 "연결대상 종속회사 개황/현황" 섹션이 간헐적으로
있었는데:
- 마이크로컨텍솔(20120813000220, 2012H1): "연결대상 종속회사가 없습니다." — 명확한
  긍정 신호.
- 나머지 7건은 "해당사항 없음"이 문서 어딘가엔 있었지만(다른 무관한 항목, 예: 소송/후발
  사건 등에서도 흔히 쓰는 상투어) **연결/종속회사와 직접 연결된 문맥인지 확인 안 됨**
  — 문맥 앵커 없이 이 문구만 grep하면 오탐 위험이 크다는 것도 이번에 확인.

### (C) ★★핵심 반례 — "종속회사 있음"이 "연결재무제표 있어야 함"을 보장하지 않음

pre2011 표본 중 **에넥스(00139764, 2010 Q3, rcept 20101115001425)**를 원문대조한 결과,
"바. 연결대상 종속회사 개황" 섹션에 **실제 종속회사가 지분율(76.34%)과 함께 명시**돼
있었다(중국 소재 자회사 1개). 그런데도 이 필링 전체에 "연결 재무상태표/손익계산서" 류
타이틀이 **단 하나도 없다** — 즉 이 회사는 종속회사가 실재하는데도 **그 시대(K-GAAP,
IFRS 의무화 2011년 이전) 인터림(분기) 연결재무제표 작성 의무가 없어서** 정상적으로
결측이다(`basis_fallback_stale_reprint_exclusion_design_2026-09-08.md`의 버킷A와 동일
메커니즘, "그 시대 연결 인터림 작성의무 없음"이 여기서도 실측으로 재확인됨).

**결론: §3-1에서 제안한 "종속회사 목록 유무" 판정 기준은 그 자체로 불충분하다.** 종속회사
없음(§2 표본처럼)은 확정 신호로 쓸 수 있지만, 종속회사 있음은 "그 기간에 연결재무제표가
있어야 한다"는 결론으로 이어지지 않는다(연도+기간유형[FY vs 인터림]에 따른 그 시대 작성
의무 규칙이 별도로 필요 — 이미 R63/버킷A·B 설계에서 다룬 문제와 동일 축).

### (D) 정정본 vs 최초등록본 — 이번 표본에서는 불변 확인(단, 일반화는 금지)

사용자가 우려한 "정정본이 최초본 누락분을 추가할 수 있다"는 점을 직접 검증하기 위해
정정 체인 2건을 원문대조했다:
- 강원에너지(00100601) 2022 Q1: 최초 20220516002477 → `[기재정정]` 20220524000266(8일 후)
  — "1. 연결대상 종속회사 현황(상세)" 표 내용 **완전히 동일**.
- 흥국화재(00103176) 2019 FY: 최초 20200330003683 → `[기재정정]` 20210114000331
  (**9.5개월 후**, 상당한 간격) — "2. 연결재무제표" 아래 "- 해당사항 없음" **완전히
  동일**.

→ 확인한 2건에서는 변화가 없었지만, **표본 2건으로 "절대 안 바뀐다"를 일반화할 수 없다.**
사용자 지적대로 정정본이 이 섹션 내용을 바꾸는 사례가 이론적으로 가능한 이상(예: 종속회사
신규 편입을 뒤늦게 기재정정), 구현 시 반드시 **그 (corp,fy,period)의 최신/canonical
rcept**(기존 `select_canonical_rcepts()`가 이미 다른 데이터에 적용 중인 최초등록본+델타
패치 정책과 동일 원칙)에서 evidence를 판정해야 하며, 최초 rcept만 보고 캐싱하면 안 된다.

### (E) 부산물 — 인코딩은 연도로 추측하면 안 됨(이번 조사 중 스스로 실수→정정)

조사 초반에 "2015+는 UTF-8, 그 이전은 EUC-KR"이라고 가정하고 2015+ 표본 일부를 EUC-KR로
강제 변환했다가 mojibake로 오판(거짓 "신호 없음")할 뻔했다 — 흥국화재 사업보고서는 2020년
필링인데도 실제로는 EUC-KR였다. **파일별로 인코딩을 실제 감지해야 하며 연도 컷오프로
가정하면 안 된다**(기존 `feedback-grep-euckr-locale-trap` 메모리와 같은 교훈, 이번엔
"pre-2010만 EUC-KR"이 아니라 "회사/서식에 따라 2020년에도 EUC-KR일 수 있다"는 게 새로
확인된 부분).

## 3. 제안 설계 (is_ifrs_evidence 패턴 재사용, §2-1 결과로 갱신)

`fin2/extract/ifrs_evidence.py`가 이미 "연도로 추측하지 않고, 원문에서 읽은 증거가 있을
때만 채운다. 증거 없으면 NULL"이라는 원칙으로 정확히 같은 모양의 문제(is_ifrs)를 풀어놓은
선례가 있다. 이 구조를 그대로 재사용:

1. **`fin2/extract/consolidation_evidence.py`(신규)** — 우선순위(§2-1 실측 기준, 위에서부터
   먼저 성립하는 신호를 채택, 짐작 금지):
   - **Track 1(강한 신호, 2015+ 주력)** — `SECTION-2`의 `TITLE`이 정확히 "2. 연결재무제표"
     (`AASSOCNOTE="D-0-3-2-0"`)인 섹션의 본문에 "해당사항"+"없" 토큰이 함께 있으면
     → `NO_CONSOLIDATED_FS_CONFIRMED`(이 기간 연결재무제표 자체가 원문상 없다고 확정).
     본문에 실제 표(BS/IS 등)가 있으면 → 폴백 대상 아님(애초에 `basis_fallback`이 False여야
     정상).
   - **Track 2(약한 신호, pre-2015 보조)** — "연결대상 종속회사 개황/현황" 섹션 본문에
     "없습니다"/"해당사항 없음"이 **그 섹션 문맥 안에서** 있으면 → `NO_SUBSIDIARY_CONFIRMED`.
     ★§2-1(C)에서 확인했듯 이 트랙은 **"종속회사 없음"만 확정할 뿐**, 종속회사가 있는
     경우엔 그 자체로 연결비대상 여부를 판정하지 않는다(그 시대 인터림 작성의무 규칙과
     별도 결합 필요 — 이번 설계 범위 밖, 기존 R63/버킷A·B 메커니즘에 위임).
   - 둘 다 없음 → `None`(판정 불가, 짐작 금지 — 호출측이 NULL로 남김).
   - ★어느 트랙이든 반드시 그 (corp,fy,period)의 **canonical(최신 정정 반영) rcept**에서
     판정한다(§2-1-D) — 최초등록본만 보고 캐싱 금지.
2. **`filings` 테이블에 캐시 컬럼 추가**(예: `consolidation_evidence`,
   `consolidation_evidence_detail`) — `ifrs_evidence`/`ifrs_evidence_detail`과 동일한
   자리에 캐싱해 재추출 비용 없이 재사용.
3. **`std_financials_v3`에 파생 컬럼**(예: `consolidation_status`) — `combine_full()`이
   `basis_fallback`을 세팅하는 바로 그 지점에서 위 evidence를 조회해 3분류:
   - `consolidated` — 정상적으로 연결 데이터 있음(폴백 아님)
   - `no_subsidiary_confirmed` — 폴백 발동 + Track 1 또는 Track 2로 원문 확인됨 → **이게
     사용자가 원하는 "확정"**
   - `fallback_unconfirmed` — 폴백은 발동했는데 원문 확인은 안 됨(섹션 없음/판정불가,
     또는 Track 2에서 종속회사가 있는데도 연결이 없는 §2-1(C) 케이스) → 지금처럼 "혹시
     버그일 수도 있는" 상태로 남김, 잠재적 결측 큐 후보

## 4. 화면 반영 (제안)

- `no_subsidiary_confirmed`: 기존의 애매한 "※ 연결 데이터 없음 → 별도 표시" 대신
  **"※ 이 기업/기간은 연결대상 종속회사 없음(원문 확인) → 별도 기준 표시"**처럼 명확한
  문구로 교체. 사용자가 "데이터 갭이 아니라 정상"임을 바로 알 수 있게.
- `fallback_unconfirmed`: 기존 문구 유지(아직 확정 못 했으니 과신 금지) — 다만 이 목록은
  향후 결측 스크리닝/원문대조 큐의 좋은 후보가 됨.
