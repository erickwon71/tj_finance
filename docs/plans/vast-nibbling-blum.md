# 재무데이터 재구축 — 4섹션 base · 최초보고서 · 추측 제거

## Context

**왜**: `extended_financials_n_facts_outlier` 트리아지 중 사용자 질문("주석에서 읽은 재무 data는
어떻게 처리하나?")에서 출발해, **주석·요약 데이터가 본문 재무제표 필드를 오염시켜 소비계층까지
도달**한 사실이 드러났다. std_v2 에 물리적 불가값 **307행/56개 기업**이 DQ<3 으로 **앱에 정상
데이터처럼 노출** 중(DB손해보험 2023 별도 이익잉여금 **8.5경원** 등).

조사 과정에서 더 큰 문제가 드러났다: **코드 곳곳이 원본을 읽는 대신 추측한다** — 단위를 모르면
백만원으로 가정하고, 배율 5개를 대입해 "매출 대비 비율이 그럴듯한" 것을 고르고, 후보가 여럿이면
큰 값을 집는다. **그리고 그 추측을 기록하지 않아, 추측한 값과 읽은 값이 DB 에서 구분되지 않는다.**

**목표**: 재무데이터(fact_v2 계열)를 **DART 4개 섹션 기준 · 최초보고서 기반 · 추측 없이**
재구축하고, "주석은 주석"과 "원본만 적재"를 **스키마로 강제·증명** 가능하게 만든다.

## 1. 사용자 질문의 답 — "재파싱 없이 가능한가?"

### ❌ **불가능.** (단 재다운로드는 불요 — raw_report 189,128 파일 보존)

| 요구 | 재파싱 없이? | 근거 |
|---|---|---|
| 4섹션 base 정리 | ❌ | `FactV2` 에 섹션 출처 컬럼 없음(전 22컬럼 확인) |
| 요약재무정보 적재분 삭제 | ❌ | 요약 경로(`text.py:401`)와 본문 경로(`text.py:289`)가 **동일한 `_row_to_fact`** 호출 → `source_ref`·`acontext_raw`·`source_format` **완전 동일**(`BS_C/자산총계`) |
| **코드 추측값 삭제** | ❌ | **추측한 값과 읽은 값을 구분하는 컬럼이 없다**(§2-A) → *"오염된 것만 골라 삭제"를 SQL 로 표현 불가* |
| 정정본 데이터 삭제 | ✅ | `rcept_no → filings.report_nm LIKE '%정정%'`. 원본 팩트도 fact_v2 에 보존(리메드: 원본 780·정정본 271 공존) |

**⟹ 재파싱 확정.** 그렇다면 정정본·요약·추측값 제거는 "삭제"가 아니라 **"애초에 만들지 않는"**
방식이 단순·안전하다.

**★ 결정적 단서**: **같은 코드로 재파싱하면 같은 추측이 그대로 재생산된다.**
→ **추측 로직 제거가 재파싱보다 먼저다.**

## 2. 원칙 (사용자 확정)

> **"오염된 데이터는 없는게 더 좋아."**
> **"로직으로 값을 정해서 db에 적재하는 것은 없도록 해."**
> **"명확하지 않은 것은 나와함께 명확히하고 파서 개선하면서 넘어가고."**

1. **결측 > 오염.** 애매하면 넣지 않는다.
2. **추측·선택·강제 금지.** 단위 추측, max-abs 채택, 항등식 강제, 열 위치 추론 → **전부 제거**.
3. **투명한 파생은 허용하되 반드시 표시**(사용자 확정). 입력이 **둘 다 명확히 읽힌 값**일 때의
   계산(EBITDA=영업이익+D&A, Q2=H1−Q1, CY=ΣCQ)은 추측이 아니다. 단 `is_discrete`·`derivation`·
   `source_lineage` 로 파생임을 명시하고, **입력이 하나라도 없으면 NULL**(추정 금지).
4. **애매하면 사용자 확인 → 파서 개선**(사용자 확정). **패턴 단위**로 묶어 대표 사례만 확인하고,
   파서를 고쳐 그 패턴 전체를 해결한다. 값 하나하나를 손으로 채우지 않는다.

**근거(실증)**: 금액 이상 신호만으로는 오탐/진짜가 갈리지 않았다 — **3S**(원문 `(단위:백만원)`
오기·진짜) · **네오크레마**(정정본 `(단위:천원)` 오기·진짜) · **엔케이젠**(납기 2027~32 장기계약,
**정상·오탐**). 셋 다 같은 신호였고 **사용자 원문 확인으로만 갈렸다.** 자동 추측은 이 셋을 반드시 틀린다.

## 3. 확정 결정

1. **섹션 4분할 적재**: `2.연결재무제표`→`bs./is./cf.`(consolidated) · `4.재무제표`→(separate) ·
   `3.연결재무제표 주석`/`5.재무제표 주석`→**`note.*` 전용**. `1.요약재무정보`→**적재 제외**.
2. **최초 보고서만.** 정정본은 **fact_v2 에서도 제외**(= 추출 대상에서 배제). → **Track 2** 에서 재편입.
3. **본문 없는 (기업,기간) → 제외 + 별도 리스트.** 처리는 나중에 재논의.
4. **정정본만 있고 원본 없는 108개 기간(0.07%) → 제외 + 별도 리스트.**
5. **재무데이터(fact_v2 계열)만 대상.** 다른 테이블은 범위 밖 — **단 "오염 없음"이 아님**(§5).
6. **추측값 제거**(§2 원칙 2), **투명 파생은 표시 후 허용**(§2 원칙 3).
