## 1. 고친 것

### F1 — 단위 판정을 표 단위에서 **열 단위**로 (`681e42a`)

종전에는 표가 선언한 첫 금액 배수를 **표의 전 열**에 적용했다. 그래서 `이자율(%)` 열에
2,228조원이 들어갔다(실측 6,130,738 행). 또 `단위` 직후에 금액 토큰을 요구하는 정규식 한 줄
때문에 `'(단위 : 주, 천원)'` 같은 표는 **통째로 버려졌다**(2.63M 셀).

- `detect_unit_tokens()` — 선언을 **토큰 리스트**로 읽는다. 서술문 오인은 3중 게이트로 막는다
  (본문이 닫혀 있을 것 · 모든 토큰이 짧을 것 · 하나 이상이 **알려진** 단위일 것).
- `fin2/extract/units.py` — 열 헤더 원문으로 **열마다** 배수를 정한다. 확정 못 한 열은
  `value_won=NULL` + `value_raw`(셀 원문). **NULL 이 정보 손실이 아니게 만드는 장치**다.
- 주석 전사 범위를 '데이터행이 있는 표 전부'로 넓혔다(종전엔 금액 선언 표만).

### F2 — 헤더 의심행을 삭제 대신 전사 (`14cd8e7`)

행이 기간축인 주석 표(유형자산 증감표)에서 '당기말'·'전기초' 는 열 헤더가 아니라 **데이터 행
라벨**이다. 규칙에 걸린 행을 버리는 대신 규칙 이름을 `header_hint` 로 남기고, 판단은 계층3 이
한다. 계층3 가드를 **같은 커밋에** 넣었다(가드 없이 배포하면 D&A 합산이 오염된다).

### F4 — 데일리에 본문 배선 (`a2bb0c7`) · 계획의 P0

`collect_new.py` 는 같은 호출로 **본문 행을 만들어 놓고 버리고 있었다.** 두 call site 모두
배선했고, 기업 하나를 지웠다 다시 넣어 **실제 적재로** 확인했다(body 0 → 214행).

## 3. ★이 세션에서 내가 틀렸던 것 (같은 실수 반복 금지)

전부 **집계만 보고 판단했다가 원문·코드를 열어 보고 뒤집힌** 경우다.

1. **D1 규모 4.9M 셀 → 실제 약 50만.** '항목 경계 안에 선언이 있다'는 측정이 **앞 소항목의
   선언까지** 관장 선언으로 셌다. 형제 사슬을 출력해 보고 알았다.
2. **오염 1,598,596 행 → 0.** 검증기가 로더와 **다른 판정식**을 썼다(선언 접두
   `(원화단위 : 천원, 외화단위 : 1단위)>차입금액` 이 marker 에 걸림). 로더와 같게 맞추니 0.
3. **컬럼 drop 후 값 검사가 깨졌다.** drop 뒤에는 `WHERE table_title IS NOT NULL` 이 아니라
   **컬럼 존재 여부**로 봐야 한다.
4. 열 표지를 넓히다 **기간 표지를 비금액에 넣을 뻔했다** — 만기분석의 '6개월이내' 칸은
   천원 금액이다. 원문 대조에서 잡았다.
5. 도구 초판이 **'넓은 창'에서 남의 표 선언을 주워** 99% 회수 가능이라고 셌다(→ 53% → 실제 10.7%).

⇒ **집계가 나오면 원문 한 건을 열어 확인한 뒤에 서술한다.** 이번에 이 규칙으로 거짓양성
3 종(`계약금액($)`·`10%상승`·선언 접두)을 잡았고, 그것들은 전부 코드 주석에 근거를 남겼다.
