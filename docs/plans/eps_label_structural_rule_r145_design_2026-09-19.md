# EPS 행 판정을 `"주당"` 부분문자열에서 **구조 패턴**으로 교체 (R145 설계)

작성 2026-09-19 · 상태 **설계 검토 대기(미구현)** · 선행 R144
(`docs/PARSING_RULES.md` R144) · 관련 R27 / R28

---

## 1. 문제

계층2 IS 전사는 EPS(주당손익) 행을 **표 본류와 다른 경로**로 처리한다. 주당 금액은
표 단위(천원/백만원)가 아니라 **원** 단위이기 때문이다.

그 두 경로를 가르는 판정이 지금은 라벨의 **`"주당"` 부분문자열 단 하나**다.

| 위치 | 코드 |
|---|---|
| `fin2/extract/report_lines.py:653` | `if not cells or "주당" not in cells[0]: continue` (EPS 경로 진입) |
| `fin2/extract/report_lines.py:891` | `if "주당" in row.account_name and _looks_like_eps_amounts(...)` (본류 제외) |

이 판정이 두 방향으로 틀린다.

**(a) 거짓 양성 — 총액 행을 EPS로 오판**
`지배주주당기순이익`(= 지배 + **주주** + **당기**순이익)은 우연히 `주당` 부분문자열이
생긴 **총액** 행인데 EPS로 끌려간다. R27(2026-08-15)이 KBI메탈에서 발견한 결함이다.

**(b) 거짓 음성 — 진짜 EPS를 놓쳐 ×10⁶ 유령행 생성**
R144 조사에서 드러났다. 표가 백만원 선언이면 본류 게이트(`_looks_like_eps_amounts`,
표 단위를 이미 곱한 값으로 판정)가 EPS를 "EPS 아님"으로 보고 같은 행을 한 번 더
담는다. R144 가 이를 "원 단위 선언" · "금액 없는 `주당` 섹션 헤더" 두 증거로 막았지만,
**증거가 둘 다 없는 원문**이 남았다 — 2015+ 기준 38행 / 19필링 / 5개사.

```
NH투자증권 20160325001275 연결IS   표 선언 단위 = 백만원
  ['기본보통주당순이익 주석37>', '', '719', '', '373']
    → eps/  경로 :           719 원   (정답)
    → IS_C  경로 : 719,000,000 원   (유령, ×10⁶)
```

## 2. R27 의 기각 근거를 재검증했다 — **실측으로 뒤집혔다**

R27 은 라벨 텍스트 규칙을 다음 근거로 기각했다:

> "보통주주당이익"(=보통주+주당이익, 진짜 EPS)과 "지배주주당기순이익"(=지배+주주+
> 당기순이익, 버그)은 **서로 다른 조어구조에서 나온 문자열 레벨 동일 부분열**이라
> 정규식으로 원리적으로 구분 불가. "주당기"(주당+기) 뒤 글자로 가르는 것도 기각 —
> `기본주당기순이익`류(DART 관행상 **매우 흔한** 정상 EPS 표기)가 **대량으로** 걸림.

두 주장 다 실측과 다르다.

### 2-1. `기본주당기순이익` 계열은 "대량"이 아니다

`report_lines` 2015+ EPS 경로 전수 집계:

| | 값 |
|---|---|
| 전체 EPS 경로 | 363,565행 / 4,854종 |
| `주당기순이익` 계열 | **213행 / 32종 / 0.059%** |

"매우 흔한"이 아니라 **극소수**다. 회사별로도 13개사(한익스프레스 38행이 최대)에
그친다. 값 범위 8~2,467원 + 행 자체에 `(단위 : 원)` 표기 → **EPS 개념이 맞다**
(사용자 확인 2026-09-19).

### 2-2. 두 라벨은 구분된다 — `주당` **뒤**를 보면 된다

R27 은 공유 부분열 `주주당`만 봤다. `주당` 뒤를 보면 갈린다:

| 라벨 | `주당` 뒤 | 성격 |
|---|---|---|
| `보통주주당이익` | **이익** (수익어가 바로) | EPS |
| `지배주주당기순이익` | **기**순이익 (`당기순이익`이 걸쳐 있음) | 총액 |

여기에 두 번째 신호를 더하면 거의 완벽해진다 — **총액 행은 `기본`/`희석`(산정방식)을
쓰지 않는다.** 2015+ EPS 경로에서 `주당` **앞** 6글자 분포:

```
142,306행 '기본'          16,337행 '계속영업기본'     5,383행 '보통주기본'
111,120행 '희석'          11,927행 '기본및희석'       3,890행 '보통주희석'
                          11,214행 '계속영업희석'     2,452행 '우선주기본'
                           7,913행 '중단영업기본'
```

## 3. 제안하는 규칙 (A ∪ B ∪ C)

`주당` 단독 매칭을 버리고 **구조**로 판정한다. 자간 공백은 전부 `\s*` 허용
(R111 실측 — 옛 강조체가 `주 당 순 이 익`처럼 글자마다 공백을 넣는다).

```
A) 산정방식 선행 :  (기본|희석)  …≤8자…  주당
B) 수익어 후행   :  주당  (계속영업|중단영업|분기|반기|당기|연결|별도)?  (순이익|순손익|순손실|이익|손익|손실)
C) 섹션 문맥     :  직전의 **금액 없는 헤더 행**이 '주당' 을 포함하는가(= EPS 섹션 안인가)

EPS  ⟺  (A 또는 B) 또는 C
```

`C` 는 사용자 제안(2026-09-19)이며 **모호한 `주당+기순이익` 형태를 가르는 결정타**다.
원문이 스스로 밝힌 절 구조를 읽는 것이라 라벨 문자열 추측이 아니다.

```
주당순손익                              ← 금액 없는 헤더 = EPS 섹션 시작
  기본주당계속사업순손익 (단위 : 원)   582  240  (167)
  기본주당중단사업순손익 (단위 : 원)   (1)
  기본주당기순이익 (단위 : 원)         581  240  (167)   ← C 로 EPS 확정
```

R144 가 이미 `in_eps_section` 으로 절반을 구현해 뒀다(금액 없는 `주당` 행을 헤더로
인식). R145 에서는 이것을 **판정의 1급 신호로 승격**하고 아래 §3-3 처럼 보강한다.

`B` 의 수식어 목록에 **`기` 단독은 넣지 않는다** — 그게 `당기순이익`이 걸친 총액
행(`주당기순이익`)과 갈리는 지점이다. 반대로 그런 라벨이라도 `기본`/`희석`이 앞에
있으면 `A` 로 EPS가 된다(`기본주당기순이익` = EPS, §2-1).

### 3-1. 커버리지 (2015+, 363,565행)

| | 행 | 비율 |
|---|---|---|
| A ∪ B 커버 | 363,500 | **99.982%** |
| 미커버 | 65 (8종) | 0.018% |

### 3-2. 함정 배제 검증

| 라벨 | 새 규칙 | 기대 | |
|---|---|---|---|
| `지배주주당기순이익` | 아님 | 아님 | ✓ 총액 보존 |
| `비지배주주당기순이익` | 아님 | 아님 | ✓ |
| `지배기업주주당기순이익(손실)` | 아님 | 아님 | ✓ |
| `보통주주당이익` | EPS | EPS | ✓ **R27이 "구분 불가"라던 쌍** |
| `기본주당기순이익 (단위 : 원)` | EPS | EPS | ✓ |

### 3-3. `C`(섹션 문맥) 실측 검증 — 함정이 어디 있는지

미커버 8종 중 유일한 **총액** 라벨 `지배기업주주당기순이익(손실)`(00160588
`20170515004474` 연결IS)의 원문 절 구조:

```
tr#20  당기순이익                       616,201 …
tr#21  당기순이익(손실)의 귀속            (금액 없음 = 헤더)      ← 총액 섹션
tr#22    지배기업주주당기순이익(손실)     270,700 …               ← 함정
tr#23    비지배지분당기순이익(손실)       345,501 …
…
tr#38  XV. 주당이익(단위:원)             (금액 없음 = 헤더)      ← EPS 섹션
tr#40    (1) 주당계속영업이익             3,839 …
tr#42    (3) 주당이익                     3,839 …
```

직전 헤더가 `당기순이익(손실)의 귀속`(= `주당` 없음) → `C` 불성립 → **총액으로 올바르게
배제**된다. 진짜 EPS 는 `XV. 주당이익(단위:원)` 헤더 아래 따로 있다. 값 크기로도
교차 확인된다(270,700원 vs 3,839원).

★**구현 주의 — `in_eps_section` 을 one-way latch 로 두면 안 된다.** 위 표처럼 총액
섹션이 EPS 섹션보다 **앞**에 오는 게 일반적이라 현재 R144 구현(한 번 True 면 유지)은
이 표에서 우연히 맞지만, 순서가 뒤집힌 표에서는 총액 행을 EPS 로 오판한다. **금액 없는
헤더 행을 만날 때마다 플래그를 다시 계산**한다(그 헤더가 `주당` 포함이면 True, 아니면
False).

## 4. ★적용 범위 = **2015+ 한정** (pre-2015 무변경)

전수 측정 결과 pre-2015 에 같은 규칙을 적용하면 **양방향으로 손해**다.

| 방향 | 2015+ | pre-2015 |
|---|---|---|
| ① 현재 EPS경로 → 새 규칙이 "아니다" (**회귀 위험**) | 65행 / 8종 (0.018%) | **1,834행 / 204종 (2.212%)** |
| ② 현재 본류행 → 새 규칙이 "EPS다" (수정 효과) | 417행 / 164종 | **11,519행 / 7,350종** |

pre-2015 의 ②가 커 보이지만 **이건 효과가 아니라 사고다.** 그 라벨들이 R28 이 다룬
K-GAAP 통짜 블럽이기 때문이다:

```
'ⅩⅢ. 당기순이익주당 경상이익: 주당 순이익  :'
'(주당경상이익:원)      (주당순이익:원)'
```

이건 **헤드라인 당기순이익 행에 EPS 노트가 괄호로 곁들여진 것**이라 EPS 로 담으면
안 된다(R28 이 curated 키로 본류에 위임해 둔 바로 그 패턴). 새 규칙은 이 블럽을
`주당 순이익` 으로 읽어 EPS 로 끌어간다 — 11,519행 규모의 신규 오염.

→ **결론: 2015+ 에만 적용.** pre-2015 는 서식 자체가 다른 별개 트랙이라는 기존
아키텍처(R13 `legacy_pre2015.py`, 캠페인 era 게이트)와도 일치하고, 사용자 지시
("캠페인이 2015+니까 이 가드를 잘 지켜라", 2026-09-19)와도 맞는다.

게이트 값은 `_PRE2015_ROUTING_MAX_FY`(=2010)가 아니라 **2015** 를 쓴다 — 둘은 다른
경계다(전자는 파서 라우팅, 이건 라벨 관행 경계). 상수를 새로 두고 근거를 주석에 남긴다.

## 5. 구현 계획

`fin2/extract/report_lines.py` 한 파일, 두 곳. **판정은 헬퍼 하나로 단일화**한다 —
R144 가 "두 경로가 같은 판정을 각자 하면 갈린다"를 이미 증명했다.

```
# 신설
_EPS_METHOD_RE / _EPS_PROFIT_RE            # §3 의 A, B
def _is_eps_label(label: str, report_fiscal_year: int) -> bool
    # fy < 2015 면 기존 동작("주당" 부분문자열) 그대로 반환 — §4

# :653  _emit_eps_lines 진입
-   if not cells or "주당" not in cells[0]: continue
+   if not cells or not _is_eps_label(cells[0], report_fiscal_year): continue

# :891  _emit_section_lines 본류 제외 (R144 로 추가된 eps_labels 스킵은 유지)
-   if "주당" in row.account_name and _looks_like_eps_amounts(row.amounts):
+   if _is_eps_label(row.account_name, report_fiscal_year) and _looks_like_eps_amounts(...):
```

`_looks_like_eps_amounts`(R27 값크기 게이트)와 `_EPS_KGAAP_HEADLINE_NOT_EPS_KEYS`
(R28 curated)는 **그대로 둔다** — 새 규칙은 진입 게이트를 좁힐 뿐이고, 두 안전장치는
그 뒤에서 계속 작동한다.

### 5-1. 미커버 8종 처리

2015+ 미커버 65행:

| 행 | 라벨 | 성격 |
|---|---|---|
| 17 | `우선주당기순이익` | 진짜 EPS(주당+기순이익 형태) |
| 10 | `지배기업주주당기순이익(손실)` | **총액** — 배제가 정답 |
| 9 | `보통주당기순손익` / 9 `보통주당기순이익` | 진짜 EPS |
| 9+5 | `지배기업소유주지분 주당 계속사업손익` | 진짜 EPS(`계속사업` 미등록) |
| 5 | `1.계속영업주당손이익` | 오타(`손이익`) |
| 1 | `제1우선주당중단 사업순이익` | 진짜 EPS |

→ `계속사업`을 §3 수식어 목록에 추가하면 14행이 해소된다. 나머지는 **R28 과 같은
방식의 curated 키**(rcept×statement×basis×table_seq×label 5-튜플)로 처리한다.
전부 1개사씩이라 블랭킷 규칙을 넓히는 것보다 안전하다.

   `당기순이익(손실)의 귀속`이라 `C` 로 총액으로 올바르게 배제된다. 지금 DB 에 EPS 로
   들어가 있는 것(270,700~491,670원)은 이번 변경으로 **고쳐지는 기존 오류**다. 다만
   본류로 넘어가면 표 단위가 곱해지므로 그 표의 단위 선언을 구현 전 확인할 것.
2. **`계속사업` 수식어 추가 여부**(§5-1) — 14행 해소 vs 규칙 확장 리스크.
   (`C` 가 들어오면 상당수가 섹션 문맥으로 자동 해소될 가능성이 높다 — 착수 시 재측정)
3. **적용 후 백필 범위** — ② 5개사만? 아니면 2015+ `주당` 보유 전 기업?
4. **`C` 단독으로 EPS 를 인정할 것인가** — 위 식은 `(A∪B)∪C`다. `C` 만으로 인정하면
   EPS 섹션 아래 섞여 들어온 비-EPS 행까지 EPS 가 된다. 보수적으로 `C ∧ (라벨에 '주당'
   포함)` 으로 제한하는 안도 있다 — 착수 전 전수 차분(§6-1)으로 실제 차이를 보고 결정.

## 부록. 재현 방법

이 문서의 모든 수치는 아래로 재현된다(스크립트 아님, 1회성 집계).

```sql
-- 라벨 분포
SELECT label_raw, count(*) FROM report_lines
 WHERE report_fiscal_year >= 2015 AND statement='IS' AND source_ref LIKE 'eps/%'
 GROUP BY label_raw;
-- 본류 '주당' 행
SELECT label_raw, count(*) FROM report_lines
 WHERE report_fiscal_year >= 2015 AND statement='IS' AND source_ref LIKE 'IS%'
   AND label_raw LIKE '%주당%' GROUP BY label_raw;
```
