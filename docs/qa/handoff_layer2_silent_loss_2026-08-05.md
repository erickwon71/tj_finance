### ★ 다음 사람이 알아야 할 것

**(a) 표본으로는 안 보이는 결함이 있다.** #6 은 무작위 497건에서 **0건**이었는데 전수
102,123건에서 **255건**이 나왔다(최악 NHN KCP 886표→98표, LG화학·롯데칠성음료·하나금융지주
등 대형사 다수). `scripts/audit_xml_truncation.py` 가 그 도구다 — 원문 `<TABLE` 수 대비
파싱 표 수. **파서를 고친 뒤에는 이걸 전수로 돌릴 것.**

**(b) 같은 결함이 4번 다른 모양으로 돌아왔다.** 처분계산서 오적재는 구조(#2) → 구조(각주표)
→ 이름 오기 → 내용 동일 순으로 네 번 나왔다. **구조·이름·내용 세 층을 다 막아야** 끝났다.
검증을 `statement` 별로 갈라 보지 않았으면 전부 놓쳤다.

**(c) 형태를 열거하지 말고 구조로 일반화할 것.** #6 은 `=""값"` 한 형태만 처리하던 규칙이
`=""값""`·`="값""`·`="…("X")"` 에 뚫린 것이다. "진짜 닫는 따옴표는 뒤가 다음 속성이거나
태그 끝" 이라는 구조로 바꿔서 끝났다.

## 4. ★ 내가 틀렸던 것 (반복 주의)

1. **`&cr;` 가 웅진 절단의 원인이라는 가설 → 기각.** 제거해도 표 수 그대로(101/929)였고,
   `&cr;` 는 전체의 **60.4%(629,477회)** 에 있는데 그 파일들은 멀쩡했다. 진짜 원인은
   이스케이프 안 된 `<` **하나**(`<?틴 블레이크의 걸작선>`)였다.
2. **"단위 미선언 36건" → 오분류.** 세화피앤씨는 재무상태표에 `(단위 : 원)` 이 **있었고**
   파서도 읽었다. 진짜 문제는 그 BS 가 **분류 단계에서 유실**된 것이었다.
   → 사용자가 원문을 붙여넣어 지적해줘서 드러났다.
3. **"처분계산서 흔적 7,667 filing" → 내 질의가 과잉.** 95%가 BS 의 정상 자본 항목
   `미처분이익잉여금(미처리결손금)`. 나중에 CF 10행도 정상 항목(`미처분이익잉여금의 감소`
   = 영업활동 자산·부채 변동)이었다. **진짜 오적재는 statement 별로 갈라야 보인다.**
4. **"단위 거짓부재 6건" → 1건.** 감사 도구가 형제를 -6까지 훑어 **재무제표 경계를 넘어**
   앞 표 단위를 주워왔다(엘브이엠씨 586조 사고와 같은 실수). 표 **자신 소유** 선언만
   인정해 다시 세니 1건(특수건설 IS_S — 단위가 표 안에 있는데 첫 행이 아니라 못 찾음).
5. **`id(lxml element)` 를 diff 키로 씀.** lxml 은 접근할 때마다 새 프록시를 만들어
   `id()` 가 달라진다 → 같은 표가 제거·추가 양쪽에 잡히는 가짜 diff. `getroottree().getpath()`
   로 교체.

## 5. 외화(USD) 지원 — 설계 요지

국내 기업이 표시통화를 외화로 쓴다(아남전자 008700, 2019+ 본문 8표 전부 `(단위 : USD)`).
종전엔 원화 배수가 없어 **표 전체를 보류** — 숫자를 못 읽어서가 아니라 통화를 표현할 방법이
없어서였다. 사용자 결정: **환산하지 않고 표시통화 그대로 담고, 행에서 바로 알게 한다.**

| 요소 | 방식 |
|---|---|
| 판정 | `units.FX_ONLY` — 원화 토큰이 **하나도 없고** 외화만 있는 선언. 배수는 표기 스케일 |
| 값 | `report_lines.value_won` 에 표시통화 금액 **그대로** |
| 행 식별 | `unit_source='fx_declared'` — **기존 컬럼 재사용**(새 컬럼 0개, 저장비용 0) |
| 통화 코드 | `report_tables.currency`(원화 표는 NULL) |
| 계층3 가드 | `combine.py` 에 `unit_source <> 'fx_declared'` — **같은 커밋에**(R5) |

⚠ **혼합 선언(`1USD, 천원`)은 건드리지 않았다.** 주석표 137,680개가 그 형태인데, 원화 열만
적재되고 USD 셀은 원문이 `'USD 12,000,000'` 처럼 통화 접두를 달아 금액 정규식에 안 걸린다.
DB 실측으로 오염 0 확인(`value_won` 있는데 원문에 USD 남은 note_lines 행 = 0).
