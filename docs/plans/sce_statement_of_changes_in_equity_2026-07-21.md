## 0. 한 줄 요약

K-IFRS 기본재무제표 5종 중 **자본변동표가 계층2에서 통째로 누락**되어 있다(원문 84.3%에 존재).
`report_lines` 에 `SCE_C`/`SCE_S` 섹션을 신설하되, **열이 기간이 아니라 자본 구성요소**인
행렬 구조라 기존 컬럼 규약(`col_index`=당기/전기)을 그대로 쓸 수 없다. 주석 슬라이스가 이미
확립한 **"컬럼=위치, `context_fiscal_year`=NULL"** 규약을 재사용한다.

## 1. 현황 — 왜 없는가

`parser/xml/section_detector.py:68`
```python
_BOUNDARY_EXTRA: list[list[str]] = [["자본변동표"]]
```
자본변동표는 **경계 표시용으로만** 쓰인다. 주석에 그 이유가 적혀 있다 — 자본변동표가
포괄손익계산서 바로 뒤 `<P>` 로 오기 때문에, 경계로 인식하지 않으면 `IS_C` 가 SCE 의
"연결당기순이익" 행을 흡수해 순이익이 오염된다. 즉 **오염 방지를 위해 버리는** 구조다.

`fin2/extract/text.py:49` `_SECTION_META` 도 6섹션(BS/IS/CF × 연결/별도)뿐이다.
`collector/models.py` 의 `statement` 컬럼 주석은 `"BS/IS/CF/SCE/note"` 라고 적혀 있으나
**SCE 는 한 번도 생성된 적이 없다**(주석이 선반영된 채 방치).

### 실측 (scripts/measure_sce_presence.py, FY 300 보고서 원문 XML 직접 스캔)

| 항목 | 값 |
|---|---|
| 자본변동표 제목이 있는 보고서 | 253 / 300 (**84.3%**) |
| 제목 2개(연결+별도) | 162 보고서 |
| 제목 0개 | 47 보고서 |
| 버려지는 데이터표 | 399 표 |
| 버려지는 표 행(TR) | **12,703 행** (보고서당 평균 50행) |

1차 패스(2015+ 93,801건) 환산 시 TR 기준 **약 400만 행** 규모.

> ⚠ caveat: 스캔이 `TITLE`/`P` 텍스트(≤40자)를 세므로 목차 언급이 중복 계수됐을 수 있다
> (제목 4개인 38건이 그런 경우로 추정). **상한선**으로 읽을 것. 구현 착수 시 실제 섹션
> 검출기로 다시 세어 확정한다(§6 D-0).

## 2. 왜 필요한가

자본변동표는 **주주환원 내역의 1차 출처**다 — 배당, 자기주식 취득/소각, 유상증자, 전환권
행사 등 자본 변동 사유가 행으로 적힌 유일한 기본재무제표. 프로젝트 목표(주주환원 지표)와
직결된다. BS 는 자본의 **잔액**만 주고 **변동 사유**를 주지 않는다.

**전량적재 전에 결정해야 하는 이유**: 나중에 추가하면 93,801건 재추출이다.

## 3. 구조가 다르다 — 핵심 설계 쟁점

BS/IS/CF 는 "행=계정, 열=기간"이다. 자본변동표는 **행=변동사유, 열=자본 구성요소**다.

```
                      자본금   자본잉여금  이익잉여금  기타자본  비지배지분   총계
2024.01.01 (기초)        X         X         X        X        X        X
  당기순이익               -         -         X        -        X        X
  배당                    -         -        (X)       -       (X)      (X)
  자기주식 취득            -         -         -       (X)       -       (X)
2024.12.31 (기말)        X         X         X        X        X        X
```

기존 `_row_to_line` 은 `ctx_fy = report_fiscal_year - col_idx` 로 **열 인덱스를 연도로
환산**한다(`fin2/extract/report_lines.py:159`). SCE 에 그대로 적용하면 **자본잉여금 열이
"전기 데이터"로 둔갑**한다 — 값 오염이자 계층2가 금지하는 '주장'이다.

### 해법 — 주석 슬라이스 규약 재사용 (신규 개념 아님)

`_emit_note_lines` 가 이미 같은 문제를 풀어놨다:

| 컬럼 | BS/IS/CF | note | **SCE (제안)** |
|---|---|---|---|
| `col_index` | 0=당기 1=전기 2=전전기 | 위치(0,1,2…) | **위치(0,1,2…)** |
| `context_fiscal_year` | `report_fy - col_index` | **NULL** | **NULL** |
| `period_kind` | instant/duration | NULL | **NULL** |
| `section_path` | 들여쓰기 조상 경로 | 주석 제목 | 들여쓰기 조상 경로 |

**열의 의미(자본금인지 이익잉여금인지)는 헤더 행에 있고, 그걸 읽는 것은 계층3의 일이다.**
계층2는 "3번째 열의 값이 X 였다"는 사실만 기록한다.

> 대안으로 `col_label`(열 헤더 원문) 컬럼 신설을 검토했으나 **1차 범위에서 제외**한다.
> 헤더가 다단(예: `지배기업 소유주지분` 상위 헤더 아래 `자본금|자본잉여금|…`)이라 열 헤더
> 파싱 자체가 별도 과제이고, 계층2 원칙상 열 병합 해석은 판단에 가깝다. §7 후속 참고.

## 4. 기간 문제 — SCE 는 2개 기간이 세로로 쌓인다

BS/IS/CF 는 당기/전기가 **가로 열**이지만, 자본변동표는 당기 블록과 전기 블록이
**세로로 두 번** 반복된다:

```
2023.01.01 (전기초)   …
  …
2023.12.31 (전기말)   …
2024.01.01 (당기초)   …
  …
2024.12.31 (당기말)   …
```

즉 `col_index` 로 기간을 구분할 수 없고 **행 위치로 구분**된다. 계층2는 이것도 판단하지
않는다 — `row_order` 와 `label_raw`("2023.01.01 (기초)")를 충실히 남기면 계층3이 읽는다.
`report_fiscal_year`/`report_fiscal_period` 는 **보고서 자체의** 연도/기간이므로 그대로 둔다
(이미 그런 의미의 컬럼이다).

## 5. 섹션 검출 — 경계 트릭의 유래와 실제 무게

### 5.1 유래 (git 추적 결과)

`_BOUNDARY_EXTRA` 는 커밋 **`1b13981`**(2026-06-13, "fix(parser): 자본변동표(SCE) 섹션경계
인식 + 재추출 fact_v2 purge") 에서 도입됐다. 트리거는 **부국증권**:

> 금융 보고서는 포괄손익계산서 바로 뒤 `<P>자본변동표</P>` 가 와서, 자본변동표를 경계로
> 인식 못 하면 IS_C 표 수집이 SCE 까지 넘어가 SCE 의 "연결당기순이익/반기순이익" 행이
> is.net_income 을 오염(부국증권 Q1 순이익=SCE 27.8B)

즉 **PDF 다중페이지와 무관**하다(PDF 는 Track C `fin2/extract/pdf.py` 별도 경로).
원인은 XML 레이아웃 차이다:

| 레이아웃 | 구조 | 경계 |
|---|---|---|
| 표준 | 재무제표마다 **자기 SECTION** | 형제가 없어 자연 종료(`END`) |
| `<P>` 마커 (증권·보험·지주·SPAC·구형 레거시) | 한 SECTION 안에 `<P>표제` + `<TABLE>` 이 **형제로 나열** | `<P>` 표제를 직접 판정해야 함 |

`find_section_tables` 의 형제 순회는 `tag=='TITLE'` 에서 **무조건 break** 하므로, 표제가
TITLE 인 서식에서는 `_BOUNDARY_EXTRA` 가 애초에 개입할 여지가 없다. `<P>` 마커 서식에서만
필요하다. 회귀 테스트도 그 형태다(`fin2/tests/test_section_p_header.py:165`
`test_sce_changes_in_equity_not_absorbed_into_is`).

### 5.2 실측 — 실제로 얼마나 일하는가

IS 섹션 표 수집이 **무엇 때문에 멈췄는지** 계측(FY 400 보고서):

| 중단 원인 | 2015+ (n=401) | pre-2015 (n=203) |
|---|---|---|
| `END`(형제 소진 — 자기 SECTION) | 383 (**95.5%**) | 180 (88.7%) |
| `MAX_TABLES` | 13 (3.2%) | 8 (3.9%) |
| **`P_BOUNDARY_SCE`(자본변동표가 유일한 제동)** | **4 (1.0%)** | **8 (3.9%)** |
| `P_STATEMENT`(다른 재무제표 표제) | 1 (0.2%) | 7 (3.4%) |

**경계 트릭이 실제로 일하는 건 전체의 2.0%(12/604)**, 2015+ 로 좁히면 1.0% 다.
"2015+ 에서는 경계가 아니었을 것"이라는 관측은 대체로 맞다 — 다만 **0 은 아니다**(4건).

참고로 IS 섹션 마커 태그 분포는 2015+ 에서도 `<P>` 가 우세하다(IS_S: P 140 vs TITLE 75).
`<P>` 마커 서식이 레거시 전용이 아니라 **현재도 다수**라는 뜻이므로, 이 경로를 깨뜨리면
안 된다.

### 5.3 그래서 리스크는 처음 평가보다 작다

`_SECTION_PATTERNS` 에 SCE 를 추가하면 `find_section_tables` 의 경계 판정이
**`_SECTION_PATTERNS` 를 순회**하므로 `<P>자본변동표</P>` 가 `P_STATEMENT` 로 잡힌다 —
즉 **경계 역할이 자동으로 보존**된다. `_BOUNDARY_EXTRA` 는 중복이 되지만 폴백으로 남긴다.

남는 실질 리스크는 두 가지뿐이다:
1. `_EXCLUDE_PATTERNS["SCE_S"]=["연결"]` 이 없으면 `<P>연결자본변동표</P>` 가 SCE_S 로
   오매칭 → 연결/별도 뒤섞임.
2. `core_missing` 계산이 `not code.startswith("NOTE")` 라 **SCE 도 '핵심'으로 취급**된다.
   SCE 없는 보고서(실측 15.7%)에서 `_detect_sections_from_paragraphs` 폴백이 불필요하게
   돌게 된다. 별도재무제표 없는 보고서에서 이미 같은 일이 일어나므로 신규 위험은 아니나,
   `core_missing` 에서 SCE 를 제외하는 편이 의도에 맞다.

`IS_C` 흡수 오염을 막던 경계 역할이 깨지지 않는지는 여전히 검증하되(§6 D-3), 이 작업의
**최대 리스크는 아니다**.

```python
# 추가 (연결 우선 — 기존 패턴 순서 규칙 준수)
("SCE_C", ["연결", "자본변동표"]),
("SCE_S", ["자본변동표"]),          # _EXCLUDE_PATTERNS["SCE_S"] = ["연결"]
```

`_BOUNDARY_EXTRA` 는 **제거하지 않는다**. 정식 섹션이 되면 자연히 경계가 되지만, 검출
실패 시 폴백으로 남겨두는 편이 안전하다(경계 역할이 사라지면 IS 오염이 되살아난다).

**필수 회귀 검증**: SCE 신설 전후로 `IS_C`/`IS_S` 의 순이익이 변하지 않아야 한다.
이게 이 작업 전체에서 가장 중요한 게이트다.

## 6. 작업 순서

- **D-0 실측 재확인** — 섹션 검출기 기반으로 SCE 표/행 수를 다시 세어 §1 상한선을 확정.
- **D-1 검출** — `_SECTION_PATTERNS` 에 `SCE_C`/`SCE_S` 추가, `_EXCLUDE_PATTERNS` 갱신.
  `fin2/extract/text.py:_SECTION_META` 에 `("consolidated"|"separate", None)` 등록
  (period_kind=None — SCE 는 instant/duration 어느 쪽도 아님).
- **D-2 추출** — `_emit_section_lines` 에 SCE 분기 추가, 또는 주석 경로처럼 별도 emitter.
  판단 기준: 컬럼 규약이 note 와 같으므로 **`_emit_note_lines` 쪽에 가깝게** 만드는 편이
  자연스럽다(단 `section_path` 는 본문처럼 들여쓰기 stack 사용).
- **D-3 회귀 게이트** — IS 순이익 불변 확인(§5.3). 특히 `<P>` 마커 서식(증권·보험) 표본을
  **명시적으로 포함**할 것 — 경계 트릭이 실제로 일하는 1~4% 가 거기 몰려 있다.
  기존 테스트 `fin2/tests/test_section_p_header.py::test_sce_changes_in_equity_not_absorbed_into_is`
  가 통과 유지되어야 한다(이게 부국증권 회귀의 봉인). `verify_report_lines --sample 300` 이
  기준선 299/300 이하로 떨어지지 않을 것. `verify_section_paths` well-formedness 유지.
- **D-4 SCE 전용 검증** — 신규 `scripts/verify_sce.py`:
  · 기초잔액 + 변동 합 = 기말잔액 (열별 산술 검산 — SCE 는 부호가 명시적이라 IS 와 달리
    검산 가능하다. §7 참고)
  · 기말 총계 열 = 같은 보고서 BS 의 자본총계 (**교차 검증** — 가장 강한 증거)
- **D-5 파이프라인 편입** — `docs/runbook_new_parser_pipeline_integration.md` 3층 절차.
  단, report_lines 자체가 아직 데일리 미배선이므로 **전량적재 인프라(4패스 1단계)와 함께**
  두 call site 를 처리한다. 별도 소급 백필 불필요(아직 적재 전이므로).

## 7. 열린 질문 (구현 착수 전 결정 필요)

1. **1차 적재 범위에 포함할 것인가.** 포함 시 전량적재 착수가 D-0~D-4 만큼 늦어진다.
   미포함 시 나중에 93,801건 재추출.
2. **`col_label`(열 헤더 원문) 컬럼을 지금 넣을 것인가.** §3 대안. 지금 안 넣으면
   계층3이 헤더 행을 `row_order=0` 근처에서 직접 읽어야 한다(가능하지만 번거로움).
   나중에 넣으면 재추출.
3. **K-GAAP(pre-2015) 자본변동표.** 2차 패스(pre-2015 70,374건) 대상이며 서식이 다르다.
   1차에서는 2015+ 만 다루고 2차 패스에서 별도 처리하는 것이 순서상 맞다.
4. **SCE 검산이 IS 보다 쉬운 이유 확인 필요.** SCE 는 배당·자기주식이 음수로 명시되는
   것이 일반적이라 `기초 + Σ변동 = 기말` 이 성립할 것으로 **예상**되나, IS 부호 규약
   사례(연결/별도가 서로 다름)를 겪은 만큼 **D-0 에서 표본 검산으로 먼저 확인**할 것.
   성립하지 않으면 D-4 검증 설계를 바꿔야 한다.

## 8. 참고 — 이번 논의에서 확정된 인접 사항

- **포괄손익계산서는 이미 저장되고 있다.** 신규 섹션 아님. 1표식(89.3%)은 IS 한 표 안에
  OCI 블록이 있고, 2표식(10.7%)은 표 2개가 모두 `IS_*` 로 방출된다. 커밋 `2c4d396` 의
  `table_seq`/`table_title` 로 어느 표에서 왔는지 구분 가능해졌다.
- **`statement` 에 OCI 코드를 신설하지 않는다.** 1표식에서 한 표를 인위적으로 쪼개야 하고
  그 경계 판정이 곧 의미 판단(계층3)이다.
