## 2. 원문 구조 대조 (완료) — 3건이 **한 패턴이 아니다**

### 2-1. 특수건설 `20151116001903` — BS·IS 모두 "완전 병합"형

한 `<TABLE>` 안에 순서대로: 제목행("재무상태표"/"포괄손익계산서" 단독 셀) → 빈 행 →
기간행 2개 → **회사명+단위 선언이 같은 행**("회사명 : (주)특수건설" … "(단위 : 원)") →
헤더행("계정명"/…) → 데이터 행.

**★재확인 결과, R4-1 세션의 기존 결론과 다르다**: 8월 5일 밤 핸드오프 §6은 "SCE·CF 는
분류되지만 여전히 로컬 단위 선언이 없다"고 적었는데, 이는 SCE/CF(분류가 되는 표)만 확인한
것이었다. **BS·IS는 애초에 `stmt=None`이라 단위 검사 자체를 못 갔을 뿐, 표 안에 단위 선언은
이미 있다**(원문 실측: BS 행 `"회사명 : (주)특수건설" … "(단위 : 원)"`, IS도 동일 형태).
→ 분류만 고치면 **doc_default 없이도** 로컬 단위로 완전히 풀린다.

### 2-2. 팬엔터테인먼트 `20181114002948` — BS·IS 모두 특수건설과 동일 패턴

제목행(자간 벌림 "재 무 상 태 표"/"손 익 계 산 서") → 빈 행 → 기간행 2개 → 회사명행 →
**회계단위+단위 선언 행**("회계단위 : [1000] …" / "(단위: 원)") → 헤더행 → 데이터.
구조가 특수건설과 사실상 동형 — 같은 수정으로 함께 풀린다.

### 2-3. 포시에스 `20171114002836` — BS와 IS가 **서로 다른** 결함

- **IS**: 첫 TR이 `"(포괄손익계산서)"` 단독(괄호로 감쌈) — 제목은 표 자신 소유이지만, 그
  뒤에 회사명·단위 선언 행이 **없다**. 헤더행("과목"/"당기"/"전기"/"전전기") 바로 다음이
  데이터. → 분류는 특수건설과 같은 방식으로 풀리지만 **로컬 단위가 없어 R4-1
  `document_default_unit()` 폴백이 필요**하다.
- **BS**: 첫 TR이 곧바로 헤더행("과목"/"당기말(10기)"/"전기말(9기)"/"전기말(8기)")이다.
  **표 안 어디에도 "재무상태표" 문구가 없다** — 제목이 병합된 게 아니라 **아예 없음**.
  텍스트 근거로 분류할 방법이 없는, 앞의 4건과 질적으로 다른 결함.

  이 문서엔 `1. 요약재무정보` 섹션에 "주식회사 포시에스와 그 종속기업 … (단위 : 원)"
  선언이 있어(R4-1 doc_default 경로로 단위는 확보 가능) IS는 완전히 풀리지만, **BS는
  단위가 있어도 애초에 BS인지 분류를 못 하면 무의미**하다.

## 3. 제안하는 수정 범위 (결정 필요 — §5 참고)

### 3-A. "표 자체 소유 제목" 인식 함수 신설 (특수건설·팬엔터·포시에스 IS, 4개 섹션)

새 함수(가칭 `owned_title_and_local_unit(tbl)`, `fin2/extract/statement_titles.py`):

1. 표의 첫 TR 텍스트(공백 제거)가 재무제표명 단독(`_STMT_NAME_ANY.fullmatch` 또는 괄호로
   감싼 동형)이면 그 표가 **자기 제목을 자기 안에 담은 표**로 인정.
2. 헤더행(계정명/과목 등 라벨 행)이 나오기 전까지의 앞쪽 TR들에서 `detect_unit_tokens`로
   로컬 단위 토큰을 찾는다(있으면 반환, 없으면 None — 포시에스 IS 케이스).
3. `title_text_owned`/`title_text_for_classify`가 실패했을 때만(=직전 형제로 못 찾았을
   때만) 이 경로를 시도 — 기존 표제/데이터표 분리 서식 경로는 그대로 우선.

`fin2/extract/text.py`의 분류 지점(`_emit_section_lines` 등 title_text_owned 호출부)에
이 폴백을 배선. 로컬 단위를 찾으면 그걸 쓰고(`unit_source`는 기존 로컬 판정과 동일 계열),
못 찾으면 기존 R4-1 `document_default_unit()` 폴백으로 넘어간다(이미 있는 경로, 순서만
바뀜: 로컬 있음 → 이 표 자체 소유 단위 → doc_default → 스킵).

**예상 결과**: 특수건설 BS·IS(로컬 단위로 완전 해결) · 팬엔터 BS·IS(로컬 단위로 완전 해결)
· 포시에스 IS(doc_default로 완전 해결) — **5개 섹션, 3건 중 2.5건**.

### 3-B. 포시에스 BS(제목 아예 없음) — 결정 완료(2026-08-05, 옵션 2 채택)

처음엔 "표본 1건뿐이라 위치 추론은 위험"으로 옵션 1(보류)을 권장했으나, 사용자가 "여러
기업을 버릴 수는 없다"며 위치 조건을 추가 검증해보라고 지시 → 실측으로 재검토했다.

**1차 재검사(조건: 표 자신의 첫 TR이 곧바로 헤더행 "과목"으로 시작)** — 같은 398건
모집단에서 **9건** 매치(포시에스 외 8건: 미래아이앤지·메지온·올리패스·라파스·이엔플러스·
한탑 2020~2022). 그러나 원문 대조 결과 이 8건은 **전부 주석(Notes)/CF/IS 표가 "과목"
헤더 관례를 같이 쓴 것**이었다(자산 재분류 명세, 정정전후 비교표, "Ⅰ.영업수익"으로
시작하는 손익 표, "Ⅱ.투자활동으로 인한 현금흐름"으로 시작하는 CF 표 등) — 본문 BS 와
무관한 오검출이었다. `scripts/verify_titleless_first_table_is_bs.py`(신규, 읽기전용)로
섹션·표순번·계정명 샘플을 원문에서 직접 확인해 배제했다.

**최종 규칙(4조건 AND, 사용자 확정)**:
1. 표가 `"N. 재무제표"`/`"N. 연결재무제표"` SECTION-2 의 **첫 번째** 금액표(위치).
2. `title_text_owned()` 로 제목을 못 찾는다.
3. 표 자신의 첫 TR 이 헤더행("과목"/"계정명" 등)으로 곧바로 시작한다.
4. 헤더 다음 첫 계정명이 **"자산"** 이다.

4번 구현 시 함정 하나 발견·수정: "과목" 헤더 셀이 `ROWSPAN="2"`(2단 헤더: 과목/기간 +
과목 아래 빈칸·기간 아래 날짜)를 쓰면, rowspan 때문에 다음 TR 은 **1열이 통째로
없어져서** 그 TR 의 "첫 TD"가 이미 2열째 값(날짜, 예 `"2017-09-30"`)이 된다 — 이걸
그대로 계정명으로 읽으면 날짜를 "자산"과 다른 값으로 오판해 조건 ④가 거짓양성/거짓음성을
낸다. 날짜/기간 패턴(`^\d{4}[-.]\d{1,2}` 등)이면 계정명 행이 아니라고 건너뛰도록 고쳤다
(`scripts/census_titleless_bs_position_rule.py::_PERIOD_ROW`).

**최종 검증**: 이 4조건으로 398건 전수 재검사 → **정확히 2건 매치, 둘 다 포시에스**
(`"2. 연결재무제표"`의 연결 BS, `"4. 재무제표"`의 별도 BS) — 다른 기업 오적용 **0건**.

**채택**: 옵션 2. 이 4조건 위치+계정명 규칙을 §3-A 의 `owned_title_and_local_unit()` 과
나란히 배선하는 별도 판별 경로로 구현한다(제목이 없으므로 단위도 표 안에 없다 — §2-3
확인대로 R4-1 `document_default_unit()` 로 단위를 확보). stmt 는 위치로 확정(BS), 단위는
R4-1 경로로 확보하는 조합.

### 8-2. 구현 중 발견한 추가 결함 2건 (계획엔 없던 것)

1. **`_looks_like_appropriation` 오탐** — 팬엔터테인먼트 BS 는 대차합계를 "부채자본총계"
   (표준 "부채와자본총계"와 순서가 다름)로만 쓰는데, 처분계산서 배제 가드의 "진짜 재무제표
   확정 라벨" 목록(`_REAL_STMT_ROW_RE`)에 이 표기가 없어서 같은 표 안의 "미처분이익잉여금"
   (자본 세부 항목 한 줄, 정상 BS 구성)이 처분계산서 신호로 오인돼 **BS 전체가 배제**됐다.
   R4-2 로 분류가 성공하기 전엔 `stmt=None` 에서 먼저 걸러져 이 가드에 도달하지 못해
   드러나지 않던 **기존 결함**이었다. "부채자본총계"·"자본과부채총계" 추가로 해결.
2. **`document_default_unit` 인접성 가정 오류** — 포시에스는 요약재무정보 섹션 안에서
   [단위선언 표] → [연결범위 표(단위·데이터 둘 다 없음)] → [실제 데이터 표] 순서라, 데이터
   표의 "직전 형제"만 보던 종전 로직이 단위선언 표를 놓쳤다(사이에 낀 무관 표 때문). 데이터
   없는 표를 지나며 단위 선언을 "기억"해뒀다가 데이터 표 자신에게 선언이 없을 때 쓰도록
   확장 — R4-1 의 "요약재무정보 섹션 전체가 하나의 단위를 공유한다"는 원칙을 표 단위
   인접성이 아니라 섹션 단위로 넓힌 것이라 R4-1 정책과 모순되지 않는다.
