## 1. ★가장 중요한 발견 — 조용한 데이터 손실

DART 원문 XML 은 특수문자를 이스케이프하지 않는다. 실측(FY2024, 400 filing):

| 손상 유형 | 발생률 | 추출 영향 |
|---|---|---|
| 꺾쇠 안 텍스트 `<당기말` | 99.8% | 없음 |
| 미이스케이프 `&` | 91.8% | 없음 |
| **속성값 안 따옴표** `ENG=""KB Kookmin Bank"` | **2.0%** | **치명적** |

속성 따옴표가 깨지면 태그 중첩이 무너져 **그 뒤 내용이 통째로 사라진다. 오류 없이
적재되므로 지금까지 안 보였다.** 성일하이텍 FY2024 는 추출 셀 1,143 → **6,011**,
주석 섹션 17 → **75** 로 복구됐다(데이터의 2/3 를 잃고 있었다).

수정: `parser/xml/dart_xml_parser.sanitize_dart_xml()` — 파싱 전 3종 복구(순서 중요,
`&` 먼저). 태그 화이트리스트 밖의 `<` 는 텍스트로 본다(lxml 이 만든 '태그' 282종 중
진짜는 40여 종뿐이었다).

**안전성**: 250 filing 검증에서 파싱오류 15,720→238 · 추출 셀 **+0.32%** · 값이 바뀐
filing 5(2%). 바뀐 것은 전부 **오귀속 교정**이다(예: `차입금, 기준이자율` 이
`8. 관계기업투자` 밑 → `16. 차입금` 으로 이동. 원문 XML 로 확인).

## 4. D&A 파이프라인 (계층3 주석 해석 계층)

`std_v3` FY `da_total` **0% → 97.4%** · `ebitda` 97.3% · interim 30.5%.
항등식 위반 0 · 음수 0.

체인(항목별 전용 추출기를 만들지 않는다):
```
②note_topics(주제)  →  ③note_periods(기간)  →  ④note_labels(라벨)  →  fin2/layer3/note_da
```
- **②** `parser/common/note_topics.py` — 완결형(성격별·현금흐름표·판관비)은 **하나만**,
  구성요소형(유형/무형/투자부동산/리스)은 **전부 합산**.
- **③** `parser/common/note_periods.py` — 계층2 가 `col_label` 을 전사하게 되면서
  기간을 헤더 텍스트로 판정(rule=COL_LABEL). interim 은 '누적' 열 선택.
- **④** `parser/common/note_labels.py` — 결합표기·`<자산>상각비`·ROU 합산.
  ★함정 배제: `감가상각누계액`(잔액) `상각후원가` `대손상각비` `손상차손`.

수정한 결함(전부 원문 대조 확인):
1. `build._VALUE_COLS` 에 D&A 컬럼 누락 → 36분 재빌드가 전부 0행
2. basis fallback 미적용 → 연결 미작성 기업 통째 누락
3. `<자산종류>상각비` 라벨 누락(사용권자산상각비 등)
4. 결합라벨 옆 별도행 폐기(`rule_additive_da` 의 da_direct 우선)
5. **`_resolve` 가 가산 계열을 충돌로 폐기** — FY2024 94건·**1조 5,247억원** 누락.
   → `ADDITIVE_CANON` 선언으로 승격(`fin2/standardize/rules.py`)
6. 가산 합산이 품질 게이트를 건너뜀 → 의미 기반 라벨 가드로 확정
7. 불완전한 상위 소스가 더 나은 하위 소스를 막음(성일하이텍: 손상차손 섞인 결합라벨)
