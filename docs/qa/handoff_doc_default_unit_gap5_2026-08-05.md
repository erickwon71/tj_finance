## 4. 4건의 진짜 원인과 수정 (R4-1)

원문 XML 직접 대조(`iconv -f euc-kr -t utf-8` 필요한 EUC-KR 파일 포함) 결과:

- 이엘피(00374020) 2건 `20160330001530`·`20160513002038`, 인카금융서비스(01013694)
  `20170516000038`, 윙스풋(01405585) `20210517000207` — 전부 `<FILENAME ATYPE="dsl">
  재무제표_직접작성</FILENAME>` 템플릿. 본문 BS/IS/SCE/CF 표에 `(단위:...)` 문구가
  **아예 없다** — 제목표든 데이터표 첫 행이든.
- 그런데 문서 안에는 텍스트로 명시된 근거가 따로 있다:
  - **요약재무정보 섹션**(`1. 요약재무정보`)의 데이터표 바로 위에 `(단위 : 원)` — 이엘피
    2건·윙스풋. 이 표의 수치가 본문 표 수치와 **정확히 일치**(유동자산
    12,744,686,267 등, 실측 확인).
  - **회계정책 주석**의 "표시통화 … 원(KRW)/원화" 문구 — 인카금융서비스("회사의
    기능통화와 표시통화는 대한민국 원화이며…")·윙스풋("표시통화인 '원(KRW)'으로
    표시되고…").

신설한 `fin2/extract/text.py::document_default_unit(root)` 가 이 두 경로를 순서대로
찾아 **문서 전체 기본 단위**를 반환한다. `_emit_section_lines`/`_emit_sce_lines`
(`fin2/extract/report_lines.py`)는 그 표에 로컬 선언이 전혀 없고 FX_ONLY 도 아닐 때만
이 값을 최후 수단으로 쓰고, `unit_source='doc_default'` 로 provenance 를 남긴다.

### 엘브이엠씨 2019 사고와 다른 점 (중요)

`inherited_declaration_text()`(`text.py`)에는 "재무제표명 경계를 넘어 상속하면 안 된다"는
안전장치가 있다 — 2019년 엘브이엠씨 USD 표가 앞선 '연결현금흐름표 단위:백만원'을 잘못
주워 자산총계가 586조로 부풀었던 사고 때문이다. 이번 수정은 **그 함수를 건드리지
않았다** — 새 함수는 "다른 표의 선언을 statement 경계 너머로 넘겨받는" 게 아니라
"**어느 표도 아무것도 선언하지 않았을 때 문서 공통 선언을 쓰는**" 별개 패턴이라, 그 표
자신에게 이미 통화 선언이 있으면(FX_ONLY 등) 이 경로까지 오지 않는다. 기존 엘브이엠씨
회귀 테스트(`test_no_inherit_across_statement_title`)는 그대로 통과한다(수정 안 한
함수라 당연하지만, 확인은 했다).

## 6. 보류 — 특수건설 `20151116001903` (별개 결함)

같은 `재무제표_직접작성` 서식이지만 R4-1 로 못 고친다. 원문 대조 결과:

- **BS·IS 는 제목·기간·회사명·단위·계정데이터가 전부 한 `<TABLE>` 안에** 들어있다(다른
  3사는 제목표/데이터표가 별도 TABLE). `title_text_owned()`(직전 형제에서 제목을 찾는
  전제)가 이 형태에서 제목을 못 찾아 `stmt=None` → **BS·IS 분류 자체가 실패**한다(단위
  문제 이전 단계의 결함). SCE·CF 는 이 문서에서 정상적으로 별도 제목표를 쓰고 있어서
  분류는 되지만, 여전히 로컬 단위 선언이 없다.
- `document_default_unit()` 도 못 찾는다 — 이 문서는 요약재무정보 섹션이
  **비어있고**(분기보고서 플레이스홀더 `<WARNING>` 만 있음) 회계정책 주석도
  **없다**(분기보고서라 주석 생략, "해당사항 없습니다").

`docs/PARSING_RULES.md` 부록C 에 미해결로 등재해뒀다. 손보려면 "제목+데이터 병합 표"를
인식하는 별도 분류 경로가 필요하다(표 자기 자신의 앞부분 행에서 통계명·기간·단위를
추출하는 방식 — `title_text_owned` 와 별개 함수).
