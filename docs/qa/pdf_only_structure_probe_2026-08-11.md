### 6-0. ★최우선 발견 — "2015+ PDF-only 2,104건"은 2단계 문제. 1단계(원인)는 확정, 2단계(정확한 최종 분할)는 전량 다운로드 완료 후 확정 예정

적용:

**이 진단은 표본만으로 이미 확정 — 전량 다운로드가 바꾸는 결론이 아니다.**

**2단계 — ★정정(같은 날 후속 조사, 최초 낙관적 결론을 스스로 뒤집음)**: "원문 zip 회수 성공 =

  `sync_xbrl_instance_lines()`의 기본 `FY_MIN=2015`는 `fiscal_year` 기준이라 44건 중
  39건이 조용히 걸러짐 — `year_min=1999`로 스크립트 수정 완료.
- 2차 원인(기존 코드, ★미수정 — 별도 판단 필요): 수정 후에도 44건 전부 0행. 원문 zip을

  ("ifrs-full")`), **2015~2019년 무렵 필링은 더 오래된 IFRS taxonomy(2010-04-30 버전,
  실제 확인: `xmlns:ifrs = http://xbrl.iasb.org/taxonomy/2010-04-30/ifrs`)를 쓰며 접두사가

### 6-1. 이미지 스캔 PDF / OCR (§1-3, §1-8) — 조사 종결, 불필요

전수(3,509건) 스캔 결과 **이미지 스캔 PDF 0건(100% 텍스트 기반)**. OCR 조사(§1-8, Q2)는
착수할 대상 자체가 없어 **"불필요"로 종결**한다 — `tesseract` 등 OCR 인프라 설치는
불요하다.

### 6-2. Face 섹션 앵커 탐지 (§1-4) — §3-2 방식은 목차 오탐에 취약, 강화 필요

`제목+기간마커` 앵커 방식(§3-2 `fin2/extract/pdf.py` 재사용)을 그대로 적용한 결과, **제목
텍스트 매치 중 70~87%가 기간마커 부재로 배제**됐다(pre2015 3462/4187=82.7%, 2015-2019
823/1173=70.2%, 2020+ 607/699=86.8%) — 목차·주석 언급이 절대다수라는 뜻으로, 앵커 로직
자체는 정상 작동하는 것으로 보인다. 다만 최종적으로 **BS 라벨(자산총계 등 2개 이상)까지
확인된 표본은 156/271건(57.6%)뿐**이고 나머지 115건(42.4%)은 실패했다 — 특히 여러
pre-2015 초기(1999~2002) 표본에서 title_hits는 있으나 anchor 자체가 0으로 떨어지는 사례가
다수 관찰됨(§2b 표 참고, 예: 원익홀딩스/롯데쇼핑/서부T&D 등). 원인은 개별 확인 필요 —
가설: (a) 이 시기 PDF는 "제 N 기" 마커 표기가 다르거나(예: "제N기" 붙여쓰기, 자간 다름),
(b) 요약재무정보만 있고 본문 face가 실제로 없는 문서(사업보고서 첨부서류가 별도 PDF일 가능성).
Phase 2에서 원문 직접 대조로 재확인 필요.

### 6-3. 표/숫자 표기 (§1-5) — 괄호 음수가 압도적, 세대 무관하게 일관

괄호 표기(`(1,234)`)가 전 era에서 압도적 다수(pre2015 31,167 / 2015-2019 25,653 / 2020+
10,074), △▲·마이너스 표기는 소수(pre2015에서만 △▲ 800건 — 구형 K-GAAP 문서에서 상대적으로
더 흔함). `fin2/extract/pdf.py`의 `parse_number()`가 이미 괄호/△▲/마이너스 3종을 모두
처리하므로 **재사용 가능, 신규 로직 불요**로 결론.

### 6-4. 들여쓰기/구조 보존 (§1-6, Q1) — ★거의 전 세대에서 보존 확인, XML 방식 재사용 가능

**핵심 발견**: 라벨 라인의 x0 좌표를 3pt 단위로 클러스터링한 결과, probe 성공 164건 중
**163건(99.4%)이 서로 다른 x0 클러스터 2개 이상**을 가졌다(pre2015 109/110, 2015-2019
39/39, 2020+ 15/15 — 클러스터수=1로 "들여쓰기 없음" 판정된 건 pre-2015 1건뿐). 평균
클러스터 수는 era가 최신일수록 오히려 늘어난다(pre2015 6.8 → 2015-2019 7.1 → 2020+ 12.3).

**결론(§6 Q1 확정)**: "PDF는 구조가 없다"는 초기 우려는 기각한다. pdfplumber가 텍스트를
x-좌표 기반으로 추출하는 이상, DART PDF의 시각적 들여쓰기는 좌표 정보로 사실상 전 세대에
걸쳐 보존돼 있다. **Phase 2는 §3-3에서 계획한 대로 XML과 동일 방식(x0 좌표 비교 →
depth/node_role 산출)을 기본 경로로 채택**하면 된다 — §1-7 대체 신호(폰트/번호매김/bbox/
간격) 조사는 "들여쓰기 소실 세대의 폴백"으로 계획했으나, 그런 세대가 표본에서 사실상
발견되지 않아 **우선순위를 낮춘다**(완전 배제는 아님 — 전량 실행 시 예외 케이스 대비용
2차 신호로 Phase 2 설계에만 남겨둠).

### 6-5. 대체 구조 신호 (§1-7) — 폰트 신호는 기각, 번호매김은 보조 신호로 유효

- **폰트 굵기(a)**: `bold_ratio`가 표본 전체 **164건 전부 0.0** — 원인을 직접 확인한 결과

  없다(예시 파일 실측). **폰트명 문자열 매칭으로는 굵기 신호를 못 얻는다 — 이 신호는 기각**

  주 신호이므로 우선순위 낮음).
- **번호매김 접두기호(b)**: 검출은 되나 표본별 편차가 큼(0건인 표본도 다수, 수십~백여 건인
  표본도 존재) — 존재할 때는 들여쓰기와 함께 보조 신호로 쓸 수 있으나 단독 채택은 부적절.
- **표 셀 bbox 패딩(c), 줄간격(d)**: 6-4 결론에 따라 우선순위가 낮아져 이번 표본에서는
  본격 실측하지 않음(gap_median 컬럼만 수집 — 표마다 편차가 크고(0~19) 유의미한 패턴은
  못 찾음). 필요해지면 Phase 2에서 재조사.
