# TJ Finance 시각화 앱 — 감리(QA) 테스트 방향서 & 전기능 체크리스트

## Context

`docs/user_manual_app.md`(2026-07-06)에 기술된 재무·주가 시각화/스크리너 Streamlit 앱은 8개 페이지·9개 탭·50종 지표·다수의 다운로드/차트/토글을 갖췄으나, **앱을 실제로 구동해 화면을 검증하는 테스트가 전무**하다(기존 `tests/`는 데이터·계산 계층 단위테스트뿐, Streamlit을 띄우지 않음). 신규 시각화 서비스의 출시 품질을 담보하기 위해, **매뉴얼을 유일한 스펙(블랙박스 기준)** 으로 삼아 (1) 테스트 방향을 정의하고 (2) 모든 기능을 검증하는 체크리스트를 만들며 (3) 실제 테스트는 별도 테스트 담당자(Sonnet)가 수행하고 (4) 감리 담당(본인)이 결과를 종합해 **감리보고서**를 제출한다.

**감리 원칙**
- **블랙박스**: 기대동작의 근거는 앱 소스가 아니라 `docs/user_manual_app.md`. 매뉴얼과 실제 화면이 다르면 결함(앱 버그 또는 매뉴얼 오류)으로 보고.
- **화면 직접 검증**: 렌더된 페이지를 실제로 확인(헤드리스 Chromium 스크린샷/DOM)해 결과를 판정. 로그·DB만으로 판정하지 않음.
- **전수 + 심층 2계층**: 데이터 표시는 전 기업(2,554사) 전수, 기능 인터랙션은 엣지케이스 층화표본.
- **재현 가능한 결함 보고**: 개발자가 그대로 재현하도록 기업코드·페이지·토글상태·단계·기대/실제·스크린샷을 포함.

## 확정된 감리 결정사항 (사용자 확인 완료)
1. **전수검증 방식** = 자동 스윕 + 이상건만 스크린샷. 단, **기업 시각화 화면은 연간·분기·별도·연결 4조합 모두 × 전 대상기업**을 확인하고, **값 표시 자체의 문제(특히 시계열 중간이 비는 mid-series gap)** 를 집중 점검.
2. **값 정확성** = **UI 표시값 ↔ DB값 기간별 자동대조**(앱이 DB를 올바르게 표시/단위환산하는지).
3. **기능 심층 테스트 표본** = 엣지케이스 층화표본(아래 §6).

## 1. 테스트 대상 환경 & 사전조건 (테스트 담당자 준비)

| 항목 | 값 |
|---|---|
| 실행 | 프로젝트 루트에서 `.venv_tj_finance/bin/streamlit run app/main.py` |
| URL | `http://localhost:8501` (기본 8501, 오버라이드 없음) |
| 페이지 딥링크 | url_path로 이동 가능: `/company`(기본) `/screener` `/quarter-change` `/valuation` `/compare` `/chart-builder` `/collect` `/help`. **기업 선택은 URL 불가** — 사이드바 검색창에 코드/명 입력 |
| 사전조건 | PostgreSQL 기동 + `.env`의 `DATABASE_URL`이 적재된 DB를 가리킴. 사이드바 "DB 상태" expander가 **"DB 연결 OK"** 인지 먼저 확인 |
| 자동화 | venv에 **Playwright 1.60 + Chromium 사전설치**. 캡처/구동 스크립트는 미존재 → 담당자가 신규 작성 |
| DB 조회 | 앱: `from collector.db import get_session`. 스크립트: psycopg2 DSN `dbname=tj_finance user=taejin` |

**전제 리스크(감리 착안점)**: Playwright가 사이드바 텍스트 입력→자동선택 대기→탭 라디오 클릭 순으로 구동해야 하며, 기업 선택이 세션상태 기반이라 병렬 워커는 세션 격리(별도 브라우저 컨텍스트) 필요.

## 2. 대상 유니버스 & 기간 산정 (전수검증 기준선)

- **활성 대상기업 = 2,554사** (`corporations` where `is_active=TRUE AND COALESCE(coverage_class,'periodic')<>'non_periodic'`).
- **회사별 시작연도/최신연도**는 재사용: `scripts/check_period_completeness.py`의 `fetch_corps`(§65-88)·`fetch_corp_first_period`(§126-159), 또는 아래 SQL로 대조 기준 테이블을 먼저 생성한다.

```sql
-- 회사별 데이터 보유 구간 (전수검증의 기대범위 기준선)
SELECT c.corp_code, c.corp_name, c.stock_code, c.market, c.fiscal_month,
       MIN(s.fiscal_year) AS earliest_fy, MAX(s.fiscal_year) AS latest_fy
FROM corporations c
JOIN std_financials_v2 s ON s.corp_code = c.corp_code
WHERE c.is_active = TRUE AND COALESCE(c.coverage_class,'periodic') <> 'non_periodic'
GROUP BY c.corp_code, c.corp_name, c.stock_code, c.market, c.fiscal_month
ORDER BY c.market, c.corp_name;
```
- **비-12월 결산 주의**: `fiscal_month`≠12 기업은 FY 연도와 달력분기(CQ) 매핑이 다름 → "시작연도" 판정 시 `fiscal_month` 동반 해석(부록 D·주1). 이 기업군은 mid-gap 오탐 위험이 크므로 별도 검증 규칙 적용.

## 3. Tier 1 — 전 기업 데이터 표시 무결성 스윕 (전수 2,554사)

**목표**: 매뉴얼 §3(기업 시각화)의 데이터 표시가 전 기업에서 정확·완전한지. **판정은 자동, 스크린샷은 이상건 + 무작위 감사표본(예: 2%≈50사)만.**

**실행 매트릭스**: 각 기업 × **{연간, 분기} × {연결, 별도} = 4조합** × {재무제표·지표·밸류에이션·대가지표·주가·주가·재무결합·생산·가동률·섹터·피어·임원·지분 탭}. (연결/별도 대체가 일어나면 주2 캡션과 함께 대체본으로 판정.)

### 3.1 자동 판정 항목 (DS = Data Sweep)
| ID | 점검 | 합격 기준 |
|---|---|---|
| DS-1 | 페이지 로드 무오류 | 4조합 전부 Python 예외·빈 화면·Streamlit 에러박스 없음 |
| DS-2 | **UI값 ↔ DB값 기간별 대조** | 재무제표/지표 탭의 표시값을 `std_financials_v2`(뷰 `standard_financials`) 값과 기간별 대조. 억원/조원·%·소수 **단위환산 규칙**(매뉴얼 §공통규칙, 부록 C) 적용 후 허용오차 내 일치 |
| DS-3 | **mid-series gap 탐지** | 시작연도~최신연도 사이 **중간 기간이 비는 경우**를 플래그. 판정: DB에 값이 있는데 UI가 빈 경우=앱버그(중대), DB에도 없는 경우=데이터 결함으로 분류. 양끝 결측(최근 미공시 등)은 허용, **중간 결측만 이상** |
| DS-4 | 연결/별도 대체 표기 | 요청 기준 데이터 없을 때 반대 기준 자동대체 + **주2 안내 캡션** 노출(매뉴얼 §2.3) |
| DS-5 | 연간↔분기 일관성 | 분기 선택 시 달력분기(CQ) 재배치 값 존재, 비-12월 결산은 주1 각주 표기 |
| DS-6 | 값 형식 이상치 | 음수 자산·1e15 초과 등 표시 깨짐, NaN/None/`inf` 문자열 노출, 천단위·단위 라벨 누락 |
| DS-7 | 배지/경고 렌더 | 신뢰배지(✅/🔎/⚠)·DQ배너·이상치 경고·기재정정/시장조치 배지가 조건 충족 시 정상 렌더(매뉴얼 §3.1, 부록 B) |
| DS-8 | 헤더 정합성 | 기업명(종목코드)·corp_code·시장·각주(주1/2/3)가 DB 속성과 일치 |

### 3.2 산출물
- `docs/qa/results/sweep_all_companies.csv` — 기업×조합별 DS-1~8 판정(PASS/FAIL/이상값 상세).

## 4. Tier 2 — 전기능 인터랙션 체크리스트 (엣지케이스 표본)

매뉴얼의 모든 페이지·위젯을 항목화. 각 항목 형식 = **[ID] 기능 | 조작 단계 | 기대결과(매뉴얼 근거) | 합격기준 | 적용범위**. 담당자는 표본 기업(§6)에서 실행하고 `docs/qa/results/checklist_run.csv`에 PASS/FAIL/N/A + 스크린샷 경로 기록.

### 4.1 사이드바 (SB) — 전 페이지 공통 (매뉴얼 §2)
- **SB-1** 기업검색 1건 자동선택 / **SB-2** 다건 라디오+[선택] 확정 / **SB-3** "검색 결과 없음" / **SB-4** 종목코드·기업명 양쪽 입력.
- **SB-5** 관심종목 추가(☆)/해제(⭐), 목록 펼침/접힘, 항목 클릭 이동, [❌] 제거, **앱 재시작 후 유지**(§2.2).
- **SB-6** 표시옵션 연결/별도 전환이 페이지에 전역 반영 / **SB-7** 연간/분기 전환 전역 반영.
- **SB-8** DB 상태 expander: 연결 여부 + 활성 보통주/재무행/주가행 수 표시, 실패 시 오류.
- **SB-9** 포커스 기업 공유(기업 시각화·밸류에이션·자유조합이 동일 포커스), 스크리너·분기변화 행 클릭 시 포커스 변경(§1).

### 4.3 스크리너 (SC) (매뉴얼 §4)
- **SC-1** 저장된 스크린: [저장]/[불러오기]/[삭제], 재시작 후 유지.
- **SC-2** 기본설정: 기간단위/집계기간 슬라이더/집계방법(평균·CAGR·YoY·QoQ)/시장/결측처리(제외·통과).
- **SC-3** 퀀트패스 1~4 순차: 필터 지표 멀티셀렉트(50종+멀티플+대가+시총), 최소/최대(단측·구간·미적용), 정렬 지표·방향·한도.
- **SC-4** 다패스 "퀀트 축소: P1→P2→…" 표기.
- **SC-5** [스크리닝 실행] → 결과표, **행 클릭 시 우측 기업 시각화 전체 임베드**(좌측 결과 유지).
- **SC-6** 흑자/적자 전환 라벨(성장률 왜곡 방지).
- **SC-7** [결과 CSV].

### 4.4 분기 변화 (QC) (매뉴얼 §5)
- **QC-1** 달력연도 셀렉트 + Q1~Q4 탭. **QC-2** 표 컬럼(매출/영업이익 QoQ·YoY 액·률), 기본정렬=매출YoY내림, **헤더 클릭 재정렬**.
- **QC-3** 행 클릭 모달: 최근16분기 표/그래프 라디오, **"전체 상세 분석 보기" 토글 → 9탭 임베드(분기 강제)**.
- **QC-4** [결과 CSV], 데이터 없는 분기 빈 표.

### 4.5 밸류에이션 페이지 (VL) (매뉴얼 §6)
- **VL-1** DCF 가정 expander(FCF성장률/WACC/영구성장률/예측기간 슬라이더, 0=자동추정), **VL-2** 결과 메트릭(적정가·현재가·안전마진·자기자본가치)+가정 요약 캡션+연도별 FCF/PV 표, **VL-3** 계산 불가 안내.
- **VL-4** 배당 분석 메트릭(연속연수·3년평균수익률·성향·DPS CAGR)+연도별 표, **VL-5** 배당 없음 안내.

### 4.6 기업 비교 (CMP) (매뉴얼 §7)
- **CMP-1** 페이지 내 검색→[➕ 비교에 추가], **CMP-2** [제거], **CMP-3** 2개 이상 시 비교표(21개 항목행×기업열), **CMP-4** 연결/별도 사이드바 추종.
