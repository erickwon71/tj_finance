# net_debt 차입 부품의 형제 줄 합산 설계 (2026-11-18, 규칙 후보 R345, 적용 계층: 3 — 파생)

상태: **구현 완료(2026-11-18, 권장안 = 사용자 결정) — 규칙 R345, 소급 전사 재빌드 대기**
선행: R342·R342-b·R343·R344 (커밋 8f1ae2e, 9126e6b). 소급 재빌드 `scripts/qa/r342_r343_rebuild_2026-11-18.sh` 는 아직 실행 전 — 이 설계를 구현한 뒤 한 번에 돌리는 것을 권장(§7).

## 1. 문제

`net_debt` = 차입 부품 12개 canonical(`_V3_ST_DEBT_PARTS`·`_V3_LT_DEBT_PARTS`)의 `abs` 합 − cash. 각 canonical 은 `_resolve` 에서 **값 하나**로 확정된다. 같은 canonical 에 라벨이 다른 줄이 여럿이면:

- 값이 같으면 그 값, 다르면 단계(exact > normalized > fuzzy) 높은 쪽만 남기고, 같은 단계끼리 값이 다르면 `_reduce_conflict` 가 못 가르면 **보류(HELD) → 그 canonical 전체가 net_debt 에서 빠진다**.
- 그래서 원문에 따로 인쇄된 형제 줄(원화·외화 장기차입금, 유동성장기차입금·유동성장기사채 등)은 하나만 들어가거나 둘 다 빠진다.

| 사례 | 원문 BS 줄 (같은 canonical) | 지금 | 합산하면 |
|---|---|---|---|
| 00159616 2004 FY 별도 | `8.유동성원화장기차입금` 3,047.4억 + `9.유동성외화장기차입금` 174.0억 (유동성대체분), `1.원화장기차입금` 1,346.8억 + `2.외화장기차입금` 624.1억 (장기) | 둘 다 보류 → net_debt −6,551.2억 | −1,359.0억 |
| 01109539 2018 Q1 별도 | `장기차입금` 75.5억 + `비유동성장기부채` 364.4억 | 보류 → net_debt −512.8억 | −73.0억 |
| 01109715 2022 Q1 연결 | `유동성장기부채` 10.0억 + `유동성장기차입부채` 12.4억 (둘 다 exact) | 보류 → 둘 다 빠짐, net_debt 1.9억 | 24.3억 |

## 2. 규모 (전체 report_lines BS, 현재 매핑 = R344 반영, 필링·기준·canonical 단위)

- 차입 canonical 그룹 630,137 중 라벨 2개 이상 16,238, **금액 있는 라벨 2개 이상 14,058**(2015+ 4,759).
- 금액 있는 쌍의 관계: 형제(같은 표, section_path 관계 없음) **9,994필링**, section_path 부모·자식 1,586, 다른 표 503.
- 형제 canonical 분포(필링): 장기 4,458 · 단기 3,506 · 유동성대체 1,662 · 사채 1,060 · 전환사채 287 · BW 186 · 기타 245.
- 흔한 형제 쌍: `장기차입금`+`외화장기차입금`(번호 붙은 것 포함 약 2,500), `단기차입금`+`외화단기차입금`, `유동성장기차입금`+`유동성장기사채` 260, `사채`+`회사채` 163, `유동성전환사채`+`상환할증금` 60.
- 0 으로 인쇄된 줄 + 금액 있는 줄 하나인 그룹 1,622 (00916516 모양).

## 3. 위험 — 숨은 부모·자식 (단순 합산 금지 이유)

section_path 에 드러나지 않는 계층이 있다(구형 K-GAAP 평면 표):

- `2.장기차입금 193.5억 = 가.장기차입금 181.5억 + 나.외화장기차입금 12.1억` — 번호 체계(`2.` → `가.`/`나.`)로만 계층을 표시.
- `2.단기차입금 3.59억 = 12.단기차입금(구매자금) 3.26억 + 13.단기차입금(외상매출금) 0.33억`.
- `2.단기차입금 = 나.단기차입금`(자식 하나라 값이 같음), `1.장기차입금 = 1)외화장기차입금` 663.2억.

같은 표·section_path 관계 없는 그룹에서 "가장 큰 줄 = 나머지 합"(±1,000원)인 경우 127그룹, section_path 부모·자식이 있으면서 같은 산수가 성립 475그룹. 이런 그룹을 단순 합산하면 두 배가 된다.

## 4. 규칙 (안)

`net_debt` 계산에서만 쓴다. canonical 별로, `_resolve` 가 값 선택 직전에 이미 거른 후보(재게재 표·신탁 표 제외 등 같은 전처리 뒤)를 대상으로:

1. **0 줄 제외**: 값 0 인 줄은 합산 대상에서 뺀다(0 은 기여가 없고, 지금은 exact 0 이 금액 있는 fuzzy 줄을 이긴다).
2. **같은 줄 중복 정리**: 정규화 라벨(번호·주석·공백 제거) + section_path 가 같은 줄은 한 줄. 값이 둘 이상이면 정정(amended) 쪽, 그래도 갈리면 → **합산 포기(지금 동작)**.
3. **한 표만**: 남은 줄이 둘 이상의 `table_seq` 에 걸치면 → 합산 포기.
4. **section_path 부모·자식**: 다른 후보의 라벨이 section_path 에 들어 있는 줄(자식)은 뺀다(부모가 이미 포함).
5. **산수로 총계 찾기**: 한 줄이 나머지 전부의 합과 같으면(±1,000원 또는 상대 1e-6) 그 줄 하나를 쓴다.
6. **숨은 계층 의심 → 포기**: 아래 중 하나면 합산하지 않고 지금 동작을 유지한다.
   - 값이 같은 줄이 둘 이상(부모 + 외동 자식 가능성)
   - 줄이 3개 이상이고 어떤 줄이 다른 줄 2개 이상의 부분합과 같음(n ≤ 8 전수 확인)
   - 번호 머리말 체계가 섞여 있음(`2.` 와 `가.`, `1.` 와 `1)`, `(1)` 와 `가.` 등) — 섞이면 계층 표기다. 머리말 없음 + 한 가지 체계는 형제로 본다.
7. 위를 통과하면 **합산**. 전체 차입 합이 `total_liabilities × 1.05` 를 넘으면 기존 가드대로 합산 전체를 버린다(`_additive_debt_for_net_debt`).

**바꾸지 않는 것**: `short_term_debt`·`long_term_debt` 저장 열(가이드: 인쇄된 단기·장기차입금 줄 하나), 다른 canonical, extended_facts_v3 값, 계층2.

## 5. 구현 위치 (안)

- `fin2/layer3/combine.py::_resolve` — 차입 canonical 에 한해 값 선택 직전의 `rows` 를 `debt_rows[c]` 로 내보낸다(전처리를 한 곳에서 재사용, 중복 구현 안 함).
- 새 함수 `_sum_debt_siblings(rows) -> int | None`(§4 의 1~7), 스위치 `_R345_DEBT_SIBLING_SUM`.
- `_additive_debt_for_net_debt(canon, col, debt_rows)` — canonical 별로 `_sum_debt_siblings` 가 값을 주면 그 값, 아니면 지금처럼 `canon[c]`.
- R343(무차입)은 `cands` 의 차입 후보 존재로 판정하므로 영향 없음.

## 6. 검증

1. **단위 테스트**: §1 네 사례, §3 숨은 계층 네 모양(합산 안 함 확인), 0 줄, 다른 표, 정정 중복.
2. **A/B(쓰기 없음)**: 직전 커밋 worktree 대 새 코드로 형제 그룹이 있는 기간 전체(약 1만 필링)의 net_debt 비교 — 바뀐 것을 (a) 합산 (b) 0 줄 제외 (c) 총계 선택으로 나눠 센다.
3. **원문 대조**: 각 분류에서 표본 10건씩(시대·업종 고르게) DART 원문 BS 와 맞춰 본다. 숨은 계층 포기 그룹도 10건 보고 포기 조건이 과하거나 모자라지 않은지 확인.
4. **독립 확인**: 2015+ 는 주석 차입금 표(`note_lines` 의 `단기차입금`·`장기차입금`·`사채` 합계 열)와 합산값을 비교해 일치율을 잰다 — 주석 형식이 제각각이라 보조 지표로만.
5. Gate B 무영향(계층3 파생값만 바뀜).
