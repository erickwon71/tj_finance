# R192·R193 결함 후보 4건 원인 조사 (2026-09-29)

대상: R192 재판정에서 "DB 값이 맞다"는 증거가 남은 제닉·신신제약·슈프리마, R193 재판정의 케일럼.
방법: 켬/끔 재추출에서 어느 복원 단계가 셀을 바꾸는지 단계별(`repair_sce_sign_loss` → `repair_sce_row_identity` → …)·적용 라벨(`_apply`)로 추적,
`trace_blocks.py`로 블록·앵커 확인, 원문 XML 행 대조. **코드는 바꾸지 않았다.** 추적 스크립트는 scratchpad 에만 있다.

## 1. 슈프리마 — R192 의 앵커 충돌 폴백 (코드 결함)
연결 기타자본구성요소 2021·2022 블록. 끔(R192 이전)은 BS 날짜 앵커(`@2020-12-31`·`@2021-12-31`·`@2022-12-31`, 모두 −)로 잔액을 −로 정하고
1·4·5행(2021), 11·14·15·16행(2022)을 뒤집어 **정확히 닫는다**:
`−628,135,416 − 143,657,280 + 403,198,984 − 2,693,798,600 − 12,300,503 = −3,074,692,815`.
켬은 R192 가 이전 보고서 IS 앵커를 붙인다: 1행 −(맞음), **5행 `해외사업장환산외환차이` +12,300,503**(IS 는 총합·세후 기준). BS 앵커 해는 5행이 −여야 하므로 앵커 해가 사라진다.
그러면 R162-e(앵커 없는 블록의 단일 셀 반전)가 돈다. 이 단계는 **뒤집는 셀의 앵커만** 확인하고 잔액 셀(`open_i`·`close_i`)의 앵커는 확인하지 않는다.
인쇄 그대로(양수) 잔액에서 3행 하나만 뒤집으면 `628,135,416 + 143,657,280 − 403,198,984 + 2,693,798,600 + 12,300,503 = 3,074,692,815` 로 닫히는데, 이것은 잔액이 −라는 BS 앵커에 반하는 **거울 해**다.
결과는 DB(정확히 닫힘)가 닫히지 않는 값으로 바뀐다(`new=x old=0`).
**수정 후보**: ① 앵커 해가 없으면 IS 앵커를 빼고 다시 푼다(R192 이전 동작으로 폴백). ② `_solve_single_flip` 이 남는 모든 멤버 셀(특히 잔액)의 필요 부호(`_required_sign`)와 해가 충돌하면 기각한다.
① 이 R192 의 의도(IS 앵커는 보강)에 맞고, ② 는 R162-e 전반의 안전판이라 영향 범위가 더 넓다.

## 2. 케일럼 — R162-e 교차 열 미검증 + 순환 증거
별도 이익잉여금(3열) 2024 1분기 블록: `28,182,899,674 → 28,149,674,112`(감소). 총계(4열)는 `31,010,122,648 → 31,043,348,210`(증가 +33,225,562), 원문 IS 도 +.
잔액이 인쇄 그대로 양수면 3열만 손실에서 닫힌다 — 원문 결함(같은 행 총계·IS 와 모순).
1. R162-e 가 3열의 `당기순이익` 행을 −로 뒤집는다(유일 해). **행 항등식(3열 성분 = 4열 총계)과 4열 블록 닫힘을 확인하지 않는다.** 끔에서도 이 단계까지는 같다.
2. R193 켬에서만 선행 소계 행 1(`총포괄손익`)이 그 아래 행 2 와 같은 부호로 함께 뒤집힌다.
3. R162-d 행 항등식이 총계 열을 성분 열에 맞춰 뒤집는다. 이중증거 규칙은 "같은 금액이 **다른 곳**(다른 행 포함)에 음수"이면 인정하는데, 행 1 의 3열 −(R193 이 만든 값)이 행 2 의 증거,
   행 2 의 3열 −(R162-e 가 만든 값)이 행 1 의 증거가 되어 **서로를 증명한다.** 음수가 원문 괄호인지 앞 단계가 복원한 값인지 구분하지 않는다(R162-d 문서에 구분 규정 없음).
4. R185 열 일관성 가드는 "닫힌 블록을 깨는 부분 뒤집기"를 만나면 열 전체 반전을 시도하고, 열 전체가 안 닫히면 **R162-d 반전을 그대로 둔다**(엔켐 `20240516001964` 사례 때문에 그렇게 설계).
   그래서 4열이 정확히 닫혀 있어도 막지 못한다.
**수정 후보**: ① R162-e 가 행 항등식이 성립하던 행을 깨고, 그 항등식의 다른 열 블록이 인쇄 부호로 이미 닫히면 기각. ② R162-d 이중증거에서 앞 단계(R162·R162-e·R193)가 만든 음수는 증거로 세지 않는다(출처 표시 필요).
①이 좁고 안전하다. ②는 R162-d 백필(5,645필링)에 영향이 커서 전수 켬/끔이 필요하다.

## 3. 신신제약 — 원문 표 결함
표가 행 라벨 기준으로 어긋나 있다. 2018 블록 총계 열: 행 0 기초 52,270,977,917, 행 1 회계정책변경 25,659,173, **행 2 `배당금지급` 52,245,318,744 = 52,270,977,917 − 25,659,173**(조정 후 기초 잔액),
행 4 기말 2,473,745,285(= 행 3 당기순이익). 산술로는 R192 의 IS 앵커(3행 +)가 1·2행 −를 골라 `52,270,977,917 − 25,659,173 − 52,245,318,744 + 2,473,745,285 = 2,473,745,285` 로 정확히 닫는다.
그러나 이것은 어긋난 표 위의 우연한 닫힘이다. 결과로 행 2 총계가 −52bn 이 되고, 뒤이어 R162-d 가 원래 뒤집던 2열(기타포괄손익누계액) 행 2 를 뒤집지 못한다(총계가 −라서 항등식이 안 맞음):
`7,585,250,000 + 14,450,419,827 + 30,218,989,417 − 9,340,500 = 52,245,318,744` 로 2열 −9,340,500 이 항등식을 정확히 맞춘다. DB(2열 −)가 맞다.
**코드로 못 고친다**(표 구조 결함). 후보: R183 원문 결함 예외목록에 등재하거나 수동 확정.

## 4. 제닉 — 원문 결함 + 증거 충돌
연결 기타포괄손익누계액. 같은 `2014.01.01(기초)` 인데 FY2014 블록은 88,087,827, 2014 1분기 블록은 99,791,101 이다(FY2014 기말 99,791,101 과 같은 값 — 원문 열 오류).
BS 날짜 앵커(`@2013-12-31`)는 99,791,101 을 −로 가리키고, 이전 보고서 IS 앵커는 `매도가능금융자산 평가손익` −5,332,665 를 가리킨다.
두 증거를 동시에 만족하는 해가 없다: 잔액이 −이면 `−88,087,827 + m12 + m14 = −99,791,101` 이고 m12 = −5,332,665 이면 m14 = −6,370,609 인데 원문은 17,035,939 다.
R192 는 IS 앵커로 거울 방향을 정하고(새 값), DB 는 반대 거울(BS 증거와 같은 방향)이다. 어느 쪽도 원문으로 증명되지 않는다.
**코드로 못 고친다.** 원문 확인이 필요하다.

## 제안 순서
1. 슈프리마: 후보 ① IS 앵커 폴백 — R192 의 의도에 맞고 좁다. 켬/끔 전수(108,158필링, 약 3시간)로 영향 측정 후 결정.
2. 케일럼: 후보 ① R162-e 교차 열 검증. 슈프리마의 후보 ② 와 함께 R162-e 안전판으로 묶어서 측정할 수 있다.
3. 신신제약·제닉: 원문 결함. R183 예외 목록 등재 여부는 사용자 결정 사항(스키마·정책 변경은 아님, 수동 값 고정).
