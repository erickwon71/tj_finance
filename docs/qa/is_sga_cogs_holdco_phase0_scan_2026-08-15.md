# Phase 0 스캔 결과 — `is.sga`/`is.cogs` 지주회사형 라벨 오분류 (2026-08-15)

> 배경: `docs/plans/is_sga_cogs_holding_co_label_mismap_plan_2026-08-15.md` Phase 0.
> 읽기전용 조사. DB 쓰기 없음. 스크립트: `scripts/probe_sga_cogs_holdco_phase0_2026-08-15.py`.

## 방법론 교정 (계획 문서 대비 변경점)

1. **후보 매칭을 substring LIKE에서 exact-normalize로 좁힘.** `label_raw LIKE '%영업비용%'`로
   시작하면 1,108개사가 걸리는데, 실측해 보니 대부분 무관(보험사의 '기타영업비용'·'투자영업비용'·
   '보험영업비용' 등 전혀 다른 개념). `normalize_account_name(label) == '영업비용'`(로마숫자/주석
   번호 제거 후 정확히 "영업비용")로 좁히니 **309개사**로 줄었고, 여기서 다시 "직속 자식에
   매출원가류 라벨 + 판매비와관리비류 라벨이 둘 다 있고 합이 총계와 일치"하는 진짜 §1 패턴만
   추리니 **46개사**만 남았다. 계획 문서의 "166개사"는 이 정밀화 이전 추정치로, 이 문서가 대체한다.
2. **XBRL 교차검증을 `fact_v2` 대신 원문 XML 직접 재파싱으로 전환.** 세션 중 확인: `fact_v2`는
   Gate B(`face_audit.py`)가 실제로 읽는 테이블이 아니다(별도 XBRL instance 파서 파이프라인).
   Gate B는 `read_report_face_xbrl()`로 보고서 원문의 인라인 XBRL(`TE[@ACODE]`)을 직접 재파싱한다.
   실제로 한진중공업홀딩스·두산·대성홀딩스 3건 모두 `fact_v2`엔 행이 0개였다(별개 파이프라인
   커버리지 갭). 이 스크립트는 Gate B와 동일한 경로(`read_report_face_xbrl` 직접 호출)로 검증했다.

## 결과 2 — §3(Gate B report_won 개념 문제) 확정 + 시기 절벽 실측

`ifrs-full_CostOfSales`로 총계가 실제 태깅된 건 **15건 / 4개사뿐**이고, 전부 **2024~2026년**
필링이다(`{2024: 3, 2025: 10, 2026: 2}`) — 2010~2023년 필링에선 단 1건도 없다. 계획 문서 §5의
"XBRL Track A 비교 데이터는 최근 필링(2024+)에만 있어 빙산의 일각일 가능성" 가정이 **정확히
실측 확인**됐다.

4개사: 00143527, 00117212(두산), 00163673(한진중공업홀딩스), 00108940(대성홀딩스).
→ 지금 fail_a로 잡힌 3개사 + **00143527이 신규 발견**(기존 조사 때는 못 봄).

`no_track_a`(같은 target_rows 중 XBRL 비교 자체가 불가능한 필링) = **839건 / 44개사**,
2006~2025년에 고르게 분포. 즉 target 46개사 중 XBRL로 검증 가능한 건 **4개사뿐**이고 나머지
42개사는 지금 `is.sga`가 오염돼 있어도 Gate B가 영원히 못 잡는다(§5의 "침묵 오염" 확정).

## 결과 3 — §Phase 0 item 2: SGA XBRL 개념 태깅 여부 (회사마다 다름)

`dart_TotalSellingGeneralAdministrativeExpenses`(concept_map.py의 `is.sga` XBRL 개념)가
같이 태깅된 건 51건 / **5개사**: 00269852, 00115694, 00159971, 00117212(두산), 00363769.

- **두산(00117212)은 두 개념이 같은 필링에 동시 태깅**된다(`ifrs-full_CostOfSales`=총계 +
  `dart_TotalSellingGeneralAdministrativeExpenses`=순수SGA, 둘 다 존재) — 이 회사만큼은
  Phase 3에서 (b) 옵션(Gate B에 sga 필드 추가해 XBRL로 직접 검증)이 기술적으로 가능.
- **한진중공업홀딩스·대성홀딩스는 SGA 개념이 별도 태깅 안 됨** — 이 두 회사는 (b)가 불가능,
  (a)/(c) 중 선택해야 함.
→ Phase 3 결정은 **회사마다 다를 수 있다**(일괄 정책 불가능, 이것도 R16류 교훈과 같은 결).

## 결과 4 — "상품 및 제품매출원가" 라벨 (계획의 "13개사"는 과대추정)

정밀 재확인: **7개사**만 이 라벨(및 변형)을 쓴다: `00109286 00117212 00118266 00164636
00167192 00276834 00415594`. 이 중 target_corps(46개사)와 겹치는 건 **두산(00117212) 1개뿐**.
나머지 6개사는 이 트랙과 무관한 별도 맥락(각자 다른 회사의 매출원가 세부항목)에서 이 라벨을 쓴다.

4개 라벨 변형 전부 `unknown.상품및제품매출원가`(conf=0.0)로 일관되게 실패 — 충돌 후보 없음,
일반 alias 추가가 안전해 보인다(다른 canonical과 겹치는 fuzzy 매치 없음, 대상도 6개사뿐이라
파급 작아 저위험).

## Phase 1/2/3로 넘길 다음 결정 사항

1. **Phase 1 override 대상**: 46개사(target_rows) 중 identity_fail 27개사는 제외, 나머지도
   회사별 원문대조 후 개별 (corp+기간) 등재가 필요 — 46개사 전부를 한 번에 승인해도 되는지, 아니면
   더 표본을 좁혀 우선순위를 매길지 결정 필요.
2. **Phase 3 방향은 회사마다 갈릴 수 있음**: 두산은 (b) 가능, 한진중공업홀딩스/대성홀딩스는 불가능
   — "일괄 정책"이 아니라 회사별 처방이 될 가능성 높음. 사용자 결정 필요.
3. **"상품 및 제품매출원가" 일반 alias 추가**는 안전해 보이지만(7개사, 충돌 없음) 이것도 별도
   승인 필요.
