## 3. ★새로 드러난 최대 유실 채널 — `_table_has_data_rows` 게이트 **9.5M 셀**

`★금액을 선언했는데 폐기된 표 2,199,735 (숫자셀 9,501,682)` 의 정체를 쪼개 보면:

```
금액단독 폐기 24,673 표 — 그중 데이터행 없음 24,673 표 (100.0%)     ← 표본 250 filing
혼합     폐기    850 표 — 그중 데이터행 없음    850 표 (100.0%)
```

**폐기의 100% 가 단위 문제가 아니라 `_table_has_data_rows(minimum=2)` 게이트**다. 즉 F1 의
목표(단위를 못 읽어 표를 버리는 일)는 0 이 됐고, 남은 것은 **성격이 다른 별개의 게이트**다.

그 게이트는 "콤마 3자리 금액을 가진 직접 데이터행이 2 개 이상"을 요구한다(표제표·stub 배제
목적). 그래서 **작지만 진짜인 표**가 걸린다 — 원문 표본:

```
20150817000851  '16. 결손금 … (단위 : 천원)'                         2 셀
20150817000851  '변동금리부 차입금의 이자율 1% 변동시 민감도 …'          4 셀
20150817000851  '4-(3) 금융자산의 신용건전성 …'                        6 셀
```

전수 규모 **2,199,735 표 / 9,501,682 셀**(표당 4.3 셀). 단위 결함 3종 합(8.9M 셀)과 맞먹는다.

> **결정 필요(D4)** — 게이트를 `minimum=1` 로 낮출지, 아니면 '숫자 셀이 N 개 이상'처럼 다른
> 축으로 바꿀지. 낮추면 표제표·stub 이 섞여 들어올 수 있으므로 **낮춘 상태로 표본 30 건을
> 원문 대조**한 뒤 결정하는 것이 맞다. 용량은 +9.5M 행(현 스키마 ~3.5 GB, 축소 후 ~1.2 GB).
