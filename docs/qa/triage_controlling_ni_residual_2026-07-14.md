- **선행 맥락**: 총포괄 오염 수정(커밋 `22d21f9`)의 소급 재표준화가 2026-07-14 완료

## 1. 요약

`std_financials_v2`에서 항등식 프록시 `|controlling_ni| > |net_income| × 1.02`를 위반하는
행이 **16,114건 / 약 2,500사**에 존재한다. `fin2_fix_controlling_ni.py`(항등식 기반
후보 재선택)로는 더 이상 줄지 않는다(`_collect`가 고정점 도달). 이 잔여군을 실제 원인별로
분해하면 **성격이 정반대인 두 집단이 거의 반반 섞여 있다.**

| 집단 | 행 수 | 기업 수 | 성격 | 조치 |
|---|---:|---:|---|---|
| **(A) 정당 비지배 음수** | **9,164** | 1,370 | **데이터 정상** — 항등식 `controlling+nci=net` 성립. 위반 프록시가 **오탐** | 값 손대지 말 것. **DQ 어서션 정제**로 오탐 제거 |
| **(B) 진짜 총포괄 오염** | **6,950** | 1,217 | `controlling_ni`에 OCI 포함 **총포괄손익**이 저장됨 — 항등식 불성립 | 재추출/파서 개선 필요 |
| └ (B1) 대체후보 있음 | 56 | — | fact_v2에 정답 후보 존재 → 재선택으로 즉시 교정 가능 | **빠른 승리** (배치가 놓친 케이스, 원인 확인) |
| └ (B2) 단일/무 후보 | 6,894 | — | 정답값이 fact_v2에 **아예 없음** | 손익계산서 "지배기업 소유주 귀속 당기순이익" 라인 재추출 |

> **핵심**: 위반 프록시 `|cni|>|net|×1.02`는 (A)를 대량 오탐한다. 실제 판별식은
> **항등식 잔차** `|controlling_ni + noncontrolling_ni − net_income|` 이다. 이게 0이면 (A) 정상,
> 크면 (B) 오염.

## 3. 영향 범위

- **(A) 9,164행 = 영향 없음** (데이터 정상). 단, `std_v2_controlling_ni_exceeds_net` WARN을
  계속 유발 → **어서션 오탐 노이즈**로 진짜 (B)를 가림.
- **(B) 6,950행 = 실제 값오류.** `controlling_ni` 및 이를 쓰는 파생지표(지배주주 EPS, PER,
  BPS 등 per-share, 지배지분 ROE)가 틀림. **소형주뿐 아니라 삼성물산·현대해상 등 대형주 포함**
  → 이전 "소형주 한정·저영향" 평가는 **정정**함. 다만 (B)는 대부분 총포괄분이라 절대오차가
  크고 방향까지 뒤집힐 수 있어(현대해상 2022FY: +5,746 → −6,479), 시각화 신뢰도에 실질 타격.

## 4. 권고 조치 (우선순위)

### P1 — DQ 어서션 정제 (오탐 9,164건 제거, 저위험·고효과)
`std_v2_controlling_ni_exceeds_net`를 **항등식 잔차 기반**으로 교체:
- 현재: `|controlling_ni| > |net_income|×1.02` → (A) 대량 오탐
- 변경: `noncontrolling_ni`(fact_v2 또는 std 파생)를 조회해
  `|controlling_ni + noncontrolling_ni − net_income| > tol` 일 때만 WARN.
- 효과: WARN이 (B) ~6,950건으로 축소 → 진짜 오염만 추적 가능.
- ⚠️ `std_financials_v2`에는 `noncontrolling_ni` 컬럼이 **없음**. 어서션에서 fact_v2 조회하거나,
  std_v2에 파생 컬럼 추가 여부 별도 결정 필요.

### P2 — (B1) 56건 즉시 교정 + 배치 누락 원인 규명
후보가 있는데도 재선택이 안 된 56건. `_collect`의 트리거 조건
(`abs(cni-expected) > abs(expected)*0.02 + 1e6`)이나 `expected = net − nci` 계산에서
누락됐을 가능성. 원인 확인 후 배치 재적용 시 소량 감소 기대.

### P3 — (B2) 6,894건 재추출 (본질적 수정, 고비용)
정답 "지배기업 소유주 귀속 **당기순이익**"이 fact_v2에 없음(총포괄 라인만 매핑됨).
- 방향: 텍스트 추출기(`fin2/extract/text.py`)가 **손익계산서 섹션**의 소유주귀속 순이익을
  포괄손익계산서의 소유주귀속 총포괄손익과 **구분**해 각각 별도 canonical로 방출하도록 개선
  → 재선택이 정답 후보를 갖게 됨.
- ⚠️ **파서/로더 추가·개선 절차**(`docs/runbook_new_parser_pipeline_integration.md`) 필수:
  ① collect_new.py 두 call site 배선 ② 소급 백필 수동 ③ 검증. [[parser-pipeline-integration-runbook]]
- 우선순위: 대형주(삼성물산·현대해상·롯데지주 등) 먼저 표본 검증 후 전수 확대 권장.

### 하지 말 것
- (A) 9,164건에 값 보정 시도 금지 — 데이터가 정상이다.
- `fin2_fix_controlling_ni.py`로 잔여 16,114를 0까지 쫓지 말 것 — 잘못된 도구(고정점 도달).

## 4b. 실행 결과 (2026-07-15)

P1→P2→P3 순차 실행. **P1·P2 완료(DB 반영). P3 파서 수정·검증 완료, 전수 재추출 백필은
장시간(수 시간)이라 사용자 실행 대기.**

### ✅ P1 완료 — 어서션 항등식 잔차 기반 정제

- 결과: 어서션 위반 **16,114 → 6,950**(오탐 9,164 제거). ERROR=0, 무결성 OK 확인.

### ✅ P2 완료 — 비교컬럼(_collect_comparative) 총포괄 재선택 이식
- **근본원인**: `_collect` 는 총포괄 재선택 교정을 받았으나 자매 함수 `_collect_comparative`
  (비교컬럼 폴백 경로)는 **max-abs 그대로**였다. 비교컬럼 파생행은 여기서 오염 잔존.
- 수정: `fin2/standardize/build.py::_collect_comparative` 에 동일 항등식 재선택 이식(surgical).
- 백필: `scripts/fin2_fix_controlling_ni_comparative.py` (630사) 실행 완료 —
  비교컬럼 위반 **1,211 → 1,160**(−51), 진짜 오염 **6,950 → 6,900**(−50). 오류 0.
  블라스트 반경 검증: 재실행이 `controlling_ni` 만 변경(다른 컬럼 무변).

### ◐ P3 파서 수정·검증 완료 / 전수 백필 대기

  (기존 '총포괄…귀속' 헤더 스킵을 보완). 4줄 추가, 다른 계정 영향 없음(코드 인스펙션+테스트 확인).
