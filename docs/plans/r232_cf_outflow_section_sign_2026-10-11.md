# R232 — CF "현금유출액" 구간 아래에 양수로 인쇄된 항목의 부호 (계층3) — 계획 (2026-10-11)

상태: 계획 → reviewer 검토 → 구현 (사용자 지시 2026-10-11: "계획 문서 만든 뒤 reviewer 검토 받고 진행")

## 1. 증상

현금흐름표 중 투자·재무활동을 `현금유입액 / 현금유출액` 두 구간으로 나눠 인쇄하는 양식이 있다.
이 양식에서는 유출 구간 아래 항목을 **괄호 없이 양수로** 인쇄하는 회사가 많다. 소계에는 괄호를 붙이는 경우도 있고 붙이지 않는 경우도 있다.

```
재무활동현금흐름                    (2,784,714,260)
  재무활동으로 인한 현금유입액       22,500,000,000
    단기차입금의 차입                 1,500,000,000
  재무활동으로 인한 현금유출액       (6,166,384,260)   ← 소계는 괄호
    배당금의 지급                       413,409,970   ← 항목은 양수(=유출 금액의 크기)
```

계층2는 R0-2 원칙에 따라 인쇄된 양수를 그대로 싣는다(정상). 그런데 계층3에는 이 양식의 부호 규칙이 없다.
그래서 `std_financials_v3.dividends_paid` 가 양수로 들어간다(2015+ 5,231행 / 2014 이전 25,079행. 음수 관례 행은 각각 73,416 / 19,850).
`borrowings_repaid` 양수 8,923 / 34,787, extended `cf.*` 유출 계정도 같은 상태다.
R18(인라인 XBRL 배당 태그 대사)은 이 결함의 일부만 덮는다(보정 52셀). 태그가 있는 필링의 배당 행만 대상이기 때문이다.

**적용 계층 = 3.** 인쇄값은 바꾸지 않고 `layer3_cell_corrections` 에 보정 행을 추가한다(R0-2).

## 2. 측정 (2026-10-11, `report_lines` CF, 읽기 전용, scratchpad `analyze_outflow2.py`)

- 대상 구간: `section_path` 의 마지막 단계가 유출 구간 표제인 CF 행.
  표제 판정: `현\s*금\s*유\s*출` 을 포함하고 `없`·`유출입` 은 포함하지 않는다.
  이렇게 해서 `현금유출이 없는 비용등의 가산`, `현금유출입이없는손익항목` 같은 비현금 조정 구간을 제외한다(첫 측정에서 섞여 들어온 것을 확인함).
- 구간(group) = (rcept, basis, table_seq, col_index, section_path). `report_lines` CF 는 col_index=0 만 있다.
- 증명 두 가지:
  - **소계 항등식**: 표제 행(같은 표, 부모 경로, 정규화한 계정명 = 구간명, 자식보다 앞 행)의 값 H 와 자식 합 S.
  - **활동 항등식**: 활동 합계 T(예: `투자활동현금흐름` 행)와 유입 구간 합 I. `T = I − S` 이면 크기 관례, `T = I + S` 이면 부호 관례다.

| 크기 관례 증명 — H>0 이고 S=H (소계도 양수) | 97 / 219 / 11 | 1,960 / 11,364 / 575 |

| 크기 관례 증명 — 활동 항등식만 | 21 / 79 / 1 | 169 / 823 / 78 |

- 크기 관례로 증명된 구간 중 자식이 **전부 음수**인 것이 2015+ 4개, 2014 이전 5개 있다(활동 항등식만 일치). 유입 구간까지 음수로 인쇄된 이상한 표라 대상에서 뺀다(§3 가드 2).
- 크기 관례 구간 안의 음수 자식(예: `이자의 지급 (2,083,384)`, 20210517002154)은 "유출의 차감"이라 실제 값은 양수다. 소계 항등식이 이 음수까지 포함해서 맞기 때문에, **구간 전체에 −1 을 곱해야** 결과가 부호 관례 항등식을 만족한다.
- 2014 이전의 "증명 없음 · 자식 모두 양수" 28k 구간은 대부분 소계 H<0 인데 S≠−H 인 경우다. 계층2의 행 누락이나 다른 열 같은 구형 표 문제로 보인다(예: 20150813000883 정확히 3e10 차이).
  소계가 괄호(음수)이고 자식이 모두 양수인 것은 인쇄 관례 자체를 보여 준다(부호 관례라면 자식 합이 음수여야 한다). 그래서 이것을 별도 규칙 R232-b 로 둔다(§3).

## 3. 규칙

### R232 (증명형)
구간마다 아래 증명 중 **크기 관례 쪽만** 성립하면, 구간의 0 아닌 자식 값 전부에 −1 을 곱한다. 소계 H 가 양수이면 H 도 −1 을 곱한다.
- 소계 증명: (H<0 ∧ S≈−H) 또는 (H>0 ∧ S≈H)
- 활동 증명: T≈I−S ∧ ¬(T≈I+S)
- 부호 관례 증명: (H<0 ∧ S≈H) 또는 (T≈I+S ∧ ¬(T≈I−S))
- 허용오차 ≈ : |a−b| ≤ max(1,000원, 단위×자식 수). 단위는 구간 값 전체를 나누는 가장 큰 10의 거듭제곱이고 상한은 1e6 이다.

### R232-b (소계 부호 증거)
증명이 없는 구간이라도 **자식이 전부 양수이고 소계 H<0** 이면 자식 전부에 −1 을 곱한다(합이 맞지 않아도 적용).
근거는 인쇄 관례다. 부호 관례로 인쇄한 표라면 유출 소계가 음수일 때 자식 합도 음수여야 한다.
값 크기는 바꾸지 않고 부호만 바꾼다. 합이 맞지 않는 원인(행 누락 등)은 이 규칙이 고치지 않으며 그대로 남는다.

### 손대지 않는 경우
1. 부호 관례가 증명된 구간, 증명끼리 충돌하는 구간.
2. 크기 관례가 증명됐지만 0 아닌 자식이 **전부 음수**인 구간(유입 구간도 음수로 인쇄된 이상 표).
3. 증명이 없는 구간 중 R232-b 조건이 아닌 것(부호 섞임, 소계 없음, 소계 양수인데 합 불일치).
4. 이미 다른 규칙이 보정한 셀(R18 등). 그 보정을 덮어쓰지 않는다.
5. 구간의 손자 행(유출 항목 아래 세부 내역, 2015+ 506행). v1 범위 밖으로 둔다.
6. XBRL 경로(`unit_source='xbrl'`). XBRL 값은 인쇄가 아니라 택소노미 부호를 따른다. 텍스트(XML·웹뷰) 경로만 대상이다.

## 4. 구현

1. **순수 모듈** `fin2/extract/cf_outflow_sign.py` 에 `repair_cf_outflow_section_signs(lines) -> list[corrections]` 를 둔다.
   입력은 `.statement/.basis/.table_seq/.row_order/.col_index/.section_path/.label_raw/.value_won` 을 가진 객체이고, 값을 제자리에서 수정한다.
   추출기의 Line 객체와 DB 행 어댑터가 같은 함수를 쓴다.
2. **추출 경로 배선**: `as_printed.STEPS` 에 `"R232_cf_outflow_sign"` 을 추가한다. `report_lines.py` 에서 `checkpoint("_base")` 바로 다음, **R18 앞**에 호출한다.
   R18 을 앞에 두면 R18 이 이미 음수로 만든 배당 셀을 이 규칙이 구간 전체를 −1 할 때 다시 양수로 되돌린다.
   R232 를 먼저 두면 R18 은 이미 맞는 부호를 보고 아무것도 하지 않는다.
   `extract_with_corrections` 가 rules-on 실행에서 차이를 `rule='R232_cf_outflow_sign'` 보정으로 자동 기록한다.
   데일리 두 call site(`note_lines_sync`, `xbrl_instance_lines_sync`)와 `verification/ops.py` 재적재, `reload_as_printed.py` 가 모두 이 경로를 지나므로 **배선을 따로 추가할 곳이 없다**.
   R232-b 도 같은 step 안에서 처리하고 rule 이름을 `R232b_cf_outflow_sign` 으로 구분한다. 이를 위해 step 을 두 개(`R232_cf_outflow_sign`, `R232b_cf_outflow_sign`)로 둔다.
3. **소급 백필**은 재추출 없이 한다. `scripts/r232_cf_outflow_backfill.py`:
   대상 필링(CF 에 유출 구간이 있는 54,105건)마다 `report_lines` CF 인쇄값을 읽는다. 이미 보정이 있는 셀은 표시해 두고 건드리지 않는다.
   같은 함수를 실행한 뒤, 그 필링의 기존 `R232*` 보정을 지우고 새로 넣는다(`report_line_id` 연결, kind='value'). 재실행해도 결과가 같다(멱등).
   재적재 때 생기는 결과와 같은지 확인하기 위해, 표본 필링 20건을 `extract_xml_with_corrections` 로 돌려 R232 보정이 백필 결과와 같은지 비교한다.
4. **계층3 재빌드**: 백필 전에 std·ext 스냅샷(`r232_std_before`, `r232_ext_before` — 영향 corp 만)을 만든다.
   그다음 영향 corp 를 `scripts/build_std_v3.py --year-min 1990` 으로 재빌드하고 전·후를 비교한다.

## 7. reviewer 검토 결과와 반영 (2026-10-11)

판정은 조건부 승인이었습니다. 반영 내용은 다음과 같습니다.

1. **R232-b 기각.** 2014 이전 R232-b 대상 25,085구간 중 96% 가 S>|H| 였습니다. 행 누락이 아니라 H 자체가 오염된 표입니다(예: `20111111000419` 별도는 유출 표제 값이 활동 합계와 같음). 2015+ 에서 해당하는 구간은 217개였고, 이것도 이번 범위에서 뺍니다.
2. **소급은 2015+ 만** 합니다(R0-2 소급 범위). 2014 이전 계층2 는 아직 인쇄값이 아니라서 `printed_value` 가 틀어집니다.
3. **R18 가드 추가.** 배당 지급을 양수로 바꾸지 않습니다. 기존 R18 보정 52건 중 15건이 인쇄된 음수를 양수로 뒤집었습니다(`20251114001409` −84,588 → +84,588 등). 이 15행은 삭제했습니다(`fix-r18`).
4. **표제 정규식 강화.** 표제나 부모 단계에 활동어(`영업|투자|재무`)가 있어야 하고, 부정어 `업는|않|아니|수반` 을 제외합니다(`현금유출이업는비용등의가산` 오타 대응). 회귀 테스트에 넣었습니다.
5. **보정이 두 개 붙은 셀**은 백필 후 `GROUP BY report_line_id HAVING count(*)>1` 로 확인했고 0건입니다. 백필은 18시 데일리 전에, 모델 러너가 정지된 상태에서 했습니다(기계 데몬은 읽기 전용).
6. **frozen 셀(다른 규칙이 이미 보정한 셀) 처리.** 그 셀의 보정 부호가 R232 와 다르면 구간 전체를 건너뜁니다. 부호가 같고 크기만 다르면(R18 은 1% 이내에서 태그 금액을 씀) 그 행은 그대로 두고 나머지를 뒤집습니다. 추출기에서도 R18 이 R232 뒤에 돌아서 이기기 때문입니다.
7. **PARSING_RULES R232 절을 코드보다 먼저** 작성했습니다.

**재추출 대조**(63필링: 무작위 22, R18 필링 15, R18 양수 오보정 5, 웹뷰 10, 직접법 영업 구간 10, LG): 계층3 최종값을 비교했습니다. 2015+ 는 전부 일치합니다. 불일치 6건은 모두 2014 이전 필링이고, 그 시기 계층2 가 R0-2 이전 상태(DB ≠ 현재 인쇄 추출)라서 생긴 것이며 범위 밖입니다.

**운영 사고와 복구.** 백필 대상 목록(`rcepts.txt`)을 2015 필터를 넣기 전에 만들어 둔 탓에, 첫 적용이 2014 이전 26,040필링 297,220셀에도 들어갔습니다. 확인한 즉시 `report_lines.report_fiscal_year < 2015` 인 R232 행을 삭제했습니다. 2014 이전은 재빌드하지 않았으므로 std/ext 에는 반영되지 않았습니다. 남은 것은 2015+ 6,496필링 98,370셀입니다.
