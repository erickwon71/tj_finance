## 2. ★같이 발견한 것 — 선언이 있는데도 못 받는 표 (약 4.9M 셀)

C 버킷을 "항목 경계 안에 관장 선언이 있는가"로 다시 나누면:

| | 표 | 셀 | 전수 환산 |
|---|---|---|---|
| 항목 경계 안에 선언 있음 | 707 | 22,383 (53.4%) | **약 4.9M 셀** |
| 항목 안에 선언 없음(주주현황 등) | 1,202 | 19,501 (46.6%) | 약 4.2M 셀 |

원문 구조(실측 `20230515001080` 8.범주별 금융상품):

```
<P>   (1) 당분기말과 전기말 현재 범주별 금융상품의 내역은 다음과 같습니다.<당분기말>

```

`declared_unit` 은 직전형제·첫행·메타형제 3칸만 본다. 사이에 낀 **데이터표가 '라벨 있는 비메타'**
라 탐색이 거기서 멈춘다. 그래서 같은 선언 아래 두 번째 데이터표부터 단위를 잃는다.
당분기말/전기말 쌍으로 표를 나누는 서식이 흔해 규모가 크다.

### 왜 이번에 고치지 않았나 (사용자 판단 필요)

"직전 데이터표의 단위를 상속"은 **추측**이라 오염 위험이 있다. 같은 항목 안이라도 다음 표가
주식수 표면 ×1,000 오염이 된다. 실제로 표본에서 그런 배치가 보였다(`20230512001205`:
'(단위 : 원/주)' 선언 뒤 데이터표, 그 다음 표는 **주식 적수**).

⚠ 도구를 만들며 한 번 틀렸던 것도 기록해 둔다 — 초판은 "경계 무시 넓은 창"에서 선언을 찾아
**1,891/1,909 표(99%)가 회수 가능**이라고 셌다. 원문을 열어 보니 그 선언은 대부분 **남의 표
것**이었다(주주현황 표가 4형제 앞 '연결 재무상태표 … 단위:원' 을 주워옴). 항목 경계
(`_ITEM_BOUNDARY`)를 넣고 다시 세서 53.4% 로 정정했다. **집계는 원문을 열기 전까지 가설이다.**

### 대안 (재적재 전에 결정하면 같은 패스에 반영 가능)

| 안 | 내용 | 위험 |
|---|---|---|
| ① 현행 유지 | `value_won=NULL` + `value_raw` 보존 | 금액 4.9M 셀이 계층3 에서 못 쓰인다 |
| ② 항목 내 상속 | 경계 안의 선언을 상속하고, 열 헤더가 비금액이면 그 열은 NULL | 헤더가 침묵하는 주식수 열이 ×1,000 |
| ③ 선언표 한정 상속 | **선언만 담은 표**(데이터 없는 1행 표)가 앞에 있을 때만 상속 | 위 실측 서식을 정확히 겨냥. 적용 범위는 더 좁다 |

권고 = **③**. 상속 근거가 "표 사이에 놓인 선언 블록"이라는 원문 구조 사실이고,
`20230512001205` 같은 배치(선언이 데이터표 표제에 붙은 경우)에는 발동하지 않는다.

## 3. B 버킷(9,732 셀 = 18.9%)

금액행이 2 개 미만이라 `_table_has_data_rows` 가 걸러낸다. 지금도 적재 대상이 아니고 F1 도
바꾸지 않았다. 소형 키-값 표라 가치 대비 용량이 나쁘다고 판단 — 필요하면 별도 결정.

## 4. 용량 영향(F1 반영 시 추정)

미선언 C(9.1M) + 비금액단독(2.87M) + 금액선언 회수(2.63M) ≈ **14.6M 셀**.
현행 note_lines 는 369 B/행이라 그대로면 +5.4 GB, Phase 4 스키마 축소(목표 ~120 B/행) 후에는
**+1.8 GB** 수준이다. `value_raw` 는 값이 채워진 칸에는 넣지 않으므로 증가분은 비금액·미확정
칸에만 붙는다(표본에서 적재 행의 7.9%).
