# DEF-4 — calendar_financials 인접연도 CQ1(1분기) 수치 중복 — 광범위 데이터 결함(데이터결함, 앱버그 아님)

- **심각도**: S1 격상 검토 대상(범위가 매우 넓고 조용히 잘못된 값을 노출)
- **분류**: 데이터결함 (앱버그 아님 — 앱은 DB에 저장된 값을 있는 그대로 정확히 표시하고 있음)
- **상태**: 🔎 근본원인 확정(2026-07-08, 아래 참고) — 데이터 재생성·파이프라인 수정은 차기 라운드(사용자 결정, 이번 라운드는 조사만)
- **발견 체크리스트 ID**: DS-2/DS-3 조사 중 부수적으로 발견 — UI가 DB값을 그대로 보여주므로 자동 스윕의 UI↔DB 대조로는 잡히지 않고, DB 자체를 직접 대조하다 발견됨
- **발견일 / 담당자**: 2026-07-08 / shard5(DEF-S5-1, MDS테크)와 shard2(DEF-S2-1, 삼영이엔씨)가 각자 독립적으로 관찰, 감리(Opus)가 두 관찰을 연결하고 전수 규모를 정량화

## 위치
- **테이블**: `calendar_financials` (앱의 분기 재무제표 뷰가 조회하는 원천 테이블)
- **패턴**: 같은 기업·같은 재무제표 기준(연결 또는 별도)에서, **인접한 두 해의 CQ1(1~3월, 달력 1분기) 매출액과 영업이익이 소수점까지 완전히 동일한 값**으로 저장됨.

## 발견 경위
1. shard5가 MDS테크(00445841)의 분기x연결에서 UI↔DB 값불일치를 발견(DEF-S5-1) — 조사 중 DB 자체에 2012 CQ1과 2013 CQ1의 revenue/operating_income이 완전히 동일하게 저장된 것을 발견.
2. shard2가 삼영이엔씨(00288343)의 분기x별도에서 "동일 UI값이 다른 연도에 반복"되는 패턴을 발견(DEF-S2-1).
3. 감리가 DEF-3 조사 중 삼영이엔씨의 DB 원값을 직접 대조하다가, 2017 CQ1과 2018 CQ1의 연결 기준 매출액·영업이익이 완전히 동일함을 재확인 — MDS테크와 동일한 유형의 이상현상임을 확인.
4. 감리가 `calendar_financials` 전체에 대해 "같은 기업·같은 statement_type에서 인접연도 CQ1 매출액·영업이익이 완전히 동일한 경우"를 SQL로 전수 검사.

## 실제결과 — 규모(전수 검사 결과)
- 전체 `calendar_financials`의 CQ1(값 존재) 행 **69,485건** 중,
- **3,996건**(corp_code·statement_type·연도쌍)이 인접연도와 매출액·영업이익 모두 완전 동일(약 **5.75%**).
- 영향받는 **고유 (기업, 연결/별도) 조합 수: 3,626건**.
- **2012→2013년 전환 구간에 뚜렷하게 집중**되는 클러스터가 관찰됨(다수의 서로 무관한 기업에서 반복 확인). 그 외 연도에도 산발적으로 발생.

## 증거
- 감리가 실행한 전수 SQL(인접연도 CQ1 완전동일값 검사) 결과, 상위 30건 샘플 확인(00100601, 00100939, 00101044, 00101220, 00101433, 00101488, 00101549, 00101628, 00101664, 00101752, 00102113, 00102140, 00102353, 00102432, 00102618, 00102751, 00102858 등 다수 기업의 corp_code·statement_type·연도쌍).
- 상세 사례: MDS테크(2012/2013 CQ1, DEF-S5-1 원문), 삼영이엔씨(2017/2018 CQ1, 연결).
- **UI는 이 값을 있는 그대로 정확히 표시하고 있어 자동 스윕의 UI↔DB 대조로는 발견되지 않음** — 화면 검증만으로는 잡을 수 없고 DB 자체의 정합성 점검(인접기간 완전동일값 검사 등)이 별도로 필요함.

## 영향 범위
- 범위가 넓어(3,626개 기업×기준 조합) 단일 기업 이슈가 아니라 데이터 전반의 문제로 판단됨.
- **DEF-3(별도/연결 표시 문제)와는 무관한 별개 결함**임 — 두 문제가 우연히 같은 기업(삼영이엔씨)에서 겹쳐 관찰되어 최초 보고서(DEF-S2-1)에서는 하나의 현상처럼 보였으나, 실제로는 서로 다른 두 층의 문제(앱의 별도/연결 표시 문제, DB의 CQ1 인접연도 중복값)가 중첩된 것임.

## 근본원인 확정 (2026-07-08 개발 조사)

**결론: `fact_v2` 추출 단계의 분기 손익계산서 비교컬럼(전기 3개월) 값 중복 버그.** 앱·calendarize·comparative_fallback 은 모두 이 잘못된 셀을 충실히 전파할 뿐.

### 역추적 증거 (MDS테크 00445841, 2013 Q1 보고서 rcept=20130529000237)
`fact_v2` 의 `is.revenue` 셀을 직접 조회한 결과:

| basis | col_index | context_fiscal_year | amount_won |
|---|---|---|---|
| consolidated | 0 (당분기) | 2013 | 15,826,382,291 |
| consolidated | 1 (전기) | 2012 | **15,826,382,291** ← col0 과 동일(오류) |
| consolidated | 2 (전전기) | 2011 | 15,111,992,486 (정상, 상이) |
| separate | 0 | 2013 | 13,226,425,885 |
| separate | 1 | 2012 | **13,226,425,885** ← col0 과 동일(오류) |
| separate | 2 | 2011 | 12,639,538,117 (정상, 상이) |

→ **당분기(col_index=0) 값이 전기 3개월(col_index=1) 슬롯에 그대로 복제**됨. 전전기(col_index=2)는 정상. 분기보고서 IS 의 duration 컨텍스트(당분기 3개월 vs 전년동기 3개월)를 구분하지 못하고 같은 값을 col1 에 채우는 XBRL/표 추출 오류로 판단.

### 전파 경로
1. `fact_v2` col1 == col0 (버그 발원지).
2. `fin2/standardize/build.py::standardize_comparative_corp` → `_collect_comparative` 가 나중 보고서의 col1(전기)에서 (fy-1) 행을 합성 → 잘못된 col1 값을 std_financials_v2 (fy-1, Q1)에 기록. 이 때문에 인접연도 N·N-1 의 Q1 이 동일해짐.
3. `calendarize` 가 std 값을 CQ1 으로 그대로 배치 → `calendar_financials` 인접연도 CQ1 동일값. (calendar derivation 이 `native` 로 표기되는 라벨링 갭도 함께 확인 — 실제로는 comparative 합성행)

### 규모 (재현: `scripts/diag_calendar_cq1_dup.py`)
- calendar_financials 인접연도 CQ1 완전동일 페어 **4,046** / 고유 (기업,기준) 조합 **3,652** (CQ1 값존재 행의 5.82%).
- std_financials_v2 인접연도 Q1 동일값 페어 **3,476** 중 **3,445(99.1%)가 동일 `is_rcept` 공유** → 단일 후기보고서 백필 시그니처 확정.
- 연도쌍 분포: 2012→2013(777) 최다, 2007→2008(408), 2003→2004(218) 등 IFRS/분기 도입기에 집중되나 전 연도에 산발.

### 차기 라운드 수정 방향 (이번 라운드 미적용 — 사용자 결정: 조사만)
1. **발원지 수정**: `fact_v2` 분기 IS 추출에서 당분기 3개월 duration 을 전기(col_index=1) 컬럼에 중복 매핑하는 로직 교정. 대상은 fact_v2 를 채우는 추출기(분기 IS duration 컨텍스트 → col_index 매핑).
2. 수정 후 영향 corp 에 대해 `fin2_reextract_*` → `fin2_comparative_financial.py` → `fin2_quarterly_all.py` → `fin2_calendar_all.py` 재실행(범위·순서는 별도 계획).
3. **DQ 어서션 추가**(`scripts/dq_assertions.py`): (a) 분기보고서 fact_v2 에서 `is.revenue`/`is.operating_income` 의 col_index=0 == col_index=1, (b) calendar_financials 인접연도 CQ1 완전동일값 — 재발 감지.
4. calendar `derivation='native'` 라벨링이 comparative 합성행에도 붙는 문제 별도 점검.
