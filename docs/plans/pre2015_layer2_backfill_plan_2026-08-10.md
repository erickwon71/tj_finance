## 0. 한 줄 요약

계층2(`report_lines`)는 현재 **2015년 이후 원본만** 적재돼 있다(1차 패스, 2026-07-22 완료).
그 이전(1999~2014, K-GAAP 구서식) 원본은 **이미 전량 다운로드는 끝났지만**(로컬 XML 완비)
파싱·적재가 전혀 안 됐고, 그 공백을 `standard_financials` 뷰가 구 체인(`std_financials_v2`)
UNION 폴백으로 메우고 있다. 이번 트랙의 목표 = **그 pre-2015 XML 원본을 계층2 파이프라인으로
직접 적재**해 v2 폴백을 없앨 수 있는 상태를 만드는 것. 오늘 실측한 결과, 과거 문서가 추정한
"70,374건"보다 크고(현재 유니버스 기준 **79,283건 XML · 1,551개사**), 구조는 우려했던 것보다는
현재 파서 인프라(SECTION-2/TITLE lxml 트리, `sanitize_dart_xml` 인코딩 폴백)를 재사용할 여지가
있어 보이지만, **섹션 계층 구조 자체가 다르다**(아래 §3) — 신규 파서가 필요하다는 기존 판단은
유효하다.

## 3. 구조 실측 (샘플 조사, 결론 아님 — Phase 1에서 정밀화 필요)

FY1999 대원전선(00260392) 사업보고서(`20000224000013.xml`, 927KB)를 직접 열어 확인:

- **인코딩**: 이 샘플은 정상 UTF-8(과거 문서가 우려한 EUC-KR 오판 이슈 없음). 다만
  `sanitize_dart_xml()`이 이미 UTF-8→EUC-KR 자동판별 폴백을 갖고 있어(`_detect_xml_encoding`),
  설령 다른 연도 파일이 실제 EUC-KR이어도 **기존 인프라가 이미 처리 가능**해 보인다 — 새 작업
  불필요할 가능성이 높음(전수 검증은 필요, §5 Phase1).
- **XML 골격은 현재와 같은 계열**: `<SECTION-1>`/`<SECTION-2>`/`<TITLE>` 구조 그대로 존재.
  즉 "완전히 다른 DTD라 lxml 트리 자체를 다시 짜야 한다"는 최악의 시나리오는 아님.
- **그러나 섹션 계층(의미 구조)이 근본적으로 다르다** — 이게 신규 파서가 필요한 진짜 이유:
  - 현재(2015+) 파서는 리프 `TITLE` 텍스트 자체에 "연결"/"별도" 수식어와 재무제표 종류가
    모두 들어있다고 가정한다(`section_detector.py` 패턴: `["연결","재무상태표"]` 처럼 텍스트
    내 키워드 매칭).
  - 이 1999년 샘플은 그렇지 않다. `3. 재무제표`(별도, 상위 헤딩만으로 암시) 아래
    `가. 대차대조표`/`나. 손익계산서`/`다. 이익잉여금처분계산서 또는 결손금처리계산서`/
    `라. 현금흐름표`/`마. …재무제표에 대한 주석`이 나열되고, **완전히 별개의 상위 섹션**
    `4. 연결재무제표` 아래에 연결 재무제표가 다시 나온다. 즉 "연결" 여부가 **리프 TITLE
    텍스트가 아니라 상위 헤딩 계층**에만 있다 — 현재 패턴매칭 로직으로는 연결/별도 구분이
    안 되거나 아예 놓칠 가능성이 높다. `4. 연결재무제표` 아래의 실제 리프 구조(어떻게
    "연결대차대조표"에 해당하는 TITLE이 표기되는지)는 이번 샘플링에서 **끝까지 확인하지
    못함** — Phase 1 최우선 확인 항목.
  - **K-GAAP 전용 표**(`이익잉여금처분계산서 또는 결손금처리계산서` = 이익잉여금 처분/결손금
    처리 계산서)는 현재 스키마(BS/IS/CF/주석 4종)에 대응 항목이 없다. 스코프에 넣을지
    (신규 statement 종류 추가) 뺄지(주석 취급 or 미적재) **정책 결정 필요**(§6).
- **표(TABLE) 셀 구조**는 얼핏 다른 태그(`TU`=단위 셀, `TABLE-GROUP ACLASS="COVER"`,
  `P-SMALL`/`P-MEDIUM` 텍스트 단락)가 섞여 있으나 표지(COVER)·안내문 영역 얘기라 본문 표에도
  같은 패턴이 있는지는 미확인 — Phase 1에서 재무제표 본문 TABLE 샘플을 직접 대조 필요.
- **결론**: "신규 파서 개발 필요"라는 기존 판단은 **유효**하되, 우려했던 "전혀 다른 포맷"은
  아니고 "같은 XML 계열, 다른 섹션 계층/명명 규칙"에 가깝다 — `section_detector.py`를
  **확장**(신규 작성 아님)하는 방향이 유력. 단, 1999~2014 **16개 회계연도**에 걸쳐 서식이
  균일하지 않을 가능성이 크므로(과거 문서가 "2009~13 `<P>` 구분자·2000~08 미확인"이라 추정한
  것도 이번 샘플과는 다른 관찰 — 확인되지 않은 가설이었음이 드러남) **연도별/발행사 규모별
  층화 표본으로 실측부터** 해야 한다.

## 5. Phase 계획

### Phase 1 — 구조 정밀 실측 (읽기 전용, 밀린 T4를 부활+확장)
과거 계획의 T4("층화표본 200 filing, 파싱 성공률·단위 미선언 비율 측정")를 계승하되, §3에서
드러난 대로 **섹션 계층 구조 카탈로그**까지 넓힌다.
- 1-1. 연도(1999~2014, 16개년)×규모(대형/중소형)×report_type(annual/half/quarter) 층화 표본
  (연도당 10~15건, 총 200건 내외) 추출.
- 1-2. 표본마다: (a) 인코딩 실측(UTF-8 vs EUC-KR 실제 분포), (b) SECTION-2/TITLE 트리 구조
  스냅샷(연결/별도 표기 방식이 리프 TITLE인지 상위 헤딩인지, 연도별로 언제 바뀌는지),
  (c) 본문 TABLE의 셀 구조(현재 `table_extractor.py`가 다루는 TD/TU/ROWSPAN/COLSPAN 패턴과
  얼마나 같은지), (d) 단위 선언 문구 위치·표기(현재 `text.declared_unit`이 인식하는 패턴과
  다른지), (e) K-GAAP 전용 표(이익잉여금처분계산서 등) 존재 빈도.
- 1-3. 산출물: `docs/qa/pre2015_structure_probe_2026-08-XX.md` — 연도 구간별 "서식 세대"
  경계 확정(예: "1999~2005 A형, 2006~2011 B형, 2012~2014 C형" 식 가설 검증), 각 세대별
  필요 작업 목록.
- **게이트**: 이 Phase 결과 없이 Phase 2(파서 설계) 착수 금지 — 원본 대조 없는 추정으로
  설계하면 §3 사례처럼 틀린 가정("<P> 구분자")이 그대로 코드에 들어갈 위험([[feedback-verify-against-source]]).

### Phase 2 — 파서 설계
Phase 1 카탈로그를 근거로 확정:
- 2-1. `section_detector.py` 확장 방식 결정 — 리프 패턴매칭에 상위 헤딩 컨텍스트(연결/별도)를
  전파하는 로직 추가 vs 별도 legacy 검출 함수 신설 후 라우팅(연도 기준 분기).
- 2-2. K-GAAP 전용 표(이익잉여금처분계산서/결손금처리계산서) 스코프 결정 — 옵션: (a) 신규
  statement 종류로 report_lines에 전사만(계층3 매핑은 후속), (b) 주석 취급, (c) 미적재.
  **사용자 결정 필요**(현재 스키마엔 대응 계정 없음, 계층2 R0 "있으면 파싱"과 "쓸모없는
  계정 무단 확장 지양"이 충돌 — 판단 필요).
- 2-3. `table_extractor.py` 재사용 가능 범위 확정, 필요 시 pre-2015 전용 셀 파싱 보강.
- 2-4. `amount_normalizer`/`text.declared_unit` 단위 판정 로직의 pre-2015 표기 커버리지 확인.
- 산출물: 설계 문서(이 계획서에 이어 붙이거나 별도 문서) + 사용자 승인.

### Phase 3 — 구현 + 단위 테스트
- 3-1. Phase 2 설계대로 `section_detector.py`/`table_extractor.py`(필요 시 `parser/xml/legacy_*.py`
  신설) 구현.
- 3-2. 카나리아 표본(Phase 1의 200건 표본 재사용) 대상 단위 테스트 + 원문 대조.

### Phase 4 — 파일럿 백필 + 검증
- 4-1. 표본(연도별 대표 corp 20~30개사, 전체 filing) 파일럿 적재.
- 4-2. 원문 대조(항등식 BS: 자산=부채+자본, 표본 30~50건) + Gate B 상당 무결성 체크.
- 4-3. 실패율/미설명 잔여율 측정 → 필요시 Phase 2~3 재작업(작게 반복, "조금 진행 후 확실치
  않으면 되돌아온다" 원칙).

### Phase 5 — 전량 백필
- 5-1. `load_report_lines.py` 패턴 재사용(샤딩·재개·원자커밋) — 79,283건.
- 5-2. 무결성 어서션 통과 확인, 오류 0 목표(1차 패스 실적 기준).

### Phase 6 — 파이프라인 편입 + 문서화 (필수, [[parser-pipeline-integration-runbook]])

## 7. 리스크

- **16개 회계연도의 서식 이질성** — 과거 문서의 가설("2009~13만 다르다")이 이번 샘플로
  이미 반증됐다(1999년 샘플이 SECTION-2/TITLE을 갖고 있어 "<P> only"가 아니었다). Phase 1을
  건너뛰고 설계하면 또 틀릴 위험이 큼.
- **볼륨** — 79,283건은 1차 패스(102,633건)의 77% 규모. 파싱 성공률이 1차만큼 안 나오면
  (신규 서식이라 당연히 낮게 시작) 반복 보정 사이클이 여러 차례 필요할 수 있음.
- **K-GAAP 계정 체계 차이** — IFRS 전환(2011년) 전후로 계정과목명 자체가 다를 수 있어(예:
  "이익잉여금" vs "이월이익잉여금", "자본잉여금" 세부 항목 등) 계층3 매핑(§Phase 7, 별도
  트랙)에서 추가 작업이 필요할 가능성 — 이번 트랙(계층2)은 "판단 없이 전사"만 하므로 직접
  영향은 적으나, 매핑 사전 확장 필요성을 미리 문서화해 둘 것.
