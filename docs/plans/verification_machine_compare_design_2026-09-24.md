## 1. 결정 (사용자, 2026-09-24 21시)

- **A안 채택**: 기계 대조를 기본 판정으로 한다. 기계가 불일치를 찾은 셀만 모델이 DART 웹뷰로 확인한다.
- 기계가 일치로 판정한 슬롯 중 **1%** 는 모델이 웹뷰로 전체를 다시 대조한다(audit).
- 범위는 **2015+ 전체**(pending 92,856 슬롯, 필링 약 10만 4천 건).
- 모델 러너를 중단하고 전환한다.

### 왜 바꾸나
- 웹뷰 전체 대조는 슬롯당 평균 45턴·5분이다. Max x5 주간 예산으로 하루 약 60슬롯이 한계였다.
- 그 속도면 2015+ 전체에 약 4년 3개월이 걸린다(설계 §11 실측: 회당 주간 0.14%p).
- 기계 대조는 필링 1건에 0.2~1초이고 모델 사용량이 들지 않는다. 모델은 기계가 판단하지 못한 곳에만 쓴다.

### 무엇이 바뀌나 (판정 근거)
| 필링 | 이전 | 이후 |
|---|---|---|
| 기계 clean | 모델이 웹뷰로 전체 대조 | 기계가 pass(`verified_by=camp_run:machine`, 노트 `[machine mc1] …`) |
| 기계 mismatch | 〃 | 모델이 **발견 항목만** 웹뷰로 확인 → 이슈 등록 또는 pass(`기계오탐:` 노트) |
| audit(1%)·원문 XML 없음·구조 판단 불가 | 〃 | 모델이 웹뷰로 전체 대조(이전과 같음) |

## 2. 기계 대조 규칙 (`fin2/verification/machine_compare.py`, 버전 `mc1`)

**파서와 독립**이다. `parser/`·`fin2/extract/` 를 쓰지 않는다. 파서 결함이 양쪽을 똑같이 틀리게 만들지 못하도록 하기 위해서다.
판단이 애매하면 항상 "불일치" 쪽으로 보낸다. 기계 오탐은 모델 시간만 쓰지만, 기계 누락은 결함을 숨기기 때문이다.

- **대상 표**: 원문 XML `SECTION` 제목이 `연결재무제표`/`재무제표` 인 섹션 안의 표만 본다(`주석`·`요약` 제외). 섹션으로 연결/별도를 정한다.
  표 종류(BS/IS/SCE/CF)는 앞 제목표(`연결 포괄손익계산서` 등)로 정하고, 없으면 내용으로 정한다(기초자본→SCE, 영업활동→CF, 자산총계→BS).
- **격자**: rowspan/colspan 을 펼친다. 첫 금액 행 이전이 헤더다. 헤더가 `주석` 인 열은 금액이 아니다.
- **당기 열**(BS/IS/CF, DB `col_index` 0)
  - 같은 헤더를 공유하는 인접 열은 한 기간이다(`제65(당)기` 아래 세부·합계 2열). 기간 안 어느 열이든 일치하면 인정한다.
  - 헤더에 `누적` 열이 있으면 DB `is_cumulative` 에 따라 가장 왼쪽 `누적`(또는 `3개월`) 기간이다. 없으면 가장 왼쪽 기간이다.
- **SCE**: DB `col_index` k = k번째 금액 열.
- **행 맞춤**: 정규화 라벨(공백·`&cr;`·번호·`(주석n)` 제거)로 difflib 정렬 후, 순서만 다른 같은 라벨 행을 다시 짝짓는다.
  2단 라벨(`상위|하위|금액…`)은 `상위>하위` 로 합친다(DB 표기와 같음).
- **금액**: `(1,234)`·`△`·`-`(=0)·빈칸(값 없음)·`2,564원`. 한 셀에 `&cr;` 로 여러 값이 있으면 첫 값이다(대손준비금 보충표기).
  배수(1/천/백만/억)는 DB 그룹마다 다수결로 정하고, 주당 행은 항상 원 단위다.

### 발견 종류
| 종류 | 뜻 |
|---|---|
| `value` | DB 값 ≠ 기대 열의 원문 셀. `found_at`(같은 값이 있는 열)·`flipped_at`(부호만 다른 열)을 함께 남긴다 |
| `missing_row` | 당기 금액(0 아님)이 있는 원문 행이 DB 에 없음. SCE 는 0 아닌 셀이 있는 행 |
| `zero_row` | 전열 `-` 인 원문 행이 DB 에 없음. 값 영향은 없지만 캠페인이 이슈로 등록해 왔다(#103~) |
| `extra_row` | DB 행이 원문 표에 없음 |
| `uncovered_cell` | SCE: 짝지어진 행의 0 아닌 원문 셀에 대응하는 DB 셀이 없음 |
| `unmatched_table` | 재무제표 섹션의 데이터 표(금액 행 3+)가 어느 DB 그룹과도 짝이 없음(이익잉여금처분계산서 제외) |
| `no_table` | DB 그룹에 대응하는 원문 표가 없음 |
| `sce_identity` | SCE 열별 `기초 + 변동 = 기말`, 또는 날짜가 이어지는 `기말 → 다음 기초` 불일치 |
| `bs_identity` | `자산총계 = 부채총계 + 자본총계` 불일치 |

- **항등식이 필요한 이유**: 원문 자체가 음수 괄호를 빠뜨린 경우(R162)에는 DB 가 원문을 그대로 따르므로 셀 대조로는 보이지 않는다.
- **SCE 합계행 판정**: 라벨이 너무 다양해서 값으로 판정한다.
  - 앞 연속 행들의 합 = 이 행이면 합계다(2행 이상, 합계형 라벨이면 1행).
  - 뒤 연속 행들의 합 = 이 행이면 부모 행이다.
  - 누적 잔액과 같으면 잔액 반복 행(`수정 후 기초`)이다.
  - 세 방식 중 하나라도 맞으면 통과다.
- **DB 우선 계산**: 항등식은 DB 값으로 계산한다. DB 가 원문의 부호를 뒤집어 적재했고 그 부호로 항등식이 성립하면,
  로더가 원문 부호 누락을 복원한 것(R162)이다. 그래서 그 `value` 는 발견에서 빼고 `sign_restored` 로 센다.
- **판정**: 발견 0 → `clean`. 원문 XML 없음 → `no_source`. 재무제표 섹션 표 없음 → `no_structure`(DB 행도 없으면 skip). 예외 → `error`.

## 4. 흐름

```
machine run (camp_run, actor camp_run:machine, N 프로세스 병렬)
  claim(NEEDS_MACHINE: pending 필링 중 현재 load_seq 기계판정 없음) → 필링별 compare
  → machine_checks upsert → clean 이면 pass (audit 1% 당첨 슬롯은 pass 안 함) → done
model runner (camp_run, claude -p, kv machine.gate=on)
  claim(MODEL_READY: 모든 pending 필링에 현재 기계판정이 있음, 또는 has_issues 재확인)
  → show 의 기계대조 줄을 따라 발견 항목만(또는 전체) 웹뷰 확인
재적재(수정 워크트리) → load_seq 이동 → 기계판정 stale → 기계가 다시 대조
```

- 스키마: `verification.machine_checks` 한 테이블만 추가했다(기존 테이블은 바꾸지 않음). `tjf_verify` 에 INSERT/UPDATE 를 부여했다.
- kv
  - `machine.gate`(on/off): off 면 모델 러너가 예전처럼 모든 pending 슬롯을 집는다.
  - `machine.audit_pct`(기본 1).
- 기계가 건드리지 않는 것: 미해결 이슈가 있는 필링(재확인은 모델 몫). 이슈 등록·close 도 하지 않는다.

## 5. 알려진 한계 (mc1)

- 당기 값만 대조한다(DB 가 당기만 적재). 전기 열은 원문 행 존재 판정에만 쓴다(`prior_only` 로 셈).
- 헤더가 제목표로 분리돼 표 안에 없으면 가장 왼쪽 기간을 당기로 본다. 좌우가 뒤바뀐 서식은 `value` 로 모델에게 간다.
- CF 항등식(기초현금+증감=기말현금)은 아직 없다. 부호만 다른 CF 셀은 `value`(flipped_at)로 모델에게 간다.
- 라벨 없는 최종행(#51)처럼 짝 판단에 라벨이 필요한 경우는 놓칠 수 있다. 1% audit 이 이런 누락률을 잰다.

## 6. mc2 (2026-09-24 22시대, 야간 자율 진행)

mc1 가동 첫 2,779필링에서 불일치 41%가 나왔다. 그중 `sce_identity` 가 895건으로 가장 많았다.
80필링의 항등식 실패 526건을 차이 모양으로 분류했다.

| 분류 | 건수 | 예 |
|---|---|---|
| 한 행(또는 기초/기말) 부호만 뒤집으면 닫힘 | 126+2 | 20180525000233 배당금지급 454,554,457,200 이 괄호 없이 양수(원문 부호 누락, R162 계열) |
| 원문 자체 산수 불일치 | 225+ | 20220323000885 2020 자본금이 25억 늘었는데 변동행이 비어 있음 |
| 차이 = 한 행 값(합계행 판정 한계 포함) | 116 | — |
| 한 행 값이 옆 열로 밀림 | 17 | 테크윙형 빈 셀 끼임 |

- 원문 산수 불일치에서 DB 는 원문과 셀마다 같다. 이전 웹뷰 기준(셀 대조)도 이런 필링을 pass 했다.

**mc2 규칙** — 열마다 "어떤 단일 변경이 항등식을 닫는가" 로 설명을 붙인다.
- `sign_omitted`: 닫는 후보가 **정확히 하나의 셀 부호 반전**이고 열 밀림 후보가 없다. 산수가 증명이므로 **기계가 이슈를 직접 등록**한다.
  - `error_type=sign_flip`, `rule_id=R162`, evidence 에 열·구간·차이를 적는다.
  - 필링의 막는 발견이 이것뿐일 때만 자동 등록한다. 다른 발견이 섞이면 모델에게 넘긴다.
- `sce_identity`(열 밀림 설명): 모델에게 간다(DB 열 오귀속 가능성).
- `sce_arith`(그 외, DB=원문): **기록만 하고 pass 를 막지 않는다**(`INFO_KINDS`). machine_checks.findings 에 남아 나중에 분석할 수 있다.
- 구버전(mc1) 판정 중 mismatch/error 는 stale 로 보고 기계가 다시 대조한다. 모델 게이트도 이를 기다린다.

**재측정**
- 캠페인 이슈 31필링: 30/31 불일치(변화 없음).
- 무작위 passed 150 / pending 146: 불일치 21% / 32%(mc1 32% / 46%). 이 중 sign_omitted 만 있는 필링은 모델 없이 이슈로 끝난다.

## 7. mc3 (2026-09-24 22:30)

mc2 불일치 601건 중 `unmatched_table` 104건을 표본으로 봤다. 전부 은행·보험의 `예치금이자·증권이자` 명세 표이거나 `처분전이익잉여금` 처분계산서였다(적재 대상 아님).
- `unmatched_table` 은 표 종류가 확인된 표(제목 또는 내용 앵커로 BS/IS/SCE/CF)만 대상으로 한다. IS 내용 앵커를 추가했다(순이익 + 법인세/영업이익/매출).
- 처분계산서 패턴에 `처분전이익잉여금|처분예정` 을 추가했다.
- 남은 과제(모델 `기계오탐:` 노트로 확인 예정): SCE 에서 같은 라벨 행이 연도 블록마다 반복될 때 difflib 가 다른 블록 행과 짝짓는 `value` 오탐(예 20240320001872 현물출자 과세특례).

## 8. mc4·mc5 (2026-09-25 새벽) · 기계 대조 1회전 결과

**1회전 완료(02:36)**
| 항목 | 값 |
|---|---|
| 슬롯 | passed 1,695 → **65,036** · has_issues 13,549 · 모델 대기 pending 15,992 |
| 필링 기계판정 | clean 70,429 · mismatch 31,649 · no_source 1,627 · audit 192 |

- mc4: `bs_identity` 가 '자본과부채총계' 를 부채총계로 잡던 오탐 수정. 모델 run 의 첫 `기계오탐:` 노트로 발견했다.
- mc5: 모델 대기열의 `value` 셀이 SCE 에 몰려 있었다(값 다름 약 11만 4천 · 원문 빈칸 약 4만 3천 셀).

  - 조치: **값 보조 재짝짓기**. 셀이 어긋난 짝을 모두 풀고, 같은 라벨 행 가운데 DB 셀이 전부 맞는 빈 행에 다시 배정한다.
- mc5: `zero_row`(전열 `-` 행 누락)를 **정보성**(pass 를 막지 않음)으로 바꿨다. 모델 대기 6,352필링이 여기에 해당했다.
  - 값 영향이 없고, 발견은 machine_checks 에 남는다. 이슈로 올릴지는 사용자 판단 대상이다(`issues-json --kinds zero_row` 로 언제든 등록 가능).
- 재측정(mc5): 무작위 passed/pending 불일치 13% / 23%.
  - 캠페인 이슈 필링 중 clean 으로 바뀐 것: zero_row 4(설계대로), 이미 수정·재적재된 1(20220321001523), label_mismatch 2(값은 같고 라벨만 다름).
- **알려진 한계**: label_mismatch 는 기계가 라벨을 정규화해 짝지으므로 보지 못한다. 1% audit 이 이런 누락률을 잰다.
