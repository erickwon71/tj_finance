# QA: report_lines BS/IS/CF 행수(row count) 전수 이상치 스캔 (2026-09-08)

## 배경

[[r63_cross_year_stale_reprint_extension_design_2026-09-08]] 작업 중 사용자가 IS 행수가
극단적으로 적은 표본(00104698 LS네트웍스 2001Q1, IS=7행)을 원문과 직접 대조하자고
지적 → **원문에 있는 정상 손익계산서(28개 판관비 세부항목 포함)가 우리 DB엔 7행뿐**임을
확인, 이어서 "max도 100개가 넘어가는 것도 이상하다"는 지적으로 전수 스캔 요청.

## 조사 범위

`report_lines`에서 `(corp_code, rcept_no, statement, basis)` 단위로 행수를 집계 —
BS/IS/CF × 분기/반기/사업보고서 × unit_source(pdf/그외) 27개 조합, 전체 **869,191건**.

## 이상치 판정 방법

그룹(statement × 기간유형 × unit_source버킷)별로 로그스케일 IQR(사분위범위):
`하한 = exp(Q1 - 1.5×IQR)`, `상한 = exp(Q3 + 1.5×IQR)`. unit_source를 분리한 이유 —
PDF복구 경로가 구조적으로 더 거칠게 뽑히는 게 이미 알려진 특성이라(BS 중앙값
일반 41행 vs PDF복구 10행), 섞으면 정상적인 PDF복구 필링까지 대량 오탐된다.

**결과**: 낮은 이상치 3,549행(중복제거 후 (corp,rcept,basis) 단위 **3,237건**),
높은 이상치 38,037행(**30,851건**).

## 원문 재검증 — 확정된 2가지 서로 다른 문제

### 패턴A — PDF복구 경로의 값 "조작"(존재하지 않는 숫자) — ★확정(표본 2/2)

- **00104698(LS네트웍스) 2001Q1, IS**: DB 매출액=15,457,120원. DART 웹뷰어에서
  원문 손익계산서 원문을 직접 확보(dcmNo/eleId 파싱 후 `report/viewer.do` 직접
  조회)해 대조 — **매출액 실제값은 48,569,236,559원**이며, DB의 15,457,120은
  원문 재무제표 전체(4개년 비교컬럼) 어디에도 등장하지 않음. 영업이익·경상이익·
  당기순이익도 마찬가지로 원문에 없음(7행 중 "기타이자" 1행만 정확).
- **00103042(케이씨티시) 2001Q1, IS**: DB 매출액=1,793,055원. 원문 재무제표
  섹션(33만자) 전체를 검색해도 존재하지 않음.
- 로컬 아카이브 원본 XML도 확인: 정상 대비 **1/4 크기로 절단**, **UTF-8 디코딩
  시 U+FFFD(깨진문자) 11,631개/132KB(약 9%)** — 기존에 알려진 "Category C
  fy1999~2003 절단분" 문제(PDF복구 도입 계기)와 같은 계열이지만, **PDF복구
  파이프라인(`fin2/extract/pdf.py`)이 이 필링들에서 실재하지 않는 숫자를
  만들어내고 있다는 건 이번에 처음 확인된 사실**.

### 패턴B — 일반(XBRL/declared) 경로의 한쪽 basis 통째 결측 — ★미확정(표본 검증 불완전)

- **00540863(GST) 2014Q1**: `consolidated` IS는 22행 정상, `separate` IS는
  **EPS(기본/희석주당이익) 2행뿐** — 매출액·영업이익·당기순이익 등 본문 라인
  전부 없음.
- **01020524(자이글) 2019Q1**: 같은 패턴 — `separate`는 15행 정상인데
  `consolidated`는 EPS+당기순이익 3행뿐.
- DART 원문에서 실제 별도(개별) 손익계산서 표를 명확히 분리해 대조하려 했으나
  노트/각주와 표가 뒤섞여 있어 **이번 세션에서 확정 검증을 완료하지 못함**.
  가설: XBRL 태깅이 한쪽 basis의 본문 라인을 놓치는(EPS 태그만 잡히는) 결측
  버그로 추정되나 원문 대조로 확정 전까지는 가설.

### 이상치 3,237건(낮은쪽)의 unit_source 분포

pdf 1,048건 / other(declared·xbrl 등) 2,501건 — **패턴B(혹은 유사 별개 원인)로
추정되는 쪽이 건수로는 더 크다.**

### 높은 이상치(38,037건/30,851건)에 대한 판단

R63 조사 과정에서 이미 top-5(BS/IS/CF 각각)를 원문·구조 대조 — 전부 증권사
(미래에셋증권·NH투자증권·교보증권)·현대차 등 **정상적으로 세부계정이 많은
업종/대기업**으로 확인됨(중첩 tree 구조, `기타` 라벨 34회 등 정상 패턴).
로그스케일 IQR이 재무데이터의 자연스러운 업종별 우측 skew를 못 걸러내
노이즈가 많을 가능성이 높음 — **추가 검증 우선순위는 낮게 판단**, 참고용
리스트만 남김.
