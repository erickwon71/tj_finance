## 3. 측정 결과

### 3-1. 용량 — 회수 가능 **52.3 GB / 108.9 GB (48%)**
`docs/qa/db_waste_ledger_2026-07-30.md`. 반복도 추측이 아니라
`GROUP BY 키 HAVING count(DISTINCT col) > 1` 을 **실제 질의**해 함수종속을 확인했다.

| 항목 | 측정된 종속 키 | 회수 |
|---|---|---|
| `note_lines.table_title` | `rcept_no+statement+basis+table_seq` | **27.5 GB** |
| `note_lines.section_path` | 같은 키 | **6.4 GB** ← 계획에 없던 발견 |
| `report_lines.table_title` | 같은 키 | 5.6 GB |

⚠ `uq_stock_prices`·`ux_valuation_daily_corp_date` 는 **건드리면 안 된다** — `ON CONFLICT`
업서트는 `idx_scan` 을 올리지 않아 통계상 0 으로 보일 뿐이다(도구가 UNIQUE 를 합계에서 제외).

### 3-2. 단위 판정 결함 — 오염 **6,130,738 행 / 93,059 filing**
`--contamination-only` 실측(`note_lines.col_label` 근거). 비금액 열 표지인데 `value_won` 이
채워진 행: `이자율(%)` 최대 **2,228조원** · `지분율(%)` 최대 114조원.

원인은 `parser/common/amount_normalizer.py:62` 한 줄. `단위` **직후**에 금액 토큰을 요구한다.

| 패턴 | 결과 | 원문 확인 |
|---|---|---|
| `(단위 : 주, 천원)` | 매칭 실패 → **표째 폐기** | 에쎈테크 `20150817000851` 18셀 미적재 |

## 4. ★이 세션에서 내가 틀렸던 것 두 건 (같은 실수 반복 금지)

계층2 작업의 반복된 실패 모드가 또 나왔다 — **구조적 가설을 세우고 검증 전에 사실처럼 쓰는 것.**

1. "주석이 per-topic SECTION-2 면 주석이 통째 유실될 것" → **틀림.** DB 확인 결과 정상
   적재(SNT다이내믹스 `20250220001259` 3,824행 / 61섹션).
2. "사업의 내용 귀속 붕괴가 추출기 3종 모두에 영향" → **틀림.** 코드 확인 결과 `rd_note`
   한정. `biz_section`·`order_backlog` 는 `root.iter()` 별도 경로다.

도구 자체의 거짓양성도 두 번 잡았다(둘 다 스크립트 docstring 에 기록):
- `audit_db_waste` 초판이 반복도만으로 `value_won`(행별 실데이터)을 정규화 후보로 올려
  합계가 87.5 GB 로 부풀었다 → 함수종속 질의로 교체, **52.3 GB** 로 정정.
- `audit_unit_declarations` 초판이 금액 토큰을 부분문자열(`'원' in tok`)로 판정해
  `원화`·`각1단위`까지 금액으로 셌다 → 토큰 종료 정규식으로 교체(헤드라인 89 → 50).

⇒ **집계가 나오면 반드시 `--rcept` 드릴로 원문 한 건을 열어 확인한 뒤 서술할 것.**
