# 설계 — SCE 자본변동 상세 추출 + 앱 표출 구조 (2026-07-24)

> 상태: **설계 초안 (미실행)**. 사용자 결정(2026-07-24): **SCE 적재 유지 + 자본변동 상세를 앱에 표출**.
> 마스터 허브: [`rearchitecture_4layer.md`](rearchitecture_4layer.md) · 선행(계층2 편입): [`sce_statement_of_changes_in_equity_2026-07-21.md`](sce_statement_of_changes_in_equity_2026-07-21.md)
> 관련: 주주환원 중복점검(gap-fill vs SCE) 결과 → **헤드라인은 gap-fill, 분해상세는 SCE(비중복)**.

---

## 0. 한 줄 요약
report_lines 에 이미 전량 저장된 SCE(자본변동표, 17.5M행)에서 **자본 구성요소(열)×변동사유(행)
매트릭스**를 계층3에서 정규화 추출해 신규 정규화 테이블에 적재하고, 앱에서 **배당(지배/비지배별)·
자사주 취득/소각/처분·주식보상·이익잉여금 사용처** 등 상세를 표출한다. gap-fill 주주환원(총액/DPS/
성향)과 **중복이 아니라 분해 상세**를 제공한다.

## 1. 왜 (gap-fill과의 관계 = 비중복)
gap-fill(`dividend_facts`·`treasury_activity`·`capital_events`·CF)은 **헤드라인 총액·DPS·성향·수량**을
전 유니버스로 커버한다. 그러나 다음은 **SCE 만이 준다**(구성요소 분해가 본질):

| 사용자 요구 항목 | SCE 제공 | gap-fill 로 가능? |
|---|---|---|
| 이익잉여금이 어디에 쓰였는가(배당·결손보전·처분) | 이익잉여금 **열**의 변동사유별 감소 | ✗ (총액만) |
| 지배 vs 비지배 소유주지분별 배당 | 배당 **행** × 지배/비지배 **열** | ✗ (구분 없음) |
| 자사주 취득/소각/처분 | 자기주식 행 × 자기주식/총계 열 | 부분(취득금액 CF·수량 API, 소각은 약함) |
| 주식보상(주식선택권·주식기준보상) | 주식보상 행 | ✗ |

→ **역할 확정: SCE = 자본변동 상세 분해 소스(앱 표출).** (구 "주주환원 1차 출처"는 gap-fill이 대체 →
철회. 상세 분해로 재정의.)

## 2. 데이터 근거 (실측 2026-07-24, report_lines)
SCE 는 이미 매트릭스로 충실전사돼 있다 — **열=자본 구성요소(`col_label`), 행=변동사유(`label_raw`),
값=`value_won`**. context_fiscal_year=NULL, col_index=위치(주석 규약 재사용).

**열(구성요소) 상위**: 자본금(98,885 filing)·자본합계(97,831)·이익잉여금(88,578)·자본잉여금(67,517)·
비지배지분(66,858)·기타포괄손익누계액(57,364)·기타자본구성요소(50,166)·지배기업소유주지분합계(43,391)·
주식발행초과금(20,698)·자기주식(8,336)…

**행(변동사유) 상위**: 당기순이익(손실)·배당금지급(24,542)·유상증자(17,074)·연차배당(14,255)·
자기주식거래로인한증감(12,145)·자기주식의취득(9,467)·주식보상비용(7,276)·무상증자(7,102)·전환사채의전환·
자기주식의처분(4,157)·**자기주식소각(2,246)**·**이익잉여금처분(843)**…

→ 라벨 변형(띄어쓰기·조사 `자기주식의 소각`/`자기주식 소각`, `자기주식처분`/`자기주식의 처분`)이 많음 =
**정규화 매핑이 계층3 값판단**의 핵심. 열·행 어휘 전수 서베이(D-0)로 확정.

## 3. 계층3 추출 설계
입력 = report_lines(statement='SCE'). 출력 = 신규 정규화 테이블(§4).

1. **성분 정규화** `col_label → component_key`:
   `{자본금, 자본잉여금, 이익잉여금, 기타포괄손익누계액, 기타자본, 지배지분합계, 비지배지분, 자본총계}`.
   별칭(주식발행초과금→자본잉여금? 는 판단 — D-0에서 결정)·상위헤더(`지배기업의 소유주…`) 흡수.
2. **변동사유 분류** `label_raw → flow_key`(raw 보존):
   `{배당, 자사주_취득, 자사주_처분, 자사주_소각, 증자_유상, 증자_무상, 지분발행, 전환, 주식보상,
     이익잉여금_처분, 손익_당기순이익, 손익_기타포괄, 지분법변동, 회계정책변경, 기타}`.
3. **기간블록**: 기초/기말 경계 + row_order 로 당기/전기 블록 구분(계층2가 `2024.12.31(기말)` 등 남김).
   당기 블록만 1차 대상(전기는 비교용, 선택).
4. **셀 방출**: (period_block, flow_key, component_key) 로 value_won 방출(NULL 셀 제외). 기초/기말
   balance 행은 **표출 대상 아님**(사용자 지침 "기초/기말 무시") — 단 검증(§6)용으로만 사용.

## 4. 저장 구조 (신규 테이블 — std_v3 wide 부적합)
매트릭스라 wide 컬럼에 안 맞음 → **정규화 long 테이블** `sce_equity_movements`:

| 컬럼 | 설명 |
|---|---|
| corp_code, fiscal_year, fiscal_period, statement_type | grain(=std_v3와 조인 키) |
| period_block | 'current'/'prior' |
| flow_key | 정규화 변동사유(§3.2) |
| component_key | 정규화 성분(§3.1) |
| value_won | 금액(원) |
| flow_label_raw, component_label_raw | 원문 보존(충실성·감사) |
| row_order, source_rcept | 위치·정본 filing |

- PK = (corp, fy, fp, basis, period_block, flow_key, component_key). 재적재=delete-then-insert.
- 인덱스 = (corp_code, fiscal_year, statement_type). 앱 조회 바운드.
- **std_v3 는 무변경**(별도 테이블). 재빌드와 독립 — SCE 추출은 자체 빌더/CLI.

## 5. 앱 표출 구조
- **로더** `app/data/sce.py`: corp → 연도별 자본변동 상세.
  · `load_equity_movements(corp, basis)` → 연도×flow×component.
  · 파생: 배당 지배/비지배 분리, 자사주 순증감(취득−처분−소각), 이익잉여금 사용처 집계.
- **표출 위치**(택1, 사용자 결정): (a) tearsheet 신규 "자본변동 상세" 섹션, (b) 기업 상세 탭.
  · 표: 성분×변동사유 매트릭스(당기). · 파생 KPI: 배당(지배/비지배)·자사주(취득/소각)·주식보상.
  · 차트(선택): 이익잉여금 워터폴(기초→순이익→배당→기말) — 단 기초/기말은 표시가 아니라 워터폴
    앵커로만(사용자 "기초/기말 무시" 취지 = 지표화 안 함, 문맥 앵커는 허용 — D-단계에서 확인).
- ★ **앱은 이 테이블을 직접 읽는다**(std_v2/v3 스왑과 독립 — SCE 상세는 신규 테이블이라 구/신 체인
  무관). L3-5 swap 대기 불필요.

## 6. 검증
- **SCE 자체 검산**: 성분별 `기초 + Σ변동 = 기말`(SCE 는 부호 명시라 성립 예상 — 설계문서 §7-4).
- **교차검증**: 기말 성분합/자본총계 = BS 자본총계(기존 anomaly detector 연계 — SIGN/DIGIT 재활용).
- **원문 대조**: 배당·자사주 대표 기업 표본 DART 원문 일치.
- **gap-fill 정합(약대조)**: SCE 배당 총액 ≈ dividend_facts.total_dividend_amount(단위·범위 차 감안).

## 7. 순서 / 의존성
- **선행**: `--recheck` 완료(report_lines 안정). SCE 추출은 재추출분 위에서.
- 재빌드(build_std_v3)와 **독립**(별도 테이블) — 병행 가능.
- **파이프라인 편입**(runbook 3층): 데일리 배선(`collect_new.py` 두 call site) + 소급 백필(전량 1회) +
  검증. report_lines 데일리가 아직 미배선이므로 그 배선과 함께 처리(계층2 전량적재 인프라와 동반).
- D-0 어휘 서베이 → D-1 추출기 → D-2 테이블·빌더 → D-3 앱 로더·표출 → D-4 검증.

## 8. 열린 결정 (착수 전)
1. **표출 위치**: tearsheet 섹션 vs 기업 상세 탭 vs 둘 다.
2. **전기 블록 포함 여부**: 당기만 vs 당기+전기(YoY 비교).
3. **성분 별칭 경계**: 주식발행초과금→자본잉여금 병합 등 어디까지 합칠지(D-0에서 데이터로 결정).
4. **pre-2015 SCE**: 계층2 2차패스(미적재)라 이 상세도 2015+ 한정으로 시작.
