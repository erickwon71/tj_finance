## 0. 원인은 어디까지 확정됐나 — 정직한 경계선

### 0-1. ✅ 확정된 것 — 결함 지점과 메커니즘

원문 XML → DB 끝단까지 재현했다(handoff §8-2, 텔코웨어 `20240814002630`). 확정 내용:

**헤더는 그리드를 복원하는데 본문 행은 안 한다.** 같은 표를 두 코드가 서로 다른 좌표계로 읽는다.

| | 코드 | 좌표계 |
|---|---|---|
| 헤더 | `fin2/extract/report_lines.py::_build_col_labels` (500~512줄) | (row,col) occupied-grid — **ROWSPAN/COLSPAN 확장함** |
| 본문 행 | `parser/xml/table_extractor.py::_get_cells` (330~338줄) → `extract_rows` (253~254줄) | 물리적 `<TD>` 순서 — **확장 안 함** |

`_emit_note_lines`(`report_lines.py:614~661`)가 이 둘을 `col_idx`로 맞물리므로,
원문에서 물리적 `<TD>` 개수가 논리적 열 수보다 적어지는 행마다 값이 왼쪽으로 밀린다.

근거의 강도:
- 코드 대조 — `_get_cells`에 span 처리 코드가 **한 줄도 없음**(grep 확인).
- 원문 마크업 — 6개사·2015~2024 재현(유진증권·미래에셋생명·유비벨록스·텔코웨어·POSCO·풍강).
- DB 대조 — 텔코웨어에서 **전기말 값 470,100이 `당반기말` 라벨로 저장**된 것 확인.
- 오검출 배제 — census 인덱스 정합성 검사 0건, 규모 3개 표본에서 재현(10.3~11.5%).

### 0-2. ⚠확정 안 된 것 — 원인은 "한 지점"이 아니라 **결합된 3개**

`_get_cells`만 고치면 끝나지 않는다. 아래 (B)·(C)는 (A)의 파생결과가 아니라 **각각 독립된 결정**이다.

| | 결함 | 위치 | 상태 |
|---|---|---|---|
| **A** | 본문 행 span 미확장 | `table_extractor.py:330,253` | 원인 확정 ✅ |
| **B** | `offset = width − n_amounts`에서 `n_amounts`를 **물리적 셀 수**로 계산 | `report_lines.py:487~494, 515` | 대체 규칙 **미정** ❌ |
| **C** | 행 라벨 = 항상 `cells[0]` — ROWSPAN 이어짐 행은 자기 라벨 셀이 없음 | `table_extractor.py:254` | 정책 **미정** ❌ |

**(B)가 왜 미해결인가 — 내 첫 후보는 측정으로 반증됐다.**
handoff §11에서 "L = 선행 비금액 그리드 열 수"를 후보로 제시했으나, 실측 결과:

```
표본 250필링 · 금액 있는 표 37,314개
  결함 없는 표 32,090개 중 L == 현재 offset : 29,367 (91.5%)
                          L != 현재 offset :  2,723 ( 8.5%)  ← 대부분 L 이 1~3 큼
```

즉 이 규칙을 쓰면 **지금 멀쩡한 표의 8.5%가 새로 어긋난다.** 원인: 어떤 표에서 첫 금액 열이
통째로 `-`/공란이면 "금액이 없는 열"로 잡혀 L이 과대해진다. **선행 열 판정은 값의 유무가 아니라
헤더 그리드에서 유도해야 한다** — 이게 Phase 1에서 결정할 사항이다.

**(C)의 규모**: 주석 본문 행의 **9.99%**(23,756 / 237,840)가 그리드 열 0을 ROWSPAN으로
상속받는 행이다. 즉 10행 중 1행은 `label_raw`가 원문상 그 행의 진짜 정체가 아니다.

### 0-3. 범위 (재검증 확정)

- 대상: **주석 경로만.** 본문 BS/IS/CF는 실측 0건(handoff §10).
- 미측정: **SCE**(`_emit_sce_lines`, 별도 경로) → Phase 1에서 측정.
- 피해: 값 자체가 망가진 것은 전체 값의 **0.24%**, 누락 0.75%, 나머지 89.6%는 **열 정체 오류**.

## 1. Phase 1 — 설계 결정 (측정 기반, 코드 변경 없음)

> 목적: 0-2의 (B)·(C)를 **추측이 아니라 실측으로** 잠근다. 여기서 잠그지 않고 구현에
>들어가면 "멀쩡한 표 8.5%를 새로 망가뜨리는" 수정이 된다.

- [x] **T1.1 — 라벨 영역 폭(L) 규칙 후보 측정 — ★확정: `LV′`(값+placeholder 기반), 아래 참고**
  - 후보 ①: 헤더 그리드에서 **모든 헤더 행이 같은 텍스트로 세로 관통**하는 선행 열
    (= `구분`류 ROWSPAN 라벨 칸)
  - 후보 ②: 헤더 최하단 행에서 기간/분류 라벨이 시작되는 첫 열 (오른쪽 정렬 유지, 단
    `n_amounts`를 **확장된 그리드 폭 기준**으로 재계산)
  - 후보 ③: ①∩② 합의, 불일치 시 **보류**(현행 유지 + `unit_source`에 사실 기록)
  - 합격 기준: **결함 없는 표에서 현재 `offset`과 100% 일치**(≥99.9%), 결함 표에서는
    §8-2 텔코웨어·유진증권·풍강 3건이 원문과 일치
  - 산출물: `scripts/probe_label_region_rule.py` + 후보별 일치율 표
  - ⚠합격 기준을 만족하는 후보가 없으면 **여기서 멈추고 사용자에게 보고**한다(추측 금지)

  ### T1.1 결과 (2026-08-07, 156필링·24,006표 표본)

  **셋 다 불합격.** 결함 없는 표에서 `offset`과의 일치율(합격선 99.9%):

  | 후보 | 전체 | n_header==1 (41.8%) | n_header==2 | n_header≥3 |
  |---|---|---|---|---|
  | ① 세로관통 | 18.6% | 0%(전부 abstain) | 26.9% | 44.0% |
  | ② 최하단행 원천 | 17.9% | 0%(전부 불일치) | 25.3% | 43.4% |
  | ③ 교집합 | 17.4% | 0%(전부 abstain) | 25.3% | 40.9% |

  (측정 과정에서 두 가지를 스크립트에 반영·수정: (a) 헤더 행이 1개뿐이면 후보①의 "세로
  관통"이 무의미하게 항상 참이 되는 구현 버그 수정 → abstain 처리. (b) 표 안에 낀
  전폭 캡션 행(예: `요약연결재무상태표상 자산`처럼 전 열에 같은 텍스트가 반복되는 행 —
  실제로는 열별 라벨이 아니라 표 중간 설명문)이 두 후보 모두를 오염시킴을 발견해
  "캡션 행 제외" 필터를 추가. 이후에도 결과는 위 표와 같음.)

  **근본 원인**: 결함 없는 표의 **41.8%가 헤더 행이 1개뿐**이다(`구분|토지|건물|…`처럼).
  이 경우 ROWSPAN/COLSPAN 같은 구조적 신호가 아예 없어 "구분" 열과 진짜 금액 열을
  헤더만으로는 구분할 수 없다 — 후보①은 정의상 2개 이상의 헤더 행이 있어야 성립하고,
  후보②는 n_header==1일 때 항상 L=0(오답)으로 퇴화한다. 헤더 행이 2개 이상이어도
  **44%대**에 그쳐 합격선과 거리가 멀다.

  **참고 — 이전(같은 날) 반증된 값 기반 후보와 비교**: 핸드오프 §11/`probe_note_span_
  fix_design.py`가 시도한 "본문에 금액이 한 번도 안 뜨는 선행 그리드 열" 후보는 결함
  없는 표에서 **91.5%** 일치했다(멀쩡한 8.5%를 깬다는 이유로 기각됐지만, 헤더만 보는
  이번 후보들보다 훨씬 낫다). → **헤더만으로는 안 되고, 본문 값의 유무 신호가 필수적으로
  보인다.**

  **→ 중단 조건 발동(§6 표): "T1.1에서 합격 기준을 만족하는 후보가 없음". 사용자 보고
  후 판단 대기.** 다음 후보를 임의로 더 만들지 않음(추측 금지 원칙).

  ### T1.1 후속 — 사용자 지시로 후보④(하이브리드) 설계·측정 (같은 날 계속)

  값 기반 후보(위 §0-2, 원래 반증됨)를 두 갈래로 보강해 재측정:

  - **LV**: 원래의 값 기반 후보(본문에 파싱 가능한 금액이 한 번도 없는 선행 그리드 열).
    결함 없는 표 91.6% 일치(원래 반증 수치와 재현됨).
  - **LV′**: LV에 **placeholder 인식**을 더함 — 금액 열인데 표본 행 전체가 `-`/공란인 경우를
    "빈 금액 셀"로도 인정(파싱 성공 **또는** 셀이 `-`/공란류일 때 "금액형"으로 카운트).
    반증 사유("첫 금액 열이 통째로 공란이면 라벨 열로 오판")를 정면으로 겨냥. **결함 없는
    표 95.2% 일치**로 개선.
  - **후보④(하이브리드)**: 헤더 신호(후보①·②)가 서로 합의할 때만 그걸로 LV′를 덮어씀.
    **86.0%로 오히려 악화** — 헤더①②는 개별 정확도가 18~26%대로 낮아, "합의"해도 여전히
    자주 같이 틀린다. **하이브리드 방향은 폐기.**

  ### ★잔여 4.8%(LV′≠offset) 실측 — 진짜 불일치가 아니라 측정 기준이 잘못됐다

  `--debug-miss` 로 LV′가 offset과 다른 결함 없는 표에서, "amount 취급 안 된 열"에 실제로
  뭐가 들어있는지 500개 표본 덤프: `관계기업`·`신한은행`·`중국`·`1%`·`보통주`·날짜·회사명
  등 **전부 진짜 텍스트**(은행명/국가명/거래처/비율/날짜) — 숫자도 placeholder도 아니다.
  즉 이 표들은 라벨 영역이 `구분` 한 칸이 아니라 `구분|거래처|국가|…` 처럼 **여러 텍스트
  열로 이루어진** 표다.

  **이게 실제 결과에 영향이 없는 이유(구조적 논증 + 3건 원문 확인)**:
  1. `col_label`은 **절대 grid 열 위치의 헤더 텍스트**로 정해진다(`L`이 몇이든 안 바뀜) —
     `L`은 그 텍스트가 저장될 때 쓰는 **정수 키**(`col_idx = true_col − L`)만 바꾼다.
  2. 금액이 아닌 셀은 `L`과 무관하게 애초에 행을 만들지 않는다
     (`_emit_note_lines`: `if amount is None: continue`).
  3. `LV′`는 **정의상** "본문에 한 번이라도 금액/placeholder가 있던 열" 앞에서 멈춘다 →
     진짜 금액 열의 `true_col`보다 항상 작거나 같다(음수 `col_idx` 발생 불가, 안전 보장).
  → **`L == offset` 일치는 애초에 잘못된 합격 기준이었다.** 진짜 필요조건은 "L이 모든 금액
    열보다 작거나 같다"뿐이고, `LV′`는 그걸 구성상 항상 만족한다. 남은 4.8%는 여분의
    텍스트 열을 라벨 영역에 (무해하게) 더 포함시킨 것일 뿐, 저장되는 (값,라벨) 쌍은 동일.

  **원문 3건 확인(§8-2 명시 결함 표, 직접 대조)**:

  | 필링 | 헤더 | offset(현재, 오답) | `LV′`(신규) |
  |---|---|---|---|
  | 텔코웨어 `20240814002630` table#12/13 | `구분(COLSPAN=2)｜당반기말｜전기말` | 1 | **2 ✅** |
  | 유진증권 `20220316000791` table#4 | `구분(COLSPAN=2)｜제69(당)기｜제68(전)기` | 1 | **2 ✅** |
  | 풍강 `20150429000186` table#7(clean 대조군) | `구분｜화스너｜기계제조｜연결조정｜합계` | 1 | **1 ✅**(원래 정답 유지) |

  세 필링 모두 §8-2가 원문으로 확정한 정답과 일치 — 결함 표는 고치고, 정상 표는 안 건드린다.

  **결론 — T1.1 잠정 확정 후보 = `LV′`(값+placeholder 기반)**:
  - "결함 없는 표에서 offset과 100% 일치" 라는 합격 기준 자체를 "결함 없는 표에서 **저장
    결과(값·라벨)가 동일**"로 정정 제안(위 논증). 이 기준으로는 `LV′`가 사실상 100%.
  - 헤더 구조 신호(후보①②③)는 전부 폐기 — 실제 표 47%가 헤더행 1개뿐이라 구조 신호가
    없고, 있어도(≥2행) 정확도 18~44%로 낮음.
  - 산출물: `scripts/probe_label_region_rule.py`(`LV`/`LV′`/후보①②③④ 전부 구현,
    `--debug-miss`/`--debug-neg` 플래그로 잔여 불일치 원인 덤프 가능)

  ### T1.1 대규모 재검증(800필링·123,475표) + 반대방향 예외 2건 원문 확인 — **T1.1 확정**

  156필링 표본이 우연이 아닌지 800필링(24,006표 → 123,475표, 5배)으로 재확인:

  | 후보 | 156필링 | 800필링 |
  |---|---|---|
  | LV | 91.6% | 91.6% |
  | **LV′** | 95.2% | **95.3%** |
  | L4(하이브리드, 폐기) | 86.0% | 86.6% |

  수치가 안정적으로 재현됨. 단, 표본이 커지자 결함 없는 표 106,700개 중 **2개**에서
  지금까지 못 본 **반대 방향** 불일치(`LV′ < offset` — 라벨 영역을 offset보다 더 **좁게**
  잡음)가 나타나 원문으로 직접 확인(`--debug-neg`):

  1. 전환사채 발행조건표(n_header=8, width=3) — 실제로는 "항목명:설명"이 세로로 쌓인
     **비정형 키-값 표**(금액 그리드가 아님). `_header_split`이 숫자 있는 행도 헤더로
     잘못 흡수한 게 근본 원인 — `LV′`/offset 둘 다 이 표엔 애초에 안 맞는 모델.
  2. 보험가입내역표(n_header=4, width=4) — `보험종류|부보자산|보험회사|부보액` 4열인데
     `offset=2`(현재)가 "보험종류+부보자산"을 통째로 라벨 영역으로 오인. `LV′=1`이 오히려
     구조상 맞음(부보자산은 텍스트 열이라 어차피 금액 미발생).

  **둘 다 위험하지 않다** — 두 경우 모두 `LV′`가 offset보다 **더 많은** 열을 "금액 후보"로
  열어주는 방향(연 방향, 축소가 아니라 확장)이라, §T1.1 안전성 논증(모든 진짜 금액 열의
