# Gate B pass→fail_b 148건 트리아지 (2026-09-25)

## 배경
R172 후 Gate B 재감사(777개사, 2015~2025)에서 경로 혼합 기간 **밖** 148개 (기업·기간·basis)가 pass→fail_b 로 바뀌었다.
비교 기준은 2026-09-02/03 감사다(reader_version 은 전후 모두 `trackAB-v3`). 실패 필드는 312개다.

## 결론
**148건 전부 Gate B 기준값(report_won)이 틀린 쪽이다. DB 값은 원문과 일치한다.** 09-02 에는 DB 도 같은 틀린 값을
갖고 있어 "일치(pass)"였다. 이후 수정(R168 2단열, R169 단위 등)이 DB 를 바로잡으면서 Gate B 판독기의 한계가 드러났다.

## 근거
1. **machine_compare(원문 XML 셀 대조, 읽기 전용)**: 실패 필드 312개 중 278개는 해당 재무제표가 원문과 완전 일치(clean)했다.
   25개는 같은 재무제표의 **다른 행**에서 불일치가 나왔다(대부분 EPS 행, 아래 부수 발견). 9개는 XML 이 없다(XBRL/PDF 필링).
2. 유형별:
   - **DB=0, 기준값≠0 (195필드)**: 현금흐름 재무/투자활동·법인세·배당·유동부채. 원문 행의 당기 셀이 '-' 이고
     Gate B 가 다른 열(전기 또는 2단열의 다른 칸)을 읽었다. 예: 패션플랫폼(01101041) 2017Q3 별도 재무활동현금흐름 —
     원문 `-, -, -, 11,827,416,000`(당기 2칸 '-', 전기 합계 118억) → DB 0 이 정답이다.
   - **DB = 기준값×10⁻⁶ (31필드, 3필링)**: R169 단위 교정 필링(00161116 2021H1 · 00201131 2019Q3 · 00679314 2017H1).
     DB 는 원 단위로 맞다(예: 00679314 연결 자산 842,787,340,982). Gate B 판독기는 선언 "백만원"을 그대로 곱해 ×10⁶ 이다.
   - **기타 값 차이 (86필드)**: 해당 재무제표가 원문 clean 이다(기간·열 선택 차이).
