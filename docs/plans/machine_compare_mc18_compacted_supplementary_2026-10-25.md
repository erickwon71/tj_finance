# 기계대조 mc18 — 보충표기 압축 셀(`값(괄호)(괄호)`) 첫 값 비교 (2026-10-25)

> 상태: 계획 + 구현 (사용자 지시 2026-10-25: "계획 문서 만들고 구현까지 이어서 진행").
> 대상 코드: `fin2/verification/machine_compare.py` (TOOL_VERSION mc17 → mc18). 파서(계층2)는 건드리지 않는다.

## 1. 문제

교보증권 정정공시 4건(`20190701000264/268/273/284`)은 원본 XML 이 없고 웹 viewer 출력(`*.viewer.xml`)만 있다.
viewer 출력은 금융업 보충표기(대손준비금 적립액·전입예정액)를 본항목과 **같은 칸**에 붙여 찍는다.

| 출처 | 이익잉여금 칸 | 별도 분기순이익 칸 |
|---|---|---|
| 원본 XML (`20180515001892`) | `551,779,458,997` | `19,287,584,329` |
| viewer (`20190701000264`) | `551,779,458,997(4,056,218,467)(2,105,652,781)` | `19,287,584,329 (17,181,931,548)` |

계층2(파서)는 R152 규칙(`_first_of_compacted_supplementary_cell`)으로 라벨에 `대손준비금|비상위험준비금` 이 있을 때
칸의 **첫 값**만 적재한다 — DB 는 원본필링과 같은 값이다. 기계대조(`parse_amount`)에는 이 규칙이 없어
칸 전체를 읽을 수 없는 문자열(`None`)로 보고 `value` 불일치를 만든다 (**오탐**).

## 2. 실측 범위 (2026-10-25)

`verification.machine_checks.findings` 중 `label ~ '대손준비금|비상위험준비금'` 인 `value` 발견을 가진 필링:
mismatch 49건 (mc17 26 · mc6 12 · mc5 7 · mc16 4). 그중 45건이 passed 슬롯.
27건은 **이 발견만으로** mismatch 였다(다른 발견 0건) → 수정하면 clean 으로 바뀔 후보.

## 3. 설계

- 기계대조는 파서와 독립이라는 원칙을 유지한다 → 파서 함수를 import 하지 않고 **자체 사본**을 둔다
  (`mc13` 의 마침표 복원도 같은 방식).
- `_parse_table` 에서 셀을 읽기 전에, **라벨(전체 `label`)이 `대손준비금|비상위험준비금` 을 포함할 때만**
  금액칸을 `first_of_compacted_supplementary()` 로 줄인다. 일반 행에는 닿지 않는다.
- 줄이는 규칙은 파서 R152 / R152-b / R152-c / R258 과 같다:
  1. 공백 구분 토큰: 첫 토큰이 온전한 금액이고 **금액다우면**(천단위 콤마 묶음 또는 4자리 이상) 첫 토큰.
  2. 괄호 결합 `1,828,134(13,701)(2,886)` 와 붙임표 변형 `623,930- (692)(692)` → 선행 금액.
  3. 음수 괄호 본항목 `(129,411,450)(341,071,045)` → 첫 괄호 묶음.
  4. 콤마로 끝나는 첫 토큰은 다음 토큰과 잇는다 (R152-c).
- **금액다움 가드는 필수**: 주석번호 `26, 27` 을 금액으로 날조하지 않기 위함 (R152 실측 사고).
- 인쇄 원문(`raws`, 이슈의 `src_raw`)은 **그대로** 둔다 — 줄인 것은 비교용 값뿐이다.
- 단일 값 셀·라벨 게이트 밖 셀은 종전과 동일 (바뀌는 것은 종전에 `None` 이던 칸뿐).

## 4. 버전과 후속

- `TOOL_VERSION = "mc18"`. 버전이 바뀌면 **pending 슬롯**의 기존 판정만 다시 대조된다(`NEEDS_MACHINE_SQL`).
  passed/has_issues 슬롯의 기존 mismatch 는 자동으로 다시 보지 않는다 → 영향 필링을 읽기 전용 `machine try` 로 재측정한 뒤
  결과만 보고한다. 상태 변경(되돌리기/이슈 등록)은 별도 판단.
- 사람이 skip 한 정정공시(교보증권 4건)의 skip 판단은 유지한다.

## 5. 검증

- 단위 테스트(`fin2/tests/test_machine_compare.py`): 교보 viewer 형태 2종(붙여쓰기·공백), 붙임표 변형, 음수 괄호,
  주석번호 `26, 27` 날조 방지, 라벨 게이트 밖 셀은 그대로 `None`.
- 실측: 교보 정정본 4건 → clean, 원본 4건 → 계속 clean. 영향 49건 재대조 전/후 verdict 분포 비교.
- 전체 스위트 `pytest tests/ fin2/tests/` (범위 지정).
