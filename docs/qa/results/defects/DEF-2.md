# DEF-2 — 재무제표 표에서 결측값이 "—" 대신 문자 그대로 "None"으로 노출됨 (전사 공통, 다수 항목·다수 기업)

- **심각도**: S2 (핵심 표시값 신뢰성 훼손 — 결측 표기가 깨져 "None"이 실제 수치나 파싱 오류처럼 보일 위험이 있고, 아래 확인대로 전 기업·전 항목에 걸쳐 광범위하게 재현됨)
- **분류**: 앱버그 (`app/views/company_page.py`의 `_show_statement()`가 사용하는 `st.dataframe(styler)` 조합에서 pandas Styler의 `na_rep`이 Streamlit 렌더러에 반영되지 않음 — 근본원인은 Streamlit 프레임워크 한계이나, 앱 코드에서 우회 조치 가능)
- **상태**: ✅ 수정완료 (2026-07-08)
- **발견 체크리스트 ID**: DS-6 (값 형식 이상치 — "NaN/None/inf 문자열 노출... 없음"이 합격 기준)
- **발견일 / 담당자**: 2026-07-07 / Sonnet(테스트 담당)

## 위치
- **페이지**: `/company` (기업 시각화)
- **탭 / 위젯**: ①재무제표 탭 — 손익계산서·재무상태표·현금흐름표 3개 표 전부(`_show_statement()`가 렌더). 연간(FY)·분기(CQ) 양쪽 grain 모두 재현.

## 재현 조건
- **기업**: 삼성전자(005930), SK하이닉스(000660) — 표본 스윕 중 관찰, 근본원인이 앱 데이터가 아니라 Streamlit 자체 렌더링 한계이므로 **결측 셀이 하나라도 있는 모든 기업에서 재현될 것으로 판단**(대형주·소형주 무관)
- **토글 상태**: 연결/별도 무관, 연간/분기 무관(양쪽 모두 재현 확인)
- **기간 구간**: 표시 구간 내에 값이 없는(NULL) 기간이 하나라도 포함될 때
- **기타 입력값**: 없음

## 재현 단계
1. 사이드바에서 `삼성전자`(005930) 검색·선택, 연간·연결 기본값 상태에서 ①재무제표 탭.
2. "표시 기간(구간 선택)" 슬라이더를 전체 구간(2001~2025)으로 확장.
3. 손익계산서 표의 **EBITDA** 행을 확인: 2023~2025는 실제 수치(905,276 등)가 보이지만, **2022~2011 구간은 셀마다 문자 그대로 "None"이 표시됨**(억원 단위 "—"(결측 표시)이어야 할 자리).
4. 같은 화면의 재무상태표 표에서 **매출채권** 행의 2025·2024 열, **무형자산** 행의 2025·2024 열도 동일하게 "None"으로 표시됨. 현금흐름표의 **감가상각비(D&A)** 행도 2022 이전 구간이 전부 "None".
5. 사이드바에서 SK하이닉스(000660) + 분기 로 전환해도 EBITDA 행 전체(2023 CQ2~2026 CQ1, 12개 열 전부)가 "None"으로 표시됨(스크린샷 2).
6. **최소 재현(앱과 무관하게 순수 Streamlit 확인)**: 아래 8줄짜리 독립 스크립트만으로도 100% 재현됨(스크린샷 3) — pandas 자체 `.to_html()`은 "—"를 정확히 렌더하지만(별도 확인 완료), Streamlit의 `st.dataframe()`에 동일 Styler 객체를 넘기면 "None"이 뜬다.
   ```python
   import pandas as pd
   import streamlit as st
   df = pd.DataFrame({"2025": [100, None], "2024": [200, None], "2023": [300, 50]},
                     index=["매출액", "EBITDA"])
   disp = df.apply(pd.to_numeric, errors="coerce")
   st.dataframe(disp.style.format(thousands=",", precision=0, na_rep="—"), width="stretch")
   # 렌더 결과: EBITDA 행이 "—" 가 아니라 "None" 으로 표시됨
   ```

## 기대결과
- 매뉴얼 근거: `docs/qa/02_checklist.md` DS-6 — "표/차트 텍스트 스캔 | 음수 자산·과대치 깨짐, **NaN/None/inf 문자열 노출**, 단위·천단위 라벨 누락 없음"이 합격 기준. 앱 코드 자체도 `app/views/company_page.py:_show_statement()`에서 `na_rep="—"`를 명시적으로 지정해 "—"로 표시할 의도임이 분명함(`st.dataframe(disp.style.format(thousands=",", precision=0, na_rep="—"), ...)`, company_page.py 71-76행).

## 실제결과
- 의도한 "—" 대신 **문자 그대로 "None"** 이 표시됨. `disp` DataFrame은 `pd.to_numeric(errors="coerce")`를 거쳐 확실히 `float64` dtype이고 결측은 진짜 `NaN`임을 별도 확인(단순 파이썬 `None` 객체가 남아있는 문제 아님) — 그런데도 Streamlit의 `st.dataframe()`이 pandas Styler의 `na_rep` 서식을 반영하지 않고 자체 기본 표기("None")로 덮어씀. `df.to_html()`(순수 pandas, Streamlit 미경유)은 동일 Styler로 정확히 "—"를 렌더하므로, **문제는 앱의 데이터·서식 코드가 아니라 `st.dataframe()`이 Styler의 `na_rep`을 지원하지 않는 데 있음**이 최소 재현으로 확정됨.

## 영향 범위
- **전수 추정 근거**: 근본원인이 특정 기업의 데이터가 아니라 `st.dataframe()` 자체의 Styler `na_rep` 미지원이므로, **결측 셀이 하나라도 있는 모든 기업·모든 통계표(손익/재무상태/현금흐름 3개 표 전부, 연간·분기 양쪽)에서 100% 재현될 것으로 판단**. 프로젝트 메모리에 기록된 D&A/EBITDA(초기 커버리지 낮음)·R&D비용(0.5%) 등 결측이 흔한 항목·연도일수록 노출 빈도가 매우 높음. 실질적으로 **전체 2,548개 기업 스윕의 상당수 페이지**에서 나타날 것으로 예상되는 고빈도 결함.
- 사용자 인상: "None"이 뜨면 값이 0이거나 데이터 처리가 실패한 것으로 오인하기 쉬워, 부록 B/D에서 설명하는 "결측=—" 관례와 어긋나 신뢰도를 떨어뜨림.
- 지표 탭(`app/views/metric_panel.py`)·스크리너·자유조합 차트 등 **다른 `st.dataframe()` 사용처에도 동일 패턴(Styler+na_rep)이 있다면 동일 결함이 있을 수 있음** — 이번 조사는 재무제표 탭 표(CV-2/DS-6) 범위로 한정했으므로 타 화면은 별도 확인 권장.

## 비고
- **CSV 내보내기(CV-3)는 영향 없음**: `⬇ 재무제표 CSV` 다운로드 파일을 직접 확인한 결과, 동일 결측 셀이 CSV에서는 빈 문자열(정상)로 나오고 "None" 문자열이 섞이지 않음(예: `손익계산서,EBITDA,90527643000000.0,75356783000000.0,45233535000000.0,,,,,,,` — 뒤쪽 결측 연도는 정상적으로 비어 있음). 즉 이 결함은 **화면 표시(`st.dataframe`+Styler 경로)에만 국한**되고, CSV로 내보낸 raw 데이터의 무결성에는 영향이 없음 — 다운로드해 사용하는 사용자에게는 문제가 없으나, 화면을 직접 보는 사용자에게는 매 페이지 노출되는 시각적 결함임.
- 권장 수정 방향: `na_rep`에 의존하지 말고, **표시 직전에 결측 셀을 실제 문자열 "—"로 치환한 뒤 나머지 숫자 셀만 서식 적용**(예: `disp.astype(object).where(disp.notna(), "—")` 후 숫자 셀만 별도 포맷, 또는 `st.dataframe`에 넘기기 전에 `.map()`으로 전체를 문자열화)하는 방식이 Streamlit 버전에 안전함. Streamlit changelog·이슈 트래커에서 `st.dataframe` + Styler `na_rep` 관련 알려진 제약인지 확인 권장.
